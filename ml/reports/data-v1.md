## 계획서와 다르게 한 것

- **다양화를 Claude API 대신 Claude Code 세션 서브에이전트로** — API 요금 없이 같은 검사(`accept`)를 거친다. 그래서 `paraphrase.py` 는 `call_claude`·`--yes` 대신 `export`(요청 묶음 + 지시문) / `ingest`(검사·집계) 두 명령. 다시 만들려면 `export` → 세션에서 묶음마다 `*.out.jsonl` 작성 → `ingest`.
- 시범 1묶음(300개, 100% 통과)이 너무 얌전해서 나머지 묶음은 "문장마다 변형 하나 이상은 줄임말·띄어쓰기 생략·반말 명령 등 확 구어체"로 지시했다.
- 생성기 조사 고침(`fix(ml)`): `{값}로`·`{값}이요` 를 값의 끝소리에 맞춤. 8,000문장 중 243문장의 조사만 바뀌고 id·정답 양식은 그대로 — 변형을 다시 만들 필요 없음. 거절 2건은 고친 원문과 변형이 같아진 것.

## 시험 세트 (Task 5) — `data/test_human.jsonl` 305문장

| 작성 | 말투 | 문장 | 이어지는 턴 |
|---|---|---|---|
| A | 학과 조교 — 짧은 메신저체, 줄임말·오타 | 100 | 20 |
| B | 행정직원 — 공손, 정확한 날짜, 강의실 여러 개 | 100 | 24 |
| C | 교수 — 말하듯, 맥락 생략, 엉뚱한 부탁 | 100 | 19 |
| W | **실제 관리자(wj)** — 수집 페이지로 입력 | 5 | 0 |

- **사람이 아니라 Sonnet 서브에이전트가 역할을 맡아 썼다**(wj 결정 — 실제 관리자 문장을 모으기 전 임시). 학습 데이터·생성기·계약 예문을 보지 않고 규격 문서(설계서 §1·§3, `assistant_proto` README·지시문·스키마·rules)만 보고 썼다. 실제 관리자 문장을 받으면 이 세트에 더한다.
- intent 18종 모두(최소 11), 이어지는 턴 63. 이름·학번·건물은 모두 지어낸 것.
- 라벨 보정: `fill` 의 답 칸은 지시문대로 모두 `set`(작성자가 `rules.PRIMARY` 를 보고 `target` 에 넣은 12줄을 옮김).
- 겹침 검사(`overlap`, 기준 0.8): 1건(`대기중 신청 뭐 있어?`) → 시험 문장은 두고 학습 변형을 지웠다 → **0건**.
- 알려진 차이: 작성자 C 의 이어지는 턴 `ctx_items` 는 서버가 푼 값(`12/11(금)`)으로 적었다 — 서버는 문장 속 표현 그대로 적는다. 접두어 입력이 실제와 조금 다르다.
- W 5문장: 문장은 입력 그대로, 교수 실명은 가상 이름으로 바꿈. 정답은 지시문 규칙에 맞춰 보정 — 정규 수업의 그날 휴강(`class.change` → `event.add` type 휴강), 하루만 강의실 옮기기(`event.change`), `when`·`time` 에 잘못 들어간 값 정리.
