# cw-15 갱신 지연 50회 실측

- 일시: 2026-11-04 (KST) · 진행: cw
- 결론: **진행표 cw-15 완료 기준 통과 — 50회 중 50회가 30 s 안(목표 48회 이상).** 전부 첫 시도 `acked`(재시도 0), 중앙값 **4.48 s**, 95 % **5.06 s**, 최대 **5.25 s**.

## 2. 방법

- 관리자 API `PUT /api/rooms/{id}/slots` 로 E301 **일요일 23:00–23:50 측정용 슬롯**의 과목명을 50번 바꿨다(평일 화면 영향 없음). 끝나고 `DELETE` 로 지웠다(그것도 4.19 s `acked`).
- 지연 = outbox `created_at`(API 가 변경을 접수한 시각) → `finished_at`(노드 ACK 를 받아 `acked` 로 끝난 시각). 관리자 대시보드 지연 통계(`/api/admin/analytics/latency`)와 같은 정의.
- 한 번에 하나씩 — 앞 변경이 `acked` 된 뒤 2~8 s 무작위로 쉬고 다음을 보냈다(대기열 지연 제외, 순수 전달 지연).
- 경로: 웹 API → 메인Pi DB·outbox → WebSocket → 모뎀Pi 파이프라인 → 모뎀 보드(CAD → wake 프리앰블 3 s 송신) → 노드 저장(LittleFS) → ACK.
- 스크립트는 메인Pi `esc-server` 컨테이너 안에서 돌렸다(관리자 토큰을 그 안에서 만들어 썼다).

### 화면 반영까지
ACK 는 저장 직후·렌더 전에 보낸다(v2 §6.4). 화면은 마지막 수신 뒤 8 s 조용하면 다시 그리고, 3색 전체 리프레시가 약 27 s(10/21 실측 26~27 s) 걸린다. 그래서 **웹 저장 → 문 앞 화면이 바뀌기까지 ≈ 4.5 + 8 + 27 ≈ 40 s** 다(로드맵 §7.1 의 "화면 반영 지연"). 렌더 꼬리 실측은 dh-09.
