## 1. 평가 기준

1. 라이선스: 펌웨어 임베딩·상업 이용 가능 여부, 고지 의무, 파생 이름 제한
2. 격자 크기: 어느 크기에서 1비트로 선명한가. 스펙의 타입 스케일(78/62/32/28/20/16)과의 관계
3. 한글 범위: 완성형 11,172자 전부 지원하는가, 필요한 기호(`–` `·` `↑` `↓`)
4. 저장 크기: 전체 한글 1비트 기준. 앱 파티션 3MB, 커밋 훅 500KB 제한과의 관계
5. 1비트 화질: 획 끊김·뭉침, 굵기 균일성
6. 가독성: 문 앞 1~3m. 실기 패널에서만 확인 가능
7. 디자인 영향: 타입 스케일·분위기 변경(mh 스펙이 원본), 상태명·라벨 이미지 자산의 서체 통일
8. 생성 파이프라인 재현성: 글자 집합·크기 파라미터화, 폰트 다운로드 출처

## 2. 기준선: 나눔고딕 (v1 자산)

- 라이선스: SIL OFL 1.1. 상업 이용 가능, 번들 시 저작권 안내와 라이선스 전문 포함. `[출처]` help.naver.com 나눔글꼴 라이선스 안내, m-hangeul.naver.com/font
- 20px 전체 한글 1비트: 676,020B(컴파일 실측 676,032B). 28px 전체는 1,261,904B `[계산]`
- v1은 20px 한 벌만 실제로 사용했고 `min_spiffs` 파티션이었다. `[확인]`
- 1비트 화질: 빈도 상위 2,000자 중 20px 17%, 28px 12%는 획 연결이 4배 해상도 정답과 다르지만 눈으로는 대부분 읽힌다. Regular 기준이라 획이 1px로 가늘다. `[확인]`
- 큰 폰트 하나를 축소하는 방식은 기각: 임계값 정책만 바꿔도 획 연결 일치율이 21%~97%로 뒤집혀 크기마다 튜닝이 필요하다. `[확인]`

## 3. 후보 조사 결과

### 3-1. 둥근모꼴+Fixedsys (눈누 font_page/250, 제작 길형진)

라이선스
- 눈누 표기: "원본과 동일한 퍼블릭 도메인으로 재배포, 수정, 영리 목적 사용 등 걱정 없이 자유롭게". `[출처]`
- 한글 원작은 1990년대 김중태 IT문화원 원장이 공개한 퍼블릭 도메인 비트맵 글꼴. `[출처]`
- **영문·숫자는 Fixedsys Excelsior**에서 왔고, 이것은 Microsoft의 원본 Fixedsys(Windows 95/98/Me 메모장 글꼴)를 변환한 것이다. 변환 저장소(kika/fixedsys)는 기여자들이 퍼블릭 도메인/CC0로 공개했다고 밝힌다. `[출처]` 원본 Microsoft 글꼴의 권리 관계는 `[미검증]`
- 제작자 블로그 글 하단에 "저작자표시 비영리 변경금지" 표기가 있다(블로그 글 기본 표기로 보이나 사용권 문구와 어긋남). `[확인]` 표기 / 의미는 `[미검증]`
- 완화책 후보: 한글만 이 폰트에서 쓰고 숫자는 다른 폰트로 대체. 시험 안 함.

기술
- 한글 11,172자, ASCII 95자 전부 지원. `–` `·` `↑` `↓` 있음. `[확인]`
- 외곽선 좌표가 전부 픽셀 격자(160 단위/em)에 있음(검사한 242개 좌표). `[확인]`
- 선명한 크기는 **16/32/48/64px뿐**. 20/24/28/40/56px는 회색 픽셀 27~47%. `[확인]`
- 셀: 한글 16×16, ASCII 8×16. 전체 한글+ASCII 1비트 359,024B. `[확인]` 폭 / `[계산]` 합계
- 32px 직접 렌더 = 16px 렌더의 2배 확대(500/500 글자 동일) → 32px를 위한 추가 저장 0. `[확인]`
- 20/28px로 억지로 만들기: 직접 렌더(A)·16px 최근접 확대(B)·32px 박스 축소(C) 모두 읽히고, 연결 성분 수가 16px 원본과 99.9~100% 일치. 획 굵기는 고르지 않다(20px 2~3px, 28px 3~4px). 잉크 비율은 (A) 0.96/1.09, (B) 0.98/1.03, (C) 1.20/1.10 — (C) 20px는 조밀한 글자가 뭉친다. `[확인]`
- (B)는 저장을 16px 한 벌(359,024B)로 두고 그릴 때 확대하는 방식. 런타임 확대 비용 `[미검증]`

화질 (호스트 1비트, 스펙 문구 mock)
- 나눔고딕(현재 스펙 20/28) 대비 획이 굵고 대비가 강하다. 잉크 밀도 30.1% vs 17.3%(20px)/21.4%(28px). `[확인]` 수치
- 자간이 촘촘하고 숫자가 넓고 무겁다(`13:00` 8px 고정폭). 분위기가 레트로 게임풍. 주관 판단
- 정보 행 32px 6자=192px는 값 영역 330px 안, 목록 16px 6자=96px는 164px 안. `[계산]`
- 3m 가독성, 실기 패널 번짐 `[미검증]`

### 3-2. 굵은둥근모(BoldDungGeunMo, 눈누 font_page/1606, 제작 사왈이) — D4(굵기) 관련 조사 완료 (2026-09-23)

- **둥근모꼴+Fixedsys(3-1)와는 다른 제작자의 별도 파생물**이다. 같은 계열의 공식 볼드 웨이트가 아니라 사왈이가 독립적으로 만든 것. `[확인]`
- 라이선스: 눈누 표기 "원본 폰트와 같은 퍼블릭 도메인 — 상업·수정·재배포 자유, 제3자 제작 표기만 금지". `[출처]` 다만 눈누 요약표는 이번에도 "수정·재배포·유료판매 모두 금지"로 본문과 모순된다(3-1과 같은 패턴의 표기 오류로 보임). "원본과 같은 라이선스"라는 문구로 볼 때 3-1의 라이선스 구조(한글=퍼블릭도메인, 영문/숫자=Fixedsys Excelsior 유래 추정)를 그대로 물려받을 가능성이 높다 `[추정]`, 제작자 확인 필요.
- 기술: 한글 11,172자 전부 지원(`[확인]`). `unitsPerEm`이 원본(160)과 다르다(1024) — 그런데도 같은 16/32/48/64px 격자에서 둘 다 선명함을 확인(`[확인]`). 내부 스케일만 다르고 디자인 그리드는 호환되는 것으로 보인다.
- **화질(2026-09-23 실측)**: 32px에서 원본과 Bold의 글자 뼈대(획 위치·꺾임)가 사실상 동일하고 **획 두께만 두꺼워졌다** — 나눔고딕 4-pass처럼 대각선·모서리가 뭉개지는 부작용이 없다. 잉크 밀도 원본 19.2% vs Bold 27.7%(빈도 상위 문구 기준). **진짜로 설계된 볼드 짝**으로 보인다. `[확인]` 그림: `.superpowers/spike-d4d5-pixel-bold/d4_pixel_bold_compare.png`(로컬, gitignore)
- **결론**: 픽셀 폰트 채택 시 D4(굵기)는 나눔고딕과 마찬가지로 "가짜 굵기(4-pass/겹쳐그리기)"가 필요 없다 — 전용 Bold 파일을 그대로 쓰면 된다. 이 점에서 픽셀 폰트가 나눔고딕과 동등하게 유리하다(나눔고딕도 D4에서 실제 Bold TTF로 결론 났으므로 이 축에서는 우열이 없다).

### 3-2b. 버그 진단 — `compare_list_2x.png`의 '톤'(오늘 목록 현재 행) 글자 깨짐 (2026-09-23)

사용자가 D1 조사 산출물 `compare_list_2x.png`(§3-1 자료)에서 발견: 오늘 목록의 **현재 진행 행**(검은 배경·흰 글자로 반전되는 행, 화면 스펙 `terminal-epaper.md:150` "현재 진행 행은 컬럼 폭 전체 반전 + 과목 굵기 700")에서 `캡스톤디자인`의 `톤`의 `ㅌ`가 안 읽힘.

- **원인 진단(5개 조합 렌더로 재현·격리, `[확인]`)**: 크기(16px vs 스펙이 정한 20px) 문제가 아니라 **그 이미지가 굵기 표현에 4-pass(1px 오프셋 4회 겹쳐 그리기)를 썼기 때문**이다. 20px로 바꿔도 그대로(오히려 더 크게) 뭉갠다. 16px 원본(굵기 없음)·16px 실제 Bold(굵은둥근모)·20px 실제 Bold는 전부 `ㅌ`가 또렷하다.
- 픽셀 폰트는 획이 이미 2px로 굵어(나눔고딕 1px 획보다) **4-pass 뭉갬에 더 취약**하다 — D4(§3-2)에서 나눔고딕에 대해 이미 내린 "4-pass 기각" 결론이 픽셀 폰트에도 그대로, 오히려 더 강하게 적용된다.
- **부수 발견**: `compare_list_2x.png` 제작 당시 목록 텍스트 크기를 스펙의 20px이 아니라 16px로 임의 축소해서 썼다(픽셀 폰트가 20px에서 비선명해서 한 근사) — 이번 진단으로 20px 자체는 문제가 아니었음이 확인됐다(20px+실제 Bold도 또렷함). 크기 근사 자체가 잘못은 아니었으나 그때 명확히 안내하지 않았다.
- 그림: `.superpowers/spike-d4d5-pixel-bold/diag_ton.png`(로컬, gitignore) — A~E 5개 조합.
- **결론**: `compare_list_2x.png`는 기법 선택 오류가 섞인 산출물이라 폰트 자체의 결함으로 읽으면 안 된다. 픽셀 폰트를 실제 채택할 경우 현재-행 굵기는 §3-2와 동일하게 굵은둥근모(실제 Bold)로 가야 한다.

## 4. 실험 방법 기록 (재현용, 스크립트는 삭제됨)

- 선명도: 안티에일리어싱 렌더에서 값 16~239인 잉크 픽셀 비율. 낮을수록 격자에 맞다. **1~254를 회색으로 세면 반올림 잔여(값 1~15, 240~254)까지 잡혀 지표가 틀린다** — 첫 실행에서 실제로 틀렸다.
- 연결 성분 수 일치율: 8-연결 잉크 성분 수를 기준(4배 해상도 렌더 또는 16px 원본)과 비교. 획 굵기 균일성이나 가독성은 재지 못한다.
- 나눔고딕 렌더는 **v1 방식**(셀=명목 크기, 글리프=셀의 0.9배, 한글은 글자당 셀 폭 전진)으로 해야 한다. 셀 높이에 맞추는 규칙은 나눔고딕을 약 20% 작게 그려 비교가 편향된다 — 첫 실행에서 실제로 편향됐다.
- 임계값(128)의 동률 처리 정책이 결과를 뒤집는다. 축소·확대 비교는 정책별로 함께 봐야 한다.
- 모든 렌더는 호스트 1비트 결과다. 패널 번짐·대비·3m 가독성은 반영되지 않는다.
- 임시 가상환경(Pillow, fonttools)에서 실행하고 삭제했다. 폰트 파일은 저장소에 넣지 않았다.
