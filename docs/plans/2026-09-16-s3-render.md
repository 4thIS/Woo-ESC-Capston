# S3 — 렌더 계층 인프라(RenderModel · HostGfx · 렌더 프리뷰) 구현 계획 (plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** RenderModel(`today[24]`) 헤더, 호스트에서 실제 Adafruit_GFX 클래스 계층을 그대로 쓰는 `HostGfx` 프레임버퍼 + PNG 저장, 픽스처 JSON 파싱, `render_preview.cpp/py`를 만들어 하드웨어 없이 레이아웃을 검증할 수 있는 파이프라인을 완성한다.

**Architecture:** 렌더 함수는 `Adafruit_GFX&` 타입에만 의존한다(spec §4.3, A안). 호스트에서 진짜 Adafruit_GFX(1.11.9계열, v1과 동일 버전)를 컴파일하려면 Arduino 코어가 필요한데, `[env:native]`엔 없다 — 이 plan의 Task 1이 최소 호환 심(`tools/arduino_shim/`)과 벤더링한 Adafruit_GFX 4파일(`lib/adafruit_gfx_vendor/`)로 이 간극을 메운다. **이 Task 1은 이 세션에서 이미 실제로 컴파일·링크·실행까지 검증을 마쳤다** — 아래 내용은 재현 가능한 실제 결과이지 설계 초안이 아니다. Task 2 이후는 그 위에 얹는 순수 로직/신규 코드다.

**중요 — 이 plan의 범위 경계:** Task 5의 `smokeRender()`는 실제 8개 레이아웃 디자인이 아니라 파이프라인(JSON→RenderModel→Adafruit_GFX→PNG)이 도는지 증명하는 최소 그리기다. **v1 이식과 8개 레이아웃 픽셀 배치, `today[]` 패널 신규 설계는 dh-04의 범위이며 이 plan에 없다.** dh-04는 `render.h/render.cpp`를 새로 만들어 `smokeRender()`를 대체하고, `render_preview.cpp`의 호출부만 바꾼다 — 이 plan이 만드는 어떤 파일도 dh-04가 그대로 갖다 쓰는 "미완성 렌더"가 아니다.

**Tech Stack:** PlatformIO `[env:native]`, C++17, 벤더링한 Adafruit GFX Library(Adafruit 라이선스, `lib/adafruit_gfx_vendor/license.txt`), ArduinoJson(이미 S1에서 도입), Unity, `stb_image_write.h`(단일 헤더, public domain/MIT, PNG 저장용 — Task 3에서 도입)

**Spec:** `docs/specs/2026-09-16-s3-render-design.md`

## Global Constraints

- 렌더 관련 신규 코드는 `Adafruit_GFX&` (또는 그 파생 타입) 하나에만 의존한다. 실기 초기화·전원관리 호출은 렌더 함수 밖.

**실측으로 확인한 근거 (spec §9 연장선):**
1. v1(`esp32_e-paper_syllabus`)의 `platformio.ini`: `adafruit/Adafruit GFX Library @ ^1.11.9` — 이 plan도 같은 버전대를 쓴다.
2. `Adafruit_GFX.h`가 실제로 요구하는 건 `Arduino.h`(또는 구버전 분기 `WProgram.h`) + `Print.h` + `Adafruit_I2CDevice.h`/`Adafruit_SPIDevice.h`(include만 하고 **실사용 0건** — grep으로 확인).
3. `Adafruit_GFX.cpp`가 요구하는 표준 C 심볼: `PROGMEM`(매크로, 없으면 컴파일 자체가 안 됨), `pgm_read_byte/word/dword`(자체 `#ifndef` 폴백 있음, 정의 안 해도 됨 — 단 ArduinoJson의 `FlashReader.hpp`는 이 매크로가 필요하므로 우리가 정의한다), `radians()`/`sin`/`cos`(`<cmath>`), `malloc`/`memset`/`free`(`<cstdlib>`/`<cstring>`), `String`(`getTextBounds(const String&, ...)` 구현이 `.length()`/`.c_str()`를 실제로 호출 — 선언만이 아니라 정의라 타입 체크됨).
4. **`ARDUINO` 매크로를 전역(`-D`)으로 정의하면 안 된다** — ArduinoJson이 "진짜 Arduino 환경"으로 오판해 `Stream` 기반 Reader까지 요구하기 시작한다(실측: `pio test -e native` 전체가 깨짐). 대신 `WProgram.h`(Adafruit_GFX.h가 `#if ARDUINO >= 100`이 거짓일 때 찾는 구버전 헤더) **파일 안에서** `#define ARDUINO 10812`를 하면, `WProgram.h`를 include하는 파일(Adafruit_GFX 계열)에서만 보이고 ArduinoJson 등 다른 헤더에는 안 보인다.
5. PlatformIO 라이브러리 매니저로 받으면(`lib_deps`) LDF가 "Framework incompatible"로 include 경로 자체를 제외한다(`lib_compat_mode = off`로 우회 가능하나, 그러면 GFX 패키지에 같이 딸려오는 `Adafruit_GrayOLED`/`Adafruit_SPITFT`(우리가 안 쓰는 다른 디스플레이 드라이버)와 진짜 `Adafruit BusIO`까지 통째로 컴파일 시도해 `digitalWrite` 등 실제 Arduino 함수 요구로 깨진다). **그래서 lib_deps 대신 4개 파일만 골라서 벤더링**한다.
6. 벤더링한 라이브러리는 `firmware/lib/` 밑에 둬야 LDF가 자동으로 include 경로에 잡고 `.cpp`를 컴파일·링크한다(`tools/` 밑에서는 `build_src_filter`로 시도했으나 `pio test`가 `src_dir` 밖 경로를 인식하지 못해 링크 에러 — `lib/lora_codec/`와 같은 위치로 통일).

```cpp
#pragma once
#include <cstddef>
#include <cstdint>

// Adafruit_GFX가 public 상속하는 최소 Print. v1 렌더 코드는 print()/println()을
// 쓰지 않으므로(한글은 drawBitmap로 직접 blit) 실동작 구현 없이 컴파일만 통과하면 된다.
class Print {
public:
  virtual ~Print() {}
  virtual size_t write(uint8_t) { return 0; }
  virtual size_t write(const uint8_t *buffer, size_t size) {
    size_t n = 0;
    while (n < size) { if (!write(buffer[n])) break; ++n; }
    return n;
  }
  size_t print(const char *s) { return write(reinterpret_cast<const uint8_t *>(s), s ? __builtin_strlen(s) : 0); }
  size_t println(const char *s) { size_t n = print(s); n += write('\n'); return n; }
};
```

`firmware/tools/arduino_shim/WProgram.h`:
```cpp
#pragma once
// 호스트(native) 빌드에서 Adafruit_GFX.h가 요구하는 최소 심볼만 제공한다.
// 실기 빌드([env:terminal])에서는 이 파일이 include 경로에 없어 진짜 Arduino.h가 쓰인다.
//
// 파일명이 WProgram.h인 이유: Adafruit_GFX.h는 `#if ARDUINO >= 100`이 거짓이면 이 파일을 찾는다.
// 일부러 ARDUINO 매크로를 전역 정의하지 않는다 — 정의하면 ArduinoJson 등 다른 라이브러리도
// "진짜 Arduino 환경"으로 오판해 Stream/Print 기반 코드 경로를 추가로 요구하기 시작한다(실측 확인).
#include <cstdint>
#include <cstddef>
#include <cstdlib>  // malloc/free — 실기에서는 Arduino.h가 전이적으로 제공, 여기선 명시
#include <cstring>  // memset — 위와 동일 이유
#include <cmath>    // sin/cos — Adafruit_GFX::rotatePoint()가 씀
#include <string>   // std::string — 아래 String 최소 구현이 씀
#include "Print.h"

// Adafruit_GFX.h는 이 파일이 include된 *뒤에*(파일 안 다른 지점에서) 다시 `#if ARDUINO >= 100`로
// write(uint8_t)의 반환형(size_t vs void)을 고른다. 여기서 정의해야 그 시점엔 보이면서
// WProgram.h를 안 쓰는 ArduinoJson 등 다른 헤더에는 안 보인다(위 각주).
#define ARDUINO 10812

#define PROGMEM

#ifndef PI
#define PI 3.1415926535897932384626433832795
#endif
#define radians(deg) ((deg)*PI / 180.0)

// PROGMEM이 없는(=일반 RAM 포인터인) 호스트에서, "플래시 읽기" 매크로는 그냥 역참조.
// ArduinoJson의 __FlashStringHelper 관련 코드(FlashReader.hpp)도 이 매크로를 요구한다 —
// Adafruit_GFX.cpp 자신의 #ifndef 폴백과 이름이 같으므로 여기서 먼저 정의해도 충돌 없다.
#ifndef pgm_read_byte
#define pgm_read_byte(addr) (*(const unsigned char *)(addr))
#endif
#ifndef pgm_read_word
#define pgm_read_word(addr) (*(const unsigned short *)(addr))
#endif
#ifndef pgm_read_dword
#define pgm_read_dword(addr) (*(const unsigned long *)(addr))
#endif

class __FlashStringHelper;

// Adafruit_GFX.cpp의 getTextBounds(const String&, ...) 구현이 .length()/.c_str()를
// 실제로 호출한다(선언만이 아니라 정의가 있는 멤버 함수라 컴파일 시점에 타입 체크됨).
// v1 렌더 코드는 이 오버로드를 호출하지 않지만, 벤더 .cpp 자체가 컴파일되려면 필요.
class String {
 public:
  String(const char* s = "") : s_(s ? s : "") {}
  size_t length() const { return s_.size(); }
  const char* c_str() const { return s_.c_str(); }

 private:
  std::string s_;
};
```

```cpp
// Task 1 회귀 테스트: 벤더링한 Adafruit_GFX가 host 빌드에서 서브클래싱·상위 도형 함수까지 도는지 확인.
// Task 3(HostGfx)의 실제 프레임버퍼가 아니라, 이 shim/vendor 조합 자체가 깨지지 않는지만 본다.
#include <unity.h>
#include <Adafruit_GFX.h>
#include <vector>

struct PixelCall { int16_t x, y; uint16_t color; };

class SpyGfx : public Adafruit_GFX {
public:
  SpyGfx() : Adafruit_GFX(5, 5) {}
  std::vector<PixelCall> calls;
  void drawPixel(int16_t x, int16_t y, uint16_t color) override {
    calls.push_back({x, y, color});
  }
};

void test_fill_screen_calls_draw_pixel_for_every_cell() {
  SpyGfx g;
  g.fillScreen(7);
  TEST_ASSERT_EQUAL(25, g.calls.size());  // 5x5
  TEST_ASSERT_EQUAL_UINT16(7, g.calls[0].color);
}

void test_draw_rect_border_only() {
  SpyGfx g;
  g.drawRect(0, 0, 5, 5, 1);
  // drawRect 는 4변을 각각 drawFastHLine/VLine 으로 그리므로 모서리 4개가 두 번씩 호출된다
  // (5+5+5+5=20, 실제 실행으로 확인 — 내부 9칸은 비어 있고 고유 픽셀은 16개지만 "호출 횟수"는 20).
  TEST_ASSERT_EQUAL(20, g.calls.size());
}

int main() {
  UNITY_BEGIN();
  RUN_TEST(test_fill_screen_calls_draw_pixel_for_every_cell);
  RUN_TEST(test_draw_rect_border_only);
  return UNITY_END();
}
```

```cpp
#include "host_gfx.h"

#define STB_IMAGE_WRITE_IMPLEMENTATION
#include "vendor/stb_image_write.h"

HostGfx::HostGfx(int16_t w, int16_t h)
    : Adafruit_GFX(w, h), w_(w), h_(h), buf_((size_t)w * h, HColor::WHITE) {}

void HostGfx::drawPixel(int16_t x, int16_t y, uint16_t color) {
  if (x < 0 || y < 0 || x >= w_ || y >= h_) return;  // v2 §12 밖 좌표는 무시(크래시 방지)
  buf_[(size_t)y * w_ + x] = static_cast<HColor>(color);
}

HColor HostGfx::pixelAt(int16_t x, int16_t y) const {
  if (x < 0 || y < 0 || x >= w_ || y >= h_) return HColor::WHITE;
  return buf_[(size_t)y * w_ + x];
}

bool HostGfx::savePNG(const char* path) const {
  std::vector<uint8_t> rgb((size_t)w_ * h_ * 3);
  for (size_t i = 0; i < buf_.size(); ++i) {
    uint8_t r, g, b;
    switch (buf_[i]) {
      case HColor::BLACK: r = g = b = 0; break;
      case HColor::RED:   r = 200; g = 16; b = 46; break;
      default:            r = g = b = 255; break;  // WHITE
    }
    rgb[i * 3 + 0] = r; rgb[i * 3 + 1] = g; rgb[i * 3 + 2] = b;
  }
  return stbi_write_png(path, w_, h_, 3, rgb.data(), w_ * 3) != 0;
}
```

```cpp
#include "fixture_parse.h"

#include <ArduinoJson.h>
#include <cstdio>
#include <cstring>

namespace {

void readSlot(JsonObjectConst j, RenderSlot& s) {
  strncpy(s.subj, j["subj"] | "", sizeof(s.subj) - 1);
  strncpy(s.prof, j["prof"] | "", sizeof(s.prof) - 1);
  s.sH = j["s_h"] | 0; s.sM = j["s_m"] | 0;
  s.eH = j["e_h"] | 0; s.eM = j["e_m"] | 0;
  s.type = j["type"] | 0; s.flags = j["flags"] | 0;
}

}  // namespace

bool parseFixtureFile(const char* path, RenderModel& out, char* nameOut, size_t nameCap) {
  FILE* f = fopen(path, "rb");
  if (!f) return false;
  fseek(f, 0, SEEK_END);
  long sz = ftell(f);
  fseek(f, 0, SEEK_SET);
  std::string buf(sz, '\0');
  size_t got = fread(buf.data(), 1, (size_t)sz, f);
  fclose(f);
  if (got != (size_t)sz) return false;

  JsonDocument doc;
  if (deserializeJson(doc, buf) != DeserializationError::Ok) return false;

  strncpy(nameOut, doc["name"] | "", nameCap - 1);
  out.layout = doc["layout"] | 0;
  const char* bld = doc["bld"] | "";
  out.bld = bld[0];
  out.room = doc["room"] | 0;
  out.unit = doc["unit"] | 0;
  strncpy(out.nowStr, doc["now_str"] | "", sizeof(out.nowStr) - 1);
  out.weekday = doc["weekday"] | 0;
  readSlot(doc["prev"], out.prev);
  readSlot(doc["cur"], out.cur);
  readSlot(doc["next"], out.next);
  out.nToday = doc["n_today"] | 0;
  JsonArrayConst today = doc["today"];
  size_t i = 0;
  for (JsonObjectConst t : today) {
    if (i >= 24) break;
    out.today[i].sH = t["s_h"] | 0; out.today[i].sM = t["s_m"] | 0;
    out.today[i].eH = t["e_h"] | 0; out.today[i].eM = t["e_m"] | 0;
    strncpy(out.today[i].subj, t["subj"] | "", sizeof(out.today[i].subj) - 1);
    out.today[i].type = t["type"] | 0;
    ++i;
  }
  strncpy(out.qrUrl, doc["qr_url"] | "", sizeof(out.qrUrl) - 1);
  out.battMv = doc["batt_mv"] | 0;
  out.battPct = doc["batt_pct"] | 0;
  return true;
}
```
