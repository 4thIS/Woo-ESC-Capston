## v1에서 무엇이 바뀌었나

v1의 전제는 **"단말 e-Paper가 흑·백·적 3색이니 웹도 같은 세 값만 쓴다"** 였다. 이 전제를 철회한다.

단말의 3색은 패널의 물리적 한계이고 웹에는 그 한계가 없다. 두 화면을 묶어야 할 근거는 "관리자가 웹에서 바꾼 것이 복도의 e-Paper에 나타난다"였는데, 그것은 **강의실 상태를 어떻게 읽느냐**에만 해당하지 버튼·입력·표의 색까지 묶을 이유가 아니었다. 패널의 제약을 웹의 디자인 원칙으로 승격시킨 것이 무리였다.

| | v1 (폐기) | v2 (이 문서) |
|---|---|---|
| 값의 개수 | 3개 (`ink`·`paper`·`signal`) | 무채색 10단계 + 유채색 5 |
| 회색 | **금지** | 도입 — 위계의 주 수단 |
| 구조 | 평평한 목록 + 역할 별칭 | **원시 → 시맨틱 → 도메인 3층** |
| 사용중 표현 | 셀 전체를 `signal`로 채움 | 연한 틴트 + 진한 라벨 |
| 1차 액션 | `ink` 반전 (흑 채움) | `brand` 파랑 |
| 포커스 링 | `signal` (적) | `brand` (파랑) |
| 차트 | 규정 없음 | `chart.series.1~3` + 사용 제한 |
| 화면 분기 | 없음 (공용 1세트) | 색은 공용, **치수는 admin/student 분기** |
| 스켈레톤 | 금지(회색 의존이라) | 허용 |

**그대로 남은 것(계약)**: 사용중 = 적색 · 수업중/시험중/특강/대여중을 색으로 나누지 않고 라벨 텍스트로 나눔 · 비어있음은 칠하지 않음 · outbox는 채움 정도.

## 원칙

1. **유채색은 두 개다.** 브랜드 파랑(1차 액션·활성 전용)과 상태 적색(사용중·파괴적 동작). 그 외 색은 차트 계열색뿐이고, 차트 밖으로 나오지 않는다.
2. **구조는 전부 무채색이다.** 바탕·선·보조 텍스트에 색을 쓰지 않는다.
3. **적색은 면이 아니라 라벨에 쓴다.** 셀을 통째로 적색으로 채우면 하루치만 차도 화면이 경고판으로 읽힌다. 연한 틴트(`red.50`)를 깔고 라벨만 진한 적색(`red.700`)으로 세운다.
4. **색 토큰은 두 웹 공용, 치수 토큰만 갈린다.** 관리자 웹과 학생 웹이 다른 색을 쓰면 같은 강의실의 같은 상태가 다르게 보인다. 다르게 해야 하는 것은 밀도이지 색이 아니다.
5. **도메인이 토큰 층까지 내려온다.** 강의실 상태(`room.*`)는 범용 UI 토큰의 부록이 아니라 1급 개념이다. e-Paper `layout` 1~8과 1:1로 묶이는 자리이기 때문이다.

## 값의 확정도

시안 없이 쓴 v1이 "⚠ 제안값"을 본문에 섞어 어디까지 믿을 값인지 알 수 없었다. v2는 등급을 갈라 적는다.

| 등급 | 뜻 | 차용 시 |
|---|---|---|
| **(A) 계산값** | WCAG 2.1 상대휘도 대비, 색각이상(protan/deutan/tritan) OKLab ΔE를 **실제로 돌려** 통과한 값 | 그대로 쓴다. 바꾸려면 다시 계산해야 한다 |
| **(B) 시안값** | 위 시안에서 그려 보고 고른 값. 계산이 강제하지 않는 자리(무채색 단계 간격, 라운드, 간격) | 구현하면서 조정 가능. 이름은 유지 |

이 문서의 **유채색과 텍스트 대비는 전부 (A)**, 무채색 램프의 단계 간격과 치수는 (B)다.

# 3층 — 도메인

## `room.*` — 강의실 상태

e-Paper `layout` 1~8의 RED / BLACK 이분법과 1:1이다. **상태 색은 2개뿐이다.**

| 토큰 | = | e-Paper | 해당 SlotType |
|---|---|---|---|
| `room.busy.fill` | `red.50` | RED (layout 1·5·6·7) | `CLASS`(1) · `EXAM`(2) · `SPECIAL`(5) · `RENTAL`(6) |
| `room.busy.line` | `red.100` | ″ | ″ |
| `room.busy.label` | `red.700` | ″ | ″ |
| `room.free.text` | `text.3` | BLACK (layout 2·3·4·8) | `CANCELLED`(3) · `EMPTY`(4) · 쉬는시간 · 설정 대기 |
| `room.free.line` | `line.3` (점선) | ″ | ″ |

**수업중·시험중·특강·대여중에 서로 다른 색을 주지 않는다.** 네 상태는 전부 `room.busy` 하나이고, **구분은 라벨 텍스트가 전담한다**(`수업중` / `시험중` / `특강` / `대여중`). 색칠된 점·칸만으로 상태를 표현하는 UI는 금지한다.

왜 그런가 — 넷을 색으로 나누려면 같은 적색 계열 안에서 갈라야 하는데, 서로의 대비가 1.02~1.88이다. 즉 나눠도 나뉘지 않는다.

**비어있음은 칠하지 않는다.** `EMPTY`는 바탕 그대로 두고 아무것도 그리지 않는다. `CANCELLED`(휴강)만 점선 테두리 + `room.free.text` + 취소선으로 표시한다.

## `outbox.*` — 전송 상태

셀 우상단 점 하나. 8px, `radius.full`. **색이 아니라 채움 정도로 단계를 읽는다.**

| `OutboxOut.state` | 표시 | 색 |
|---|---|---|
| `queued` | `○` 테두리만 (1.5px) | `gray.400` |
| `dispatched` | `◐` 반 채움 | `gray.600` |
| `acked` | `●` 꽉 채움 | `gray.600` |
| `failed` | `●` 꽉 채움 | `danger` |
| `cancelled` | `○` 테두리만 + 사선 | `gray.400` |

`failed`만 적색이다. 전송 단계에 `brand` 파랑을 쓰지 않는다 — 1차 액션 전용이고, 시간표 셀 안에서 파란 점이 클릭 가능해 보인다.

## `chart.*` — 분석 대시보드 계열색 (A)

유채색 2개로는 계열을 나눌 수 없어 차트에만 색을 더 연다. **아래 값은 검증기(WCAG 대비 + 색각이상 ΔE)를 돌려 통과한 것이고, 임의로 바꾸면 통과하지 않는다.**

| 토큰 | 값 | 비고 |
|---|---|---|
| `chart.series.1` | `blue.600` `#0B5ED7` | 브랜드 파랑 겸용 |
| `chart.series.2` | `teal.600` `#0D9488` | |
| `chart.series.3` | `gold.600` `#CA8A04` | **값 라벨 또는 표 병기 의무** — 아래 |
| `chart.grid` | `line.1` | 격자 |
| `chart.axis` | `line.3` | 축선 |
| `chart.text` | `text.3` | 축 라벨 · 눈금 |

검증 결과와 그로부터 나오는 규칙:

1. **계열은 고정 순서로 배정한다.** 시리즈가 1개면 `series.1`, 2개면 1·2, 3개면 1·2·3. 필터로 계열 수가 바뀌어도 남은 계열의 색을 다시 칠하지 않는다.
2. **4계열 이상 금지.** 파랑에 보라를 더하면 적녹색약에서 ΔE 1.8로 붙는다. 넷째부터는 "기타"로 접거나 차트를 쪼갠다.
3. **`series.3`(골드)는 대비 2.86:1**이라 마크만으로는 부족하다. 쓰는 차트에는 값 라벨을 직접 달거나 같은 데이터의 표를 함께 둔다.
4. **`danger` 적색을 계열색으로 재사용하지 않는다.** 적색 인접 색(`#A16207`·`#B45309`)은 정상 시야에서도 `danger`와 ΔE 8.6~12.4로 섞여 보인다. 적색은 상태·실패 전용이다.
5. **글자는 계열색을 입지 않는다.** 값·라벨·범례 텍스트는 `text.*`를 쓰고, 옆의 색 마크가 정체성을 진다.
6. **범례는 계열이 2개 이상이면 항상 둔다.** 1개면 제목이 이름을 지므로 범례를 두지 않는다.

**한 축만 쓴다.** 축이 둘인 차트(좌우 y축)는 만들지 않는다. 척도가 다른 두 지표는 차트를 둘로 나눈다.

# 치수 — 화면별로 갈린다 (B)

**색은 공용, 치수는 두 세트다.** 관리자 웹은 밀도가 자산이고 학생 웹은 손가락이 기준이다.

| 토큰 | `admin` (데스크톱) | `student` (모바일) |
|---|---|---|
| `font.size.xs` | 11px | 12px |
| `font.size.sm` | 12px | 13px |
| `font.size.md` | 13px | 15px |
| `font.size.lg` | 16px | 18px |
| `font.size.xl` | 22px | 20px |
| `control.height.sm` | 28px | — |
| `control.height.md` | 32px | 48px |
| `radius.sm` | 4px | 6px |
| `radius.md` | 6px | 8px |
| `radius.lg` | 8px | 12px |
| `radius.full` | 999px | 999px |
| 행 높이 | 표 32px · 시간표 셀 97px | 리스트 48px 이상 |

CSS 변수로는 `--font-size-md`를 루트에서 admin 값으로 두고, 학생 웹의 진입점(`<html data-surface="student">`)에서 재정의한다. **이름은 같고 값만 갈린다** — 컴포넌트는 어느 웹에 있는지 몰라도 된다.

학생 웹의 모든 터치 타깃은 48px 이상이다. 관리자 웹에는 이 하한이 없다.

| `border.thin` | 1px |
| `border.thick` | 2px — 포커스 링 · 표 헤더 아래 |

**그림자 토큰은 없다.** 층은 면(`surface` vs `sunken`)과 테두리(`line.2`)로 나눈다. 모달만 예외로 배경을 `gray.800` `opacity: .45`로 덮는다.

# 브레이크포인트

| 토큰 | 값 | 주 대상 |
|---|---|---|
| `bp.mobile` | `< 640px` | 학생 웹 (S10) |
| `bp.tablet` | `640px ~ 1023px` | — |
| `bp.desktop` | `>= 1024px` | 관리자 웹 (S4) · 대시보드 |

관리자 웹은 데스크톱 우선, 학생 웹은 모바일 우선으로 짠다.

# 접근성

1. **텍스트 대비 4.5:1** — 위 「조합 규칙」의 모든 조합이 통과한다. 미달 조합(`gray.400` 이하 텍스트, `gold.600` 위 글자)은 금지로 명시했다.
2. **포커스 링 토큰 1개** — `focus` 하나. 값은 `brand`다.
3. **색만으로 구분하지 않기** — 강의실 상태는 라벨 텍스트가 전담하고, outbox는 채움 정도로 단계를 표현하며, 차트는 범례 + 직접 라벨을 함께 둔다.
4. **다크 모드는 v2 범위 밖이다.** 필요해지면 `gray` 램프를 뒤집는 방식(`gray.0`이 다크에서 검정)으로 넣고 시맨틱 이름은 그대로 둔다. 유채색은 다크 표면 기준으로 **다시 계산**해야 한다 — 밝기를 그냥 뒤집으면 통과하지 않는다.

# 미결

1. **`gray.400` 텍스트 잔재** — 시안의 날짜 라벨(`#909090`, 3.19:1)과 휴강 과목명이 이 문서의 하한 아래다. 구현 시 `text.3`으로 올린다. 시안도 함께 고친다
2. **Pretendard 서브셋 범위** — wj와 협의 (self-host 전제)
3. **`bp.tablet` 동작** — 관리자 웹을 태블릿에서 어떻게 접을지. `screens/admin-schedule.md`에서 정한다
4. **`chart.series.3` 실사용 여부** — 지금 대시보드에 3계열 차트가 없다. 필요해질 때까지 토큰만 두고 쓰지 않는다
