# 우송 ESC — design.md

> e-Paper·LoRa 강의실 게시 시스템의 **웹 쪽 디자인 시스템**이다. 값의 출처는 이 저장소 안에 있다 — 스펙은 `docs/design/`, 시안은 캔버스, 서버 계약은 `server/app/schemas.py`. 값마다 **등급을 갈라** 적는다: **(A) 계산값**은 WCAG 2.1 상대휘도 대비와 색각이상 OKLab ΔE 를 실제로 돌려 통과시킨 것이고, **(B) 시안값**은 그려 보고 고른 것이다. 등급을 지우고 한 팔레트로 뭉뚱그리면 이 문서는 근거보다 많은 것을 주장하게 된다 [src:1][src:2].

## Brand & Style

우송 ESC 는 강의실 문 앞의 7.5인치 e-Paper 와 그것을 조작하는 웹으로 이루어진 캡스톤 프로젝트다. 관리자가 웹에서 시간표를 바꾸면 메인Pi → 모뎀Pi → LoRa → ESP노드를 거쳐 복도의 종이 화면이 갱신된다 [src:3]. **웹의 디자인은 그 파이프라인의 입구이자 감시창이다.**

시각 언어는 **흰 바탕 · 헤어라인 · 무채색 구조**다. 유채색은 둘뿐이다 — 브랜드 파랑은 1차 액션과 활성 상태에만, 적색은 "강의실이 쓰이고 있음"과 파괴적 동작에만 쓴다. 바탕·선·보조 텍스트에는 색을 쓰지 않는다 [src:1].

**도메인이 토큰 층까지 내려와 있다.** 색 시맨틱에 `brand`·`danger`·`focus` 와 **동급으로** `room.*` 그룹이 선다 — `room.busy` / `room.free`. 강의실 상태를 색으로 코드화한 축이며, 범용 UI 프레임워크에는 존재할 이유가 없는 개념이다. 이 둘은 단말 e-Paper 의 `layout` 1~8 RED/BLACK 이분법과 1:1 로 묶인다 [src:4]. 같은 성격이 컴포넌트 트리에도 있다 — 일반 분류(`ui/`) 옆에 `domain/`(`RoomTree` · `TypeBadge` · `SourceBadge` · `OutboxDot` · `SlotForm` · `SignalBars`)이 1급 폴더로 서고, 그 경계는 **"이 컴포넌트가 `schemas.py` 를 알아야 하나"** 로 가른다 [src:5].

**두 개의 표면이 하나의 색을 쓴다.** 관리자 웹(데스크톱 전용)과 학생 웹(모바일 우선)은 진입 도메인도 사용자도 다르지만 **색 토큰은 공용**이다. 관리자가 웹에서 바꾼 것이 학생이 보는 화면과 복도의 e-Paper 에 그대로 나타나는 시스템이라, 세 표면이 다른 색 언어를 쓰면 같은 강의실의 같은 상태가 다른 것처럼 보인다. **갈라지는 것은 색이 아니라 치수다** — `font.size` · `control.height` · `radius` 가 `admin` / `student` 두 세트로 나뉜다 [src:1].

전체 인상은 "조용한 업무 도구"다. 그라디언트·그림자·일러스트·이모지가 한 조각도 없다. 깊이는 면(`surface` vs `sunken`)과 테두리(`line.2`)에서만 오며, 그림자 토큰은 발행하지 않는다 [src:1].

**Voice.** 관리자 화면은 명사형 라벨(`슬롯 추가` · `선택한 곳 동기화` · `강의실 배정`)과 `-습니다` 체 안내를 쓴다. 학생 화면은 같은 존댓말이되 더 짧고 구어에 가깝다 — `5곳이 지금 비어 있어요`, `10:00 에 비어요`, `★ 을 눌러 모아둡니다`. 서버 에러 원문을 그대로 노출하지 않고 사람 문장으로 바꾼다("이 슬롯은 웹에서 수정된 행입니다. CSV 로 덮어쓸 수 없습니다") [src:5][src:6].

**시스템의 상태.** 색 토큰 3층 · 화면 스펙 6종 · 컴포넌트 24종 · 시안 아트보드 9장. 스택은 Vue 3 + TypeScript + Vite(pnpm)이고 [src:7], 구현은 아직 시작되지 않았다 — `web/src/styles/` 와 `web/src/components/` 는 `.gitkeep` 뿐이다. 이 문서는 **구현 이전의 계약**이다.

## Colors

구조는 **원시(Palette) → 시맨틱(Semantic) → 도메인(Domain) 3층**이다. 화면(`views/`)은 3층과 2층만 참조하고 1층을 직접 쓰지 않는다. 이 규율이 화면에서 임의로 색을 고를 여지를 없앤다 [src:1].

세 가지가 이 시스템의 색 설계를 규정한다.

1. **유채색은 둘뿐이다.** `brand` 파랑과 상태 적색. 그 외 색은 차트 계열색뿐이고 차트 밖으로 나오지 않는다.
2. **구조는 전부 무채색이다.** 바탕·선·보조 텍스트에 색을 쓰지 않는다. 위계는 크기·굵기·면으로 만든다.
3. **적색은 면이 아니라 라벨에 쓴다.** 셀을 통째로 적색으로 채우면 하루치만 차도 화면이 경고판으로 읽힌다. 연한 틴트(`red-50`)를 깔고 라벨만 진한 적색(`red-700`)으로 세운다.

아래 등급 표기는 gs-retail 문서의 방식을 따랐다 [src:2].

| 등급 | 근거 | 해당 토큰 | 차용 시 취급 |
| --- | --- | --- | --- |
| (A) 계산값 | WCAG 2.1 상대휘도 + OKLab ΔE 실측 | 유채색 5종 전부 · `gray` 램프의 대비 판정 | 그대로 쓴다. 바꾸려면 다시 계산해야 한다 |
| (B) 시안값 | 캔버스에서 그려 보고 고름 | `gray` 램프의 단계 간격 · 치수 전부 | 구현하며 조정 가능. 이름은 유지 |

### Semantic — 면 · 선 · 글자

wj 가 `web/src/styles/` 에서 쓰는 이름이다.

| token | → palette | 비고 |
| --- | --- | --- |
| `bg` | `gray-0` | 관리자 웹 페이지 바탕 |
| `bg.student` | `gray-25` | **학생 웹만** 바탕을 내린다 — 아래 주 |
| `surface` | `gray-0` | 카드 · 패널 |
| `sunken` | `gray-25` | 사이드바 · 표 헤더 |
| `line.1` | `gray-100` | 헤어라인(행·셀 구분) |
| `line.2` | `gray-200` | 카드 · 표 · 컨테이너 경계 |
| `line.3` | `gray-300` | 입력 테두리 · 차트 축 |
| `text.1` | `gray-800` | 본문 · 제목 |
| `text.2` | `gray-600` | 부차 텍스트 · 표 헤더 |
| `text.3` | `gray-500` | 보조 · 캡션 · 축 라벨 |
| `text.disabled` | `gray-400` | 비활성 표시. **읽혀야 하는 텍스트에 쓰지 않는다** |

> **왜 학생 웹만 바탕을 내리나** — 관리자 웹은 흰 바탕 위에 헤어라인으로 구획을 나눈다. 모바일에서 같은 방식을 쓰면 카드 경계가 사라져 층이 읽히지 않는다. 학생 웹은 바탕을 `gray-25` 로 내리고 카드를 흰색으로 띄워 **면으로** 층을 나눈다. **색 값은 그대로이고 배치만 뒤집힌다** [src:6].

### Semantic — 액션 · 상태

| token | → palette | 비고 |
| --- | --- | --- |
| `brand` | `blue-600` | **1차 액션과 활성 상태 전용.** 화면당 채워진 brand 버튼은 하나 |
| `brand.tint` | `blue-50` | 활성 메뉴 · 선택된 행 · 오늘 열 |
| `danger` | `red-700` | 삭제 · 에러 · 실패 |
| `focus` | `blue-600` | `outline: 2px solid; outline-offset: 2px` |

포커스 링에서 적색을 뺀 이유는 `room.busy` 와 섞이기 때문이다. 같은 이유로 "지금"을 가리키는 모든 표시(주간 격자의 현재 시각 선, 오늘 목록의 현재 행 배지)에도 `brand` 를 쓴다 — 적색은 '사용중' 전용이라 '지금'에 쓰면 두 뜻이 섞인다 [src:6].

### Domain — `room.*` 강의실 상태

| token | → palette | e-Paper | 해당 SlotType |
| --- | --- | --- | --- |
| `room.busy.fill` | `red-50` | RED (layout 1·5·6·7) | `CLASS`(1) · `EXAM`(2) · `SPECIAL`(5) · `RENTAL`(6) |
| `room.busy.line` | `red-100` | ″ | ″ |
| `room.busy.label` | `red-700` | ″ | ″ |
| `room.free.text` | `text.3` | BLACK (layout 2·3·4·8) | `CANCELLED`(3) · `EMPTY`(4) |
| `room.free.line` | `line.3` (점선) | ″ | ″ |

**수업중·시험중·특강·대여중에 서로 다른 색을 주지 않는다.** 넷은 전부 `room.busy` 하나이고 구분은 **라벨 텍스트가 전담한다.** 넷을 색으로 나누려면 같은 적색 계열 안에서 갈라야 하는데, 계산해 보면 서로의 대비가 1.02~1.88 이다 — 나눠도 나뉘지 않는다 [src:1].

**비어있음은 칠하지 않는다.** `EMPTY` 는 바탕 그대로 두고 아무것도 그리지 않는다. 이 규칙 덕분에 학생 웹의 주간 격자에서 **빈 칸이 곧 비어 있는 시간**이 되어, 학생이 찾는 것이 따로 표시 없이 읽힌다 [src:6].

### Domain — `chart.*` 계열색

유채색 둘로는 계열을 나눌 수 없어 **차트에만** 색을 더 연다. 아래 값은 검증기를 돌려 통과한 것이고, 임의로 바꾸면 통과하지 않는다 (A).

| token | → palette | 비고 |
| --- | --- | --- |
| `chart.series.1` | `blue-600` | 브랜드 파랑 겸용 |
| `chart.series.2` | `teal-600` | 전 쌍 통과, 경고 없음 |
| `chart.series.3` | `gold-600` | 대비 2.94 — **값 라벨 또는 표 병기 의무** |
| `chart.grid` / `chart.axis` / `chart.text` | `line.1` / `line.3` / `text.3` | |

검증 결과와 그로부터 나오는 규칙:

```
텍스트 대비 (흰 바탕):
  gray-800 #262626   15.13  PASS
  gray-600 #595959    7.00  PASS
  gray-500 #707070    4.95  PASS   ← 보조 텍스트 하한
  gray-400 #A6A6A6    2.43  FAIL   ← 텍스트 금지로 명시
  blue-600 #0B5ED7    5.84  PASS
  red-700  #B42318    6.57  PASS
  red-700 on red-50   5.91  PASS   ← 사용중 라벨

차트 계열색 (전 쌍, protan/deutan/tritan):
  #0B5ED7,#0D9488              ALL PASS, 경고 없음
  #0B5ED7,#0D9488,#CA8A04      ALL PASS + 대비 WARN(#CA8A04 2.94) → 값 라벨 의무
  4계열(+보라)                  FAIL  파랑↔보라 ΔE 1.8 (deutan)  → 4계열 이상 금지

danger 적색과 계열색 후보의 분리도:
  #B42318 ↔ #B45309   ΔE 8.6 (normal)  FAIL
  #B42318 ↔ #A16207   ΔE 12.4 (normal) FAIL   → 적색 인접 계열 금지
  #B42318 ↔ #CA8A04   ΔE 22.4 (normal) PASS
```

1. **계열은 고정 순서로 배정한다.** 필터로 계열 수가 바뀌어도 남은 계열의 색을 다시 칠하지 않는다.
2. **4계열 이상 금지.** 넷째부터는 "기타"로 접거나 차트를 쪼갠다.
3. **`danger` 적색을 계열색으로 재사용하지 않는다.** 위 ΔE 가 이유다.
4. **글자는 계열색을 입지 않는다.** 값·라벨·범례는 `text.*` 를 쓰고 옆의 색 마크가 정체성을 진다.
5. **한 축만 쓴다.** 좌우 y축 차트를 만들지 않는다.

### 색 사용 규칙 (요약)

- `brand` 는 **1차 액션과 활성 상태 전용**. 장식으로 쓰지 않는다 [src:1].
- 구조 요소(보더·배경·구분선)는 전부 `gray` 램프 파생이다 [src:1].
- 색조는 상태와 차트에만 산다. `room.*` 은 적색 하나, `chart.*` 는 차트 안에서만 [src:1].
- Toast 에 성공 색을 쓰지 않는다 — 바탕 `surface` + 테두리 `line.2`, `danger` 만 왼쪽에 3px 띠 [src:5].
- 모달 스크림은 **평면 `gray-800` 45%** 이며 블러가 없다 [src:5].

## Typography

| token | 값 |
| --- | --- |
| `font.family` | `{typography.font-sans}` |
| `font.weight.regular / medium / bold` | 400 / 500 / 700 |
| `line.tight / normal` | 1.25 / 1.5 |

크기는 화면별로 갈린다 (B):

| token | `admin` | `student` |
| --- | --- | --- |
| `font.size.xs` | 11px | 12px |
| `font.size.sm` | 12px | 13px |
| `font.size.md` | 13px | 15px |
| `font.size.lg` | 16px | 18px |
| `font.size.xl` | 22px | 20px |

숫자가 늘어서는 곳(시각·지연·건수·호수·MAC·학번)은 `font-variant-numeric: tabular-nums` 를 켠다. **별도 모노 서체를 끌어오지 않는다** — v1 에 있던 `font.family.mono` 를 삭제하고 tabular-nums 로 자릿수를 맞춘다 [src:1].

⚠ Pretendard 는 웹폰트이고 메인Pi 가 오프라인일 수 있으므로 **CDN 이 아니라 `web/src/assets/` 에 self-host** 한다. 서브셋 범위는 미확정이다 [src:1].

⚠ **시안은 Pretendard 로 그려지지 않았다.** 캔버스가 Google Fonts 만 쓸 수 있어 Noto Sans KR 로 대역했다. 자간·굵기 인상은 실물로 다시 봐야 한다 [src:8].

## Spacing

두 웹 공용. 4px 베이스 한 세트다 — 치수 중 유일하게 갈리지 않는 축이다.

| token | 값 |
| --- | --- |
| `space.1` … `space.7` | 4 / 8 / 12 / 16 / 24 / 32 / 48 px |

실측 치수 (B):

| 자리 | `admin` | `student` |
| --- | --- | --- |
| 컨트롤 높이 | 28 / 32px | 48px (터치 하한) |
| 표 행 | 32px (두 줄 셀 44px) | 리스트 56px |
| 주간 격자 행 (30분) | 44px | 24px |
| 사이드바 폭 | 220px | — |
| 강의실 트리 드롭다운 | 320px | — |

**학생 웹의 모든 터치 타깃은 48px 이상이다.** 관리자 웹에는 이 하한이 없다 [src:1].

## Rounded

| token | `admin` | `student` |
| --- | --- | --- |
| `radius.sm` | 4px | 6px |
| `radius.md` | 6px | 8px |
| `radius.lg` | 8px | 12px |
| `radius.full` | 999px | 999px |

관리자 쪽이 한 단계씩 작다. 밀도 높은 표와 격자에서 큰 라운드는 셀 경계를 흐린다. 학생 쪽은 손가락으로 누르는 카드라 한 단계 크다 [src:1].

## Elevation & Depth

**그림자 토큰을 발행하지 않는다.**

깊이는 두 수단에서만 온다 — **면**(`surface` vs `sunken`, 흰색과 `gray-25` 의 차이)과 **테두리**(`line.2` 1px). 그림자는 회색 반투명이라 "구조는 전부 무채색" 규율 안에서 다루기 어렵고, 층이 둘뿐인 화면에서 필요하지도 않다 [src:1].

예외는 둘이다.

- **모달**: 배경을 `gray-800` `opacity: .45` 로 덮는다. 블러 없음 [src:5].
- **드롭다운**(강의실 트리): 본문 위에 뜨므로 `line.3` 1px 테두리로 경계를 한 단계 강하게 준다. 그림자는 여전히 없다 [src:9].

## Shapes

**직사각 카드 + 원형 상태 표시**의 두 축이다.

정보는 모서리가 둥근 직사각 카드·표·격자에 담는다. 상태 표시만 원이다 — `OutboxDot`(8px 원, 전송 단계), 모뎀Pi 연결 점(6px), 즐겨찾기 ★. 기하 형태가 구조를 잡고 **점 하나가 상태를 진다** [src:5].

일러스트·마스코트·아이콘 세트를 쓰지 않는다. 아이콘이 필요한 자리는 텍스트 라벨로 대신하고, 불가피한 곳(`‹` 뒤로, `›` 더보기, `▼` 펼침, `◀ ▶` 주 이동)은 문자로 쓴다. EmptyState 에도 그림을 넣지 않는다 [src:5].

**`OutboxDot` 은 색이 아니라 채움 정도로 단계를 읽는다** — `queued` ○ 테두리만 / `dispatched` ◐ 반 채움 / `acked` ● 꽉 채움 / `failed` ● + `danger` / `cancelled` ○ + 사선. 이 규칙은 색 3값 시절(v1)에 만들어져 v2 까지 살아남은 유일한 표현 장치다 [src:1].

## Components

`components/ui/`(도메인을 모름) · `components/domain/`(서버 필드와 업무 규칙을 앎) · `components/chart/` 셋으로 나뉜다 [src:5].

### button

`variant` primary / secondary / danger / ghost, `size` sm / md. primary 는 `brand` 채움 + 흰 글자이고 **화면당 하나**다. `danger` 는 확인 모달 안에서만 나온다 — 표에 적색 버튼이 흔해지면 `room.busy` 와 섞인다. `disabled` 는 색상(hue)을 바꾸지 않고 `text.disabled` + `opacity: .6` 으로만 내린다 [src:5].

### input

`maxBytes` 가 **글자 수가 아니라 UTF-8 바이트를 센다.** `subject`·`professor` 가 바이트 상한이라 글자 수로 세면 한글에서 서버가 튕긴다. 남은 양을 `18 / 20 B` 로 보여준다 [src:5][src:10].

### table

`thead` 아래 `line.2` 2px, 행 사이 `line.1` 1px, **세로 구분선 없음**. 선택된 행은 `brand.tint` 바탕이다(v1 의 흑백 반전을 버렸다 — 반전은 행이 많을 때 화면을 뒤덮는다) [src:5].

### room-tree

건물 → 층 → 호수 3단 트리. 상단 네비게이션의 버튼을 누르면 펼쳐지는 320px 드롭다운이고, 버튼 라벨이 곧 현재 선택이다(`공학관 401 · 402 · 405 [3] ▼`). `mode: multi` 는 체크박스 + `indeterminate`, `single` 은 체크박스 없이 고르면 바로 닫힌다 [src:9].

**층은 서버에 없는 값이다.** `RoomOut` 에는 `building_id` 와 `room: int` 뿐이라 `floor = room // 100` 으로 화면이 파생한다(401→4층, 1203→12층, 100 미만은 '기타'). 서버에 컬럼을 더하지 않고, 드롭다운 바닥에 `층 = 호수 ÷ 100` 을 적어 관리자에게도 규칙을 알린다 [src:9][src:10].

### type-badge

`type` 1~6 을 라벨로 가른다 — 수업중 / 시험중 / 휴강 / 빈강의실 / 특강 / 대여중. 1·2·5·6 은 전부 같은 `room.busy` 색이고 **구분은 텍스트가 한다.** 이 매핑을 화면마다 다시 쓰지 않도록 컴포넌트가 진다 [src:5].

### source-badge

`source` 1 포털 / 2 수동 / 3 긴급. 이것이 없으면 CSV 재임포트 후 "왜 이 행만 안 바뀌지"를 설명할 방법이 없다 — 서버가 낮은 출처로 높은 출처를 덮지 못하게 막기 때문이다 [src:9][src:10].

### week-grid

요일 가로 × 시간 세로 격자. 관리자와 학생이 **같은 형태**를 쓰고 눈금만 다르다(30분 행이 관리자 44px, 학생 32/24px). 기본 범위는 09:00~18:00 18행이고 야간 슬롯이 있으면 22:00 까지 자동으로 편다 [src:9][src:6].

**겹침 규칙만 두 웹에서 갈린다** — 관리자는 반씩 쪼개고 겹친 구간에 `danger` 3px 막대를 긋는다(겹침을 해결해야 하니까). 학생은 겹친 `사용중` 블록을 **하나로 합친다**(`알고리즘 외 1건 · 10:00–13:00`). 학생에게 중요한 건 '누가 쓰는지'가 아니라 '쓰이는지'다 [src:6].

### signal-bars · node-state-badge

3칸 막대 + `−71 dBm` 숫자를 함께 보인다 — 막대만으로는 −71 과 −88 을 못 가르고 숫자만으로는 좋고 나쁨이 안 읽힌다. `NodeStateBadge` 는 서버가 판정한 `NodeOut.warnings[]` 를 받아 **하나의 배지**로 줄인다 — 화면이 임계값을 다시 계산하지 않는다 [src:11].

### histogram

`chart.*` 규칙을 그대로 따른다. 막대 폭 17px, 계열 간격 2px, 상단만 라운드. **값 라벨은 계열마다 가장 큰 막대에만** 붙인다 — 전부 적으면 격자가 숫자로 덮인다 [src:5][src:12].

## Do's and Don'ts

**Do**

- 회색이 필요하면 `gray` 램프를 쓰되 **`gray-400` 이하는 텍스트에 쓰지 않는다.** 흐리게 보이길 원하면 색을 내리기 전에 크기와 굵기를 먼저 내린다.
- 적색은 **라벨에** 쓴다. 면에 쓰려면 `red-50` 틴트까지다.
- 상태를 색으로만 구분하지 않는다. 배지에는 항상 라벨 텍스트가 있고, 전송 단계는 채움 정도로 말한다.
- 값은 숫자·색상코드·토큰 이름으로 적는다. "적당히", "약간 어둡게"는 코드로 옮길 수 없다 [src:13].
- 서버 필드명은 `schemas.py` 를 그대로 쓴다. 화면이 서버에 없는 필드를 요구하면 **서버(additive)가 먼저다** [src:13].

**Don't**

- **차트 계열색을 임의로 고르지 않는다.** 위 ΔE 표가 이유다. 넷째 계열을 만들지 않는다.
- **`danger` 적색을 계열색·포커스·"지금" 표시에 재사용하지 않는다.** 적색은 사용중과 파괴적 동작 전용이다.
- **그림자를 도입하지 않는다.** 층이 필요하면 면과 테두리로 나눈다.
- **KPI 타일에 추세 화살표를 넣지 않는다.** "지연이 줄었다"와 "실패가 늘었다"는 좋고 나쁨이 반대인데 같은 방향 화살표를 쓰면 거짓말이 된다. 비교값을 문장으로 적는다 [src:12].
- **배터리를 퍼센트로 환산하지 않는다.** 리튬 방전 곡선을 모르는 채 환산하면 없는 정밀도를 만든다. mV 를 V 로만 바꿔 적고 배터리 경고는 서버가 준 `warnings[]` 를 따른다 [src:11].
- **관리자 웹에 모바일 레이아웃을 만들지 않는다.** 아래 Responsive 참고.
- **스켈레톤 금지를 되살리지 않는다.** v1 에서 금지했던 이유(회색 의존)가 v2 에서 사라졌다.

## Responsive Behavior

**관리자 웹은 데스크톱 전용이다** (`bp.desktop` ≥ 1024px). 태블릿·모바일 레이아웃을 설계하지 않는다 — iPad 가로는 이미 1024px 이라 실질 대상이 세로 768px 하나뿐이고, 거기에 별도 레이아웃을 두면 유지비만 는다.

**다만 막지는 않는다.** 콘텐츠 컨테이너에 `min-width: 1024px` 를 두어 좁은 폭에서는 데스크톱 레이아웃이 그대로 가로 스크롤된다. 좁은 폭 첫 진입에 닫을 수 있는 안내 배너를 한 번 띄운다. 아이패드밖에 없는 상황에서 휴강 하나 못 고치면 곤란하다 [src:13].

**학생 웹은 모바일 우선이고 세 폭 모두에서 동작한다.**

| token | 값 | 주 대상 |
| --- | --- | --- |
| `bp.mobile` | `< 640px` | 학생 웹 |
| `bp.tablet` | `640 ~ 1023px` | 학생 웹만 |
| `bp.desktop` | `>= 1024px` | 관리자 웹 · 학생 웹 |

**넓은 폭에서 할 일은 키우기가 아니라 더 보여주기다.** 학생 웹의 1280px 레이아웃은 같은 라우트(`/{bld}/{room}`)에서 좌측에 강의실 목록을 상주시키고(폰에서는 뒤로가기로 오가던 것), 우측에 "다음 비는 시간" 카드와 이번 주 격자를 더한다. **색 값은 폭에 따라 바뀌지 않고** `student` 치수 세트와 배치만 바뀐다 [src:6].

## 서버 설계와의 정렬 (2026-09-23)

wj 가 PR #38 로 웹 백엔드 설계 3종(**S4a** 회원·인증 / **S4b** 관리자 API / **S10** 학생·분석)을 올렸고, 화면 스펙을 그에 맞췄다. 바뀐 것이 넷이다.

| | 이 문서의 이전 판 | 지금 (wj 설계 기준) |
| --- | --- | --- |
| 학생 인증 | 로그인 없음. 예약 시 학번+이름 입력 | **웹메일 가입 → 관리자 승인 → JWT 로그인** (S4a) |
| 예약 확정 | 신청 즉시 확정 | **신청 → 관리자 승인 → 확정** (S10) |
| 예약 id | 화면이 전역 범위에서 채번 | **서버가 빈 최소 id 배정** (S4b §2.5) |
| 학번 컬럼 | `applicant_id` additive 요청 | 불필요 — `requested_by` FK `users(email)` |

그 결과로 화면 둘이 새로 생겼다 — [auth.md](screens/auth.md)(가입·로그인·재설정)와 [admin-users.md](screens/admin-users.md)(회원 승인). 둘 다 아직 시안이 없다.

**요청하려던 API 셋은 전부 그 설계 안에 있다.** 건물 단위 조회(#36)는 S4b §2.6, 학생 공개 조회·예약은 S10 §4.1, 대시보드 집계는 S10 §4.3이다. 자체 제안했던 `/api/public/*` 과 `/api/lora/stats` 는 폐기했다.

한 가지가 열린 채 남았다 — **S10 은 조회 API 에도 `require_student` 를 건다.** "복도에서 폰으로 빨리 확인"이라는 학생 웹의 목적과 부딪히므로 wj 와 확인해야 한다.

## Known Gaps

1. **구현이 없다.** `web/src/styles/` 와 `web/src/components/` 가 `.gitkeep` 뿐이다. 이 문서의 모든 값은 아직 코드로 검증되지 않았다.
2. **시안 서체가 대역이다.** Pretendard 가 아니라 Noto Sans KR 로 그렸다. 자간·굵기 인상은 실물로 다시 봐야 하고, 서브셋 범위도 미정이다.
3. **시안에 대비 미달 잔재가 있다.** 날짜 라벨을 `#909090`(2.95:1)으로 그린 곳이 남아 있다 — 이 문서의 하한(`gray-500`) 아래다. 구현 시 올린다.
4. ~~`sync_state` 의 실제 문자열 값을 모른다~~ — S4b 가 `NodeOut.warnings[]` 로 답했다. 배지는 서버 판정만 읽는다. **`warnings` 의 문자열 집합과 정렬 순서**는 wj 확인 항목으로 남는다.
5. ~~서버에 없는 API 가 셋~~ — 전부 wj 의 PR #38 설계 안에 있다(위 절). 이슈 #36 도 S4b 가 답했다.
6. ~~`/api` 에 인증이 없다~~ — S4a 가 전부 `require_admin`/`require_student` + 학교 스코프로 닫는다. 조회에도 로그인이 필요한 점은 **로그인 벽 화면**으로 완화하기로 했다(PR #41 리뷰 — 학생 웹 §로그인 벽).
7. ~~학생 예약에 승인 단계가 없다~~ — S10 이 `requested → approved` 를 확정했다. 대신 **승인·거절 메일 알림이 후속**이라, 그때까지 학생은 `/me` 를 직접 열어 확인해야 한다.
8. **다크 모드는 범위 밖이다.** 넣는다면 `gray` 램프를 뒤집는 방식이고, 유채색은 다크 표면 기준으로 **다시 계산**해야 한다 — 밝기를 그냥 뒤집으면 통과하지 않는다.
