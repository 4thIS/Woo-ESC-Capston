# 관리자 — 강의실 설정 (페이지1)

- 시안: https://claude.ai/artifact/NLQyYEEdt4Rv6Dn7JZZuHi
- 소비자: wj → `web/src/views/`
- 전제: `tokens.md` v2 (`admin` 치수 세트) · `components.md`
- 대상: **데스크톱 전용** (`bp.desktop` ≥ 1024px). 태블릿·모바일 레이아웃을 만들지 않는다 — `README.md` 규칙. 컨테이너 `min-width: 1024px` + 가로 스크롤, 좁은 폭 첫 진입 시 안내 배너 1회

## 목적 · 진입

건물 하나를 골라 **그 건물의 모든 강의실**의 시간표·예약·시험기간을 한 화면에서 만들고 고친다. 관리자 웹의 기본 화면이다.

강의실 하나의 일주일을 눈으로 확인하는 것은 이 화면이 하지 않는다 — 표의 호수를 누르면 [페이지2 주간 시간표](admin-schedule.md)로 간다.

## 레이아웃

```
┌─ 상단 ────────────────────────────────────────────────┐
│ 건물 [사회관 ▾]   강의실 [401 ▾]   [CSV 가져오기] [전체 동기화] │
└───────────────────────────────────────────────────────┘
┌─ 시간표 ──────────────────────────────── [+ 슬롯 추가] ┐
│ 필터: 호수[전체▾] 요일[전체▾] 유형[전체▾]                 │
│ 호수 │ 요일 │ 시작 │ 종료 │ 과목명 │ 교수 │ 유형 │ 출처 │ 작업 │
└───────────────────────────────────────────────────────┘
┌─ 예약 ──────────────────────────────────── [+ 예약 추가] ┐
│ 호수 │ 날짜 │ 요일 │ 시작 │ 종료 │ 과목명 │ 교수 │ 유형 │ 작업 │
└───────────────────────────────────────────────────────┘
┌─ 시험기간 ───────────────────────────────── [+ 기간 추가] ┐
│ 호수 │ 시작일 │ 종료일 │ 작업                              │
└───────────────────────────────────────────────────────┘
```

- 세 블록은 **탭이 아니라 세로 스택**이다. 셋이 같은 강의실의 서로 다른 시간 축이고, 시험기간이 어느 예약·수업 위에 겹치는지는 함께 보아야 보인다. 탭이면 오가며 기억해야 한다.
- 블록은 카드(`surface` + `line.2` 1px + `radius.lg`). 블록 사이 `space.5`.
- 상단 바는 스크롤해도 붙어 있다(`position: sticky`). 건물을 바꾸면 세 표가 함께 갈린다.
- **상단의 `강의실` Select는 필터가 아니다.** "+ 추가"로 새 행을 만들 때 채워지는 **기본 호수**다. 필터는 각 표의 `호수` 컬럼 필터가 따로 한다. 둘을 같은 것으로 오해하지 않도록 라벨을 `새 행 기본값`으로 쓴다.

## 사용하는 컴포넌트

Select(건물·강의실·필터), Button(`primary` 추가 / `secondary` CSV·동기화 / `ghost` 행 작업), Table, Badge(유형·출처), Modal(추가·수정 폼, 삭제 확인), Toast, OutboxDot, EmptyState, Loading

**추가와 수정은 같은 폼 컴포넌트를 쓴다.** 페이지2의 셀 편집도 같은 폼이다 — 편집 경로가 셋(이 표 · 페이지2 셀 · CSV)인데 검증 규칙이 갈라지면 같은 데이터가 경로마다 다르게 들어간다.

## 데이터 (서버 계약)

필드명은 `server/app/schemas.py` 그대로.

| 하는 일 | 엔드포인트 | 비고 |
|---|---|---|
| 건물 목록 | `GET /buildings` → `BuildingOut{id, name, bld, modem_id}` | |
| 강의실 목록 | `GET /rooms` → `RoomOut{id, building_id, room, units}` | **필터 파라미터가 없다.** 전체를 받아 `building_id`로 프론트에서 거른다 |
| 시간표 조회 | `GET /rooms/{id}/slots` → `SlotOut[]` | |
| 시간표 추가·수정 | `PUT /rooms/{id}/slots` (`SlotIn` 한 건) | 키 = `day`+`s_h`+`s_m`. **벌크가 아니다** |
| 시간표 삭제 | `DELETE /rooms/{id}/slots/{day}/{s_h}/{s_m}` | |
| 하루 비우기 | `DELETE /rooms/{id}/slots?day=N` | |
| 예약 조회·추가 | `GET` · `POST /rooms/{id}/reservations` (`ResvIn`) | |
| 예약 삭제 | `DELETE /rooms/{id}/reservations/{resv_id}` | |
| 시험기간 조회·추가 | `GET` · `POST /rooms/{id}/exams` (`ExamIn`) | **강의실별이다** (`ExamPeriod.room_id`) |
| 시험기간 삭제 | `DELETE /rooms/{id}/exams/{exam_id}` | |
| CSV 가져오기 | `POST /import/slots` (본문 `text/csv`, `?dry_run=true`) | 1 MB 초과 413, UTF-8 아니면 400 |
| 강제 재전송 | `POST /rooms/{id}/sync` (`SyncIn.kinds`) | |

`유형`(`type` 1~6) = 1 수업 · 2 시험 · 3 휴강 · 4 빈강의실 · 5 특강 · 6 대여 (`lora_proto/proto.h` `LP_SLOTTYPE_*`).

`subject`·`professor`는 글자 수가 아니라 **UTF-8 바이트** 상한(`P.SUBJ_MAX`/`P.PROF_MAX`)이다. 입력에서 바이트로 세어 남은 양을 보여준다 — 한글은 3바이트라 글자 수로 세면 서버에서 튕긴다.

> ⚠ **건물 단위 조회 API가 없다.** 지금 조회는 전부 강의실 단위라 건물 전체 표를 그리려면 강의실 수만큼 호출해야 한다(20개면 20번). wj에게 `GET /buildings/{id}/slots|reservations|exams`를 additive로 요청 중이며, **이 화면은 그 API를 전제로 쓴다.** 서버가 먼저 들어간 뒤 구현한다.

## 화면이 반드시 다뤄야 하는 서버 동작

이 셋은 서버가 이미 그렇게 동작하고 있어서, 화면이 모르면 관리자가 이유 없는 실패를 본다.

### 1. `source` 보호 — 낮은 출처가 높은 출처를 덮지 못한다

`PUT /rooms/{id}/slots`는 기존 슬롯의 `source`가 보내는 `source`보다 크면 **409**를 낸다.

```
source 1 = 포털(CSV 임포트)   2 = 수동(웹에서 입력)   3 = 긴급
기존 2 ← 새 1  →  409 "source 2 슬롯은 source ≥ 2 로만 수정"
```

즉 **CSV를 다시 임포트해도 손으로 고친 행은 덮이지 않는다.** 이건 기능이지 버그가 아니다.

화면 규칙:
- `출처` 컬럼을 **반드시 둔다.** 이게 없으면 CSV 임포트 후 "왜 이 행만 안 바뀌지"를 설명할 방법이 없다.
- Badge: `포털`(테두리만) / `수동`(채움) / `긴급`(`danger` 테두리). 색으로만 구분하지 않고 라벨을 쓴다.
- 웹에서 직접 만든 슬롯은 `source: 2`로 보낸다(`SlotIn.source` 기본값).
- 409를 받으면 Toast(danger): **"이 슬롯은 웹에서 수정된 행입니다. CSV로 덮어쓸 수 없습니다."** 원문 그대로 노출하지 않는다.
- CSV 임포트 결과 요약(`ImportSummary`)에 건너뛴 행이 있으면 그 사유를 표로 보여준다(`ImportSkipped{row, reason}`).

### 2. 예약 7일 지평 — 저장은 되지만 전송은 안 된다

`POST /rooms/{id}/reservations`는 `오늘 ≤ date ≤ 오늘+7`일 때만 노드로 프레임을 보낸다(`RESV_HORIZON_DAYS = 7`). 범위 밖이면 DB에는 저장되고 **`outbox_ids`가 빈 배열**로 돌아온다.

화면 규칙:
- **빈 `outbox_ids`를 실패로 표시하지 않는다.** 저장은 성공했다.
- 그 행의 OutboxDot 자리에 점 대신 `예정` 배지를 두고, 툴팁에 **"7일 이내로 들어오면 자동 전송됩니다"**.
- 예약 폼에서 날짜를 7일 밖으로 고르면 저장 전에 같은 문구를 hint로 미리 보여준다. 막지는 않는다.

### 3. 예약·시험기간 id는 화면이 정한다

`ResvIn.id`·`ExamIn.id`(1~65535)는 **클라이언트가 채우는 필수 값**이고, 서버는 그 id로 upsert한다(`s.get(Reservation, body.id) or ...`). PK가 id 단독이라 **id는 강의실별이 아니라 전역**이다.

그래서 강의실마다 1번부터 붙이면 **다른 강의실의 예약을 덮어쓴다.**

화면 규칙:
- id를 관리자에게 노출하지 않는다. 화면이 자동으로 채번한다.
- 채번 범위는 **전역**이다 — 건물 단위 조회 API(위 ⚠)에 예약·시험을 포함시켜 받고, 사용 중이지 않은 최소값을 쓴다.
- 채번에 쓸 목록을 못 받은 상태에서는 추가 버튼을 `disabled`로 두고 "목록을 불러오는 중"으로 둔다. 모르는 채로 번호를 찍지 않는다.

> 전역 id가 의도인지 강의실별이어야 하는지는 서버 쪽 판단이 필요하다. 화면은 **전역으로 가정**하고 그리며, 서버가 강의실별로 바뀌면 채번 범위만 좁히면 된다(화면 구조는 그대로).

## 시험기간 — 강의실별이되 한 번에 여러 강의실

시험기간은 **강의실마다 따로** 둔다(`ExamPeriod.room_id`). 다만 실제로는 "이 건물 3층 전부 같은 기간"처럼 묶어서 넣는 일이 많으므로, 폼에서 **강의실을 여러 개 고를 수 있게** 한다.

- 폼: `강의실(다중 선택)` · `시작일` · `종료일`. 강의실 다중 선택은 체크박스 목록(그 건물의 강의실 전체) + `전체 선택`.
- 저장하면 **고른 강의실 수만큼 `POST /rooms/{id}/exams`** 를 보낸다. 서버에 벌크 엔드포인트는 없다.
- `id`는 강의실마다 **따로 채번한다.** id가 전역이므로(위 §3) 같은 번호를 여러 강의실에 쓰면 서로 덮어쓴다. 3개 강의실을 고르면 미사용 id 3개가 필요하다.
- **일부만 실패해도 되돌리지 않는다.** 성공한 강의실은 그대로 두고, Toast에 "7개 중 5개 적용 · 402호, 405호 실패"로 알린 뒤 실패한 것만 표에서 `재시도` 버튼으로 남긴다. 되돌리려면 성공분을 DELETE 해야 하는데 그 DELETE도 실패할 수 있어 상태가 더 불분명해진다.
- 진행 중에는 버튼을 `loading`으로 잠그고 "3/7 적용 중"을 라벨에 쓴다. 강의실 20개면 20번 왕복이라 체감이 길다.

표에는 `호수` 컬럼이 있으므로 같은 기간이 여러 행으로 나열된다. 같은 `시작일`·`종료일`을 가진 행은 **호수만 묶어 한 행으로 접어** 보여주고(`401, 402, 405 외 4곳`), 펼치면 개별 행이 된다. 수정·삭제는 펼친 개별 행에서 한다.

## 상태

- **로딩**: 각 표의 본문 자리에 Loading. 헤더는 유지한다. (스켈레톤 허용 — `tokens.md` v2에서 회색이 생겼다)
- **빈 상태**: 시간표 — "이 건물에 등록된 시간표가 없습니다" + `CSV 가져오기` · `슬롯 추가`. 예약·시험기간 — "등록된 항목이 없습니다" + 추가 버튼.
- **에러**: 상단 Toast(danger) + 재시도. 표는 이전 내용을 지우지 않는다.
- **저장 후**: 행 우측에 OutboxDot(`queued → dispatched → acked`). `failed`면 점이 `danger`가 되고 행 끝에 `재전송` `ghost` 버튼이 붙는다(`POST /rooms/{id}/sync`).
- **CSV 검증 실패**: 400 응답의 `errors[]`를 표로 — 행 번호와 사유. 이때 **아무것도 적용되지 않았음**을 문구로 분명히 한다(전체 검증 후 적용이라 부분 적용이 없다).

## 상호작용

- `+ 추가` → 폼 Modal. 호수는 상단 `새 행 기본값`으로 미리 채운다.
- 행 `수정` → 같은 폼 Modal, 값 채움. 시간표는 키(`day`+`s_h`+`s_m`)가 바뀌면 **기존 행 삭제 후 새로 추가**한다 — `PUT`은 키로 찾으므로 시작 시각을 바꾸면 옛 행이 남는다.
- 행 `삭제` → 확인 Modal + `danger` 버튼. 본문에 지울 대상을 그대로 적는다("월 09:00 캡스톤디자인").
- `호수` 클릭 → 페이지2.
- **겹침 검사는 화면이 먼저 한다.** 서버는 같은 키(`day`+`s_h`+`s_m`)만 막으므로 09:00–11:00과 10:00–12:00이 둘 다 들어간다. 폼에서 저장 전에 같은 강의실·같은 요일의 기존 구간과 겹치면 에러로 막는다.
- `CSV 가져오기` → 파일 선택 후 **먼저 `?dry_run=true`로 보낸다.** 요약을 보여주고 관리자가 확인한 뒤 실제 적용한다.
