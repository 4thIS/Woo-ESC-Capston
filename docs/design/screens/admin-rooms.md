## 목적 · 진입

왼쪽 트리에서 **강의실을 여러 개 골라** 그 범위의 시간표·예약·시험기간을 한 화면에서 만들고 고친다. 관리자 웹의 기본 화면이다.

강의실 하나의 일주일을 눈으로 확인하는 것은 이 화면이 하지 않는다 — 표의 호수를 누르면 [페이지2 주간 시간표](admin-schedule.md)로 간다.

## 강의실 트리 — 상단 네비게이션의 드롭다운

**상단 바의 버튼 하나**가 현재 선택을 말하고, 누르면 아래로 320px 트리가 펼쳐진다. **건물 → 층 → 호수 3단**이고 호수가 체크박스다.

> **왜 왼쪽 세로 패널이 아닌가** — 처음에는 258px 세로 패널로 그렸다. 그러면 과목명 폭이 490px에서 **236px로 줄어든다.** 세로 패널은 가로를 영구히 먹는데, **강의실을 고르는 일은 가끔이고 표를 읽는 일은 내내다.** 드롭다운으로 옮기면 열려 있는 동안만 자리를 쓰고, 닫히면 표가 폭을 되찾는다.

버튼 라벨이 곧 현재 선택이다 — `공학관 401 · 402 · 405 [3] ▼`. 눌러야 아는 게 아니라 **닫혀 있어도 읽힌다.** 넷 이상이면 `공학관 401 외 3곳 [4]`으로 줄인다.

페이지2도 같은 자리에 같은 버튼을 둔다(단일 선택). 화면을 옮겨도 선택 장치가 움직이지 않는다.

| 누르면 | 되는 일 |
|---|---|
| 건물 | 그 건물의 모든 강의실 선택 / 해제 |
| 층 | 그 층의 모든 강의실 선택 / 해제 |
| 호수 | 그 하나만 |
| 일부만 골라진 부모 | `indeterminate`(막대) 로 표시 |

드롭다운은 바깥을 누르거나 Esc로 닫힌다. 선택은 **닫을 때가 아니라 체크하는 즉시** 표에 반영된다 — `확인` 버튼을 두지 않는다.

**Select 두 개와 표의 `호수` 필터가 이 트리 하나로 대체됐다.** 고른 것이 곧 화면의 범위이고, 같은 일을 하는 장치가 셋이던 것이 하나가 됐다.

따라서 없어진 것:

- `건물` Select — 트리의 최상위가 건물이다
- `새 행 기본값` Select — 새 행의 기본 호수는 **선택된 것 중 첫 번째**다
- 표의 `호수` 필터 — 트리가 한다. `요일`·`유형` 필터만 블록 헤더에 남는다
- 시험기간의 강의실 다중 선택 폼 — 트리에서 고르고 `+ 선택한 3곳에 기간 추가`를 누른다

`전체 동기화`는 **`선택한 곳 동기화`**가 됐다. 건물 전체를 실수로 재전송할 일이 줄어든다.

### ⚠ 층은 서버에 없는 값이다

`RoomOut`에는 `building_id`와 `room: int`뿐이고 **층 필드가 없다.** 화면이 호수에서 파생한다.

```
floor = room // 100      401 → 4층,  1203 → 12층
room < 100               '기타' 층으로 묶는다 (예: 5호)
```

서버에 컬럼을 더하지 않는다 — 한 건물의 강의실 수가 수십 개라 프론트에서 그룹핑하는 비용이 작고, 층 표기 규칙이 건물마다 달라지면 화면만 고치면 된다. 드롭다운 바닥에 `층 = 호수 ÷ 100`을 적어 이 규칙을 관리자에게도 알린다.

검색창에 호수를 치면 트리가 그 호수만 남기고 접힌다. 선택 상태는 검색과 무관하게 유지한다.

### 컬럼

| 컬럼 | 정렬 | 폭 | 비고 |
|---|---|---|---|
| 호수 | 좌 | 72px | 누르면 페이지2로 (`ghost` 링크) |

| 교수 · 신청자 | 좌 | 96px | `professor`. 예약 표에서는 라벨이 `신청자` |
| 학번 | 좌 | 88px | **예약 표에만.** 학생이 신청한 건만 값이 있고 관리자가 넣은 건 `—` |

세로 구분선은 긋지 않는다. 열은 정렬과 `space.3` 이상의 여백으로 나뉜다(`tokens.md` — 선을 덜 긋는다).

1440px에서 사이드바 220px만 빼면 **과목명에 490px이 남는다.** 트리를 드롭다운으로 올린 덕분이다 — 세로 패널이었다면 236px이었다. "임베디드 초청강연" 같은 긴 이름도 말줄임 없이 들어간다.

**행 수가 진짜 문제다.** 한 건물에 142건이면 트리에서 건물 전체를 고른 채로 표가 4500px이 된다. 트리로 층이나 강의실 몇 개만 고르는 것이 기본 사용이고, `요일`·`유형` 필터가 그 위에서 더 좁힌다.

## 사용하는 컴포넌트

RoomTree(`mode: multi`), Select(요일·유형 필터), Button(`primary` 추가 / `secondary` CSV·동기화 / `ghost` 행 작업), Table, Badge(유형·출처), Modal(추가·수정 폼, 삭제 확인), Toast, OutboxDot, EmptyState, Skeleton

**추가와 수정은 같은 폼 컴포넌트를 쓴다.** 페이지2의 셀 편집도 같은 폼이다 — 편집 경로가 셋(이 표 · 페이지2 셀 · CSV)인데 검증 규칙이 갈라지면 같은 데이터가 경로마다 다르게 들어간다.

## 데이터 (서버 계약)

필드명은 `server/app/schemas.py` 그대로.

| 하는 일 | 엔드포인트 | 비고 |
|---|---|---|
| 건물 목록 | `GET /buildings` → `BuildingOut{id, name, bld, modem_id}` | |
| 강의실 목록 | `GET /rooms` → `RoomOut{id, building_id, room, units}` | **필터 파라미터가 없다.** 전체를 받아 `building_id`로 프론트에서 거른다 |
| 시간표 조회 | `GET /rooms/{id}/slots` → `SlotOut[]` | |
| 시간표 추가·수정 | `PUT /rooms/{id}/slots` (`SlotIn` 한 건) | 키 = `day`+`s_h`+`s_m`. **벌크가 아니다** |
| 시간표 삭제 | `DELETE /rooms/{id}/slots/{day}/{s_h}/{s_m}` | |
| 하루 비우기 | `DELETE /rooms/{id}/slots?day=N` | |
| 예약 조회·추가 | `GET` · `POST /rooms/{id}/reservations` (`ResvIn`) | 학생이 신청한 것과 같은 테이블이다 |
| 예약 삭제 | `DELETE /rooms/{id}/reservations/{resv_id}` | |
| 시험기간 조회·추가 | `GET` · `POST /rooms/{id}/exams` (`ExamIn`) | **강의실별이다** (`ExamPeriod.room_id`) |
| 시험기간 삭제 | `DELETE /rooms/{id}/exams/{exam_id}` | |
| CSV 가져오기 | `POST /import/slots` (본문 `text/csv`, `?dry_run=true`) | 1 MB 초과 413, UTF-8 아니면 400 |
| 강제 재전송 | `POST /rooms/{id}/sync` (`SyncIn.kinds`) | |

`유형`(`type` 1~6) = 1 수업 · 2 시험 · 3 휴강 · 4 빈강의실 · 5 특강 · 6 대여 (`lora_proto/proto.h` `LP_SLOTTYPE_*`).

`subject`·`professor`는 글자 수가 아니라 **UTF-8 바이트** 상한(`P.SUBJ_MAX`/`P.PROF_MAX`)이다. 입력에서 바이트로 세어 남은 양을 보여준다 — 한글은 3바이트라 글자 수로 세면 서버에서 튕긴다.

**건물 단위 조회는 S4b 에서 확정됐다**(이슈 #36). 네 개다:

```
GET /api/buildings/{id}/slots          → SlotWithRoom[]   (SlotOut + room_id)
GET /api/buildings/{id}/reservations   → ResvWithRoom[]   (ResvOut + room_id)
GET /api/buildings/{id}/exams          → ExamWithRoom[]   (ExamOut + room_id)
GET /api/buildings/{id}/outbox?state=  → FailedOut[]      (outbox + room_id + building)
```

쓰기는 지금처럼 `/rooms/{id}/...` 다. 그래서 이 화면은 **조회 3번 + 쓰기는 행 단위**로 돈다.

모든 `/api/**` 가 `require_admin` + 학교 스코프다(S4a §3.2). 타 학교 리소스는 403이 아니라 **404** 이므로, 화면은 권한 오류를 "없음"으로 다룬다 — 존재를 숨기려는 서버 의도를 화면이 되돌리지 않는다.

## 화면이 반드시 다뤄야 하는 서버 동작

이 셋은 서버가 이미 그렇게 동작하고 있어서, 화면이 모르면 관리자가 이유 없는 실패를 본다.

### 1. `source` 보호 — 낮은 출처가 높은 출처를 덮지 못한다

`PUT /rooms/{id}/slots`는 기존 슬롯의 `source`가 보내는 `source`보다 크면 **409**를 낸다.

```
source 1 = 포털(CSV 임포트)   2 = 수동(웹에서 입력)   3 = 긴급
기존 2 ← 새 1  →  409 "source 2 슬롯은 source ≥ 2 로만 수정"
```

즉 **CSV를 다시 임포트해도 손으로 고친 행은 덮이지 않는다.** 이건 기능이지 버그가 아니다.

화면 규칙:
- `출처` 컬럼을 **반드시 둔다.** 이게 없으면 CSV 임포트 후 "왜 이 행만 안 바뀌지"를 설명할 방법이 없다.
- Badge: `포털`(테두리만) / `수동`(채움) / `긴급`(`danger` 테두리). 색으로만 구분하지 않고 라벨을 쓴다.
- 웹에서 직접 만든 슬롯은 `source: 2`로 보낸다(`SlotIn.source` 기본값).
- 409를 받으면 Toast(danger): **"이 슬롯은 웹에서 수정된 행입니다. CSV로 덮어쓸 수 없습니다."** 원문 그대로 노출하지 않는다.
- CSV 임포트 결과 요약(`ImportSummary`)에 건너뛴 행이 있으면 그 사유를 표로 보여준다(`ImportSkipped{row, reason}`).

### 2. 예약 7일 지평 — 저장은 되지만 전송은 안 된다

`POST /rooms/{id}/reservations`는 `오늘 ≤ date ≤ 오늘+7`일 때만 노드로 프레임을 보낸다(`RESV_HORIZON_DAYS = 7`). 범위 밖이면 DB에는 저장되고 **`outbox_ids`가 빈 배열**로 돌아온다.

화면 규칙:
- **빈 `outbox_ids`를 실패로 표시하지 않는다.** 저장은 성공했다.
- 그 행의 OutboxDot 자리에 점 대신 `예정` 배지를 두고, 툴팁에 **"7일 이내로 들어오면 자동 전송됩니다"**.
- 예약 폼에서 날짜를 7일 밖으로 고르면 저장 전에 같은 문구를 hint로 미리 보여준다. 막지는 않는다.

### 3. 예약·시험기간 id는 **서버가** 정한다

`ResvIn.id`·`ExamIn.id` 가 **선택**이 됐다(S4b §2.5). 보내지 않으면 서버가 1~65535 중 비어 있는 최소값을 배정하고 응답 `Enqueued` 에 `id` 를 담아 돌려준다.

화면 규칙:
- **채번하지 않는다.** 추가할 때 `id` 를 빼고 보내고, 응답의 `id` 를 받아 쓴다.
- 수정은 그 `id` 로 다시 POST한다. 같은 방이면 수정, **다른 방이면 409**다 — 방을 옮기려면 삭제 후 재생성이다.
- `학생 신청(requested)` 행에 관리자 CRUD로 덮어쓰려 하면 409다. 신청은 아래 「신청 대기」에서 승인·거절로 다룬다.
- id 소진(65535 전부) 409 `id 소진 — 지난 예약·시험기간을 정리하세요` 는 Toast(danger)로 그대로 전한다. 04:00 일일 작업이 지난 예약을 지워 id를 돌려주므로 흔하지 않다.

> 이 문서의 이전 판은 "화면이 전역 범위에서 채번한다"였다. 이슈 #36의 곁다리로 물었던 것을 wj가 **서버 채번**으로 답하면서 화면에서 채번 로직이 통째로 사라졌다.

## 시험기간 — 강의실별이되 한 번에 여러 강의실

시험기간은 **강의실마다 따로** 둔다(`ExamPeriod.room_id`). 다만 실제로는 "이 건물 3층 전부 같은 기간"처럼 묶어서 넣는 일이 많으므로, 폼에서 **강의실을 여러 개 고를 수 있게** 한다.

- **강의실을 고르는 것은 왼쪽 트리가 한다.** 폼 안에 강의실 목록을 따로 두지 않는다 — 폼에는 `시작일`·`종료일`만 있고, 버튼이 `+ 선택한 3곳에 기간 추가`로 대상 수를 말한다. 트리에서 `4층`을 누르면 그 층 전체가 대상이 된다.
- 저장하면 **고른 강의실 수만큼 `POST /rooms/{id}/exams`** 를 보낸다. 서버에 벌크 엔드포인트는 없다.
- `id`는 강의실마다 **따로 채번한다.** id가 전역이므로(위 §3) 같은 번호를 여러 강의실에 쓰면 서로 덮어쓴다. 3개 강의실을 고르면 미사용 id 3개가 필요하다.
- **일부만 실패해도 되돌리지 않는다.** 성공한 강의실은 그대로 두고, Toast에 "7개 중 5개 적용 · 402호, 405호 실패"로 알린 뒤 실패한 것만 표에서 `재시도` 버튼으로 남긴다. 되돌리려면 성공분을 DELETE 해야 하는데 그 DELETE도 실패할 수 있어 상태가 더 불분명해진다.
- 진행 중에는 버튼을 `loading`으로 잠그고 "3/7 적용 중"을 라벨에 쓴다. 강의실 20개면 20번 왕복이라 체감이 길다.

표에는 `호수` 컬럼이 있으므로 같은 기간이 여러 행으로 나열된다. 같은 `시작일`·`종료일`을 가진 행은 **호수만 묶어 한 행으로 접어** 보여주고(`401, 402, 405 외 4곳`), 펼치면 개별 행이 된다. 수정·삭제는 펼친 개별 행에서 한다.

## 신청 대기 — 예약 블록 위에 선다

학생 신청은 **승인을 기다린다**(S10 §0 — 2026-09-23 확정). 승인해야 `approved` 가 되어 노드로 나간다. 그래서 예약 블록 위에 **신청 대기 블록**이 하나 더 있다.

```
┌─ 신청 대기 ──────────────────────────────── 2건 ─┐
│ 신청자 │ 호수 │ 날짜 │ 시간 │ 용도 │ 신청 시각 │ 작업 │
│ 김민준 │ 401  │10-24 │10:00–12:00│캡스톤 스터디│2시간 전│[승인][거절]│
└──────────────────────────────────────────────────┘
```

- **0건이면 블록 자체를 감춘다.** 평소에 비어 있는 블록이 상시로 자리를 차지하면 다른 표를 밀어낸다.
- 정렬은 **오래된 순**. 먼저 온 신청을 먼저 본다.
- `승인` 은 `primary`, `거절` 은 `ghost`. 거절은 **사유가 필수**라 Modal을 거친다(`POST /reject {reason}` — 사유가 학생에게 그대로 보인다).
- 신청자는 `requester{email, name, student_no}` 로 온다. 표에는 **이름만** 두고 학번·메일은 툴팁으로 민다 — 목록을 넓히지 않으면서 본인 확인은 되게.
- **승인이 실패할 수 있다.** 사이에 관리자가 직접 예약을 넣었으면 겹침 재검사에서 409, 이미 시작한 신청도 409다(S10 §2.4). Toast(danger)로 이유를 말하고 목록을 새로고침한다.

### 예약 표는 신청과 한 테이블이다

같은 `reservations` 에 `status` 로 갈린다. 예약 블록은 **`approved` 만** 보여주고, 나머지는 신청 대기 블록과 이력에서 다룬다.

| 컬럼 | 관리자가 넣은 것 | 학생이 신청한 것 |
|---|---|---|
| `subject` | 행사명 ("신입생 오리엔테이션") | 용도 ("캡스톤 스터디") |
| `professor` | 주관 부서 ("학생처") | **빈 문자열** |
| `requested_by` | `—` (`NULL`) | 신청자 email |
| `type` | 상황에 따라 | 항상 6 대여 |
| `checked_in_at` | — | 체크인 시각 또는 `—` |

`신청자` 컬럼(`requested_by` 의 이름)이 둘을 가른다. **`applicant_id`(학번) 컬럼을 따로 두지 않는다** — 이전 판에서 additive 로 요청하려던 것인데, S4a 가 회원을 만들면서 `requested_by` FK 하나로 해결됐다.

**문 앞 e-Paper 에는 학생 예약의 과목이 `"학생 예약"` 으로 나간다**(S10 §2.5). 관리자 화면에만 실제 용도가 보인다.

## 상태

- **로딩**: 각 표의 본문 자리에 Loading. 헤더는 유지한다. (스켈레톤 허용 — `tokens.md` v2에서 회색이 생겼다)
- **빈 상태**: 시간표 — "이 건물에 등록된 시간표가 없습니다" + `CSV 가져오기` · `슬롯 추가`. 예약·시험기간 — "등록된 항목이 없습니다" + 추가 버튼.
- **에러**: 상단 Toast(danger) + 재시도. 표는 이전 내용을 지우지 않는다.
- **저장 후**: 행 우측에 OutboxDot(`queued → dispatched → acked`). `failed`면 점이 `danger`가 되고 행 끝에 `재전송` `ghost` 버튼이 붙는다(`POST /rooms/{id}/sync`).
- **CSV 검증 실패**: 400 응답의 `errors[]`를 표로 — 행 번호와 사유. 이때 **아무것도 적용되지 않았음**을 문구로 분명히 한다(전체 검증 후 적용이라 부분 적용이 없다).

## 상호작용

- `+ 추가` → 폼 Modal. 호수는 상단 `새 행 기본값`으로 미리 채운다.
- 행 `수정` → 같은 폼 Modal, 값 채움. 시간표는 키(`day`+`s_h`+`s_m`)가 바뀌면 **기존 행 삭제 후 새로 추가**한다 — `PUT`은 키로 찾으므로 시작 시각을 바꾸면 옛 행이 남는다.
- 행 `삭제` → 확인 Modal + `danger` 버튼. 본문에 지울 대상을 그대로 적는다("월 09:00 캡스톤디자인").
- `호수` 클릭 → 페이지2.
- **겹침 검사는 화면이 먼저 한다.** 서버는 같은 키(`day`+`s_h`+`s_m`)만 막으므로 09:00–11:00과 10:00–12:00이 둘 다 들어간다. 폼에서 저장 전에 같은 강의실·같은 요일의 기존 구간과 겹치면 에러로 막는다.
- `CSV 가져오기` → 파일 선택 후 **먼저 `?dry_run=true`로 보낸다.** 요약을 보여주고 관리자가 확인한 뒤 실제 적용한다.
