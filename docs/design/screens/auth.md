# 인증 — 가입 · 로그인 · 재설정

- 시안: ⚠ 미정 — 아직 안 그렸다 (mh-06)
- 소비자: wj → `web/src/views/`
- 전제: `tokens.md` v2 · `components.md`
- 서버 계약: wj의 **S4a**(`docs/specs/2026-09-23-s4a-auth-design.md`)
- 대상: 학생 화면은 모바일 우선(`student` 치수), 관리자 로그인은 데스크톱(`admin` 치수)

## 목적

학생은 **학교 웹메일로 가입 신청 → 메일 링크 → 관리자 승인 → 로그인**한다. 관리자 계정은 웹에서 만들 수 없고 CLI로 생성되므로 **로그인 화면만** 있다.

이 흐름이 화면 넷을 만든다. 넷 다 학생 웹 도메인에 있고, 관리자 로그인만 관리자 웹에 따로 있다.

| 경로 | 화면 | 누가 |
|---|---|---|
| `/login` | 로그인 | 학생 · 관리자(각자 도메인) |
| `/signup` | 가입 신청 — 웹메일만 | 학생 |
| `/verify#token=…` | 가입 완료 — 이름·학번·비밀번호 | 학생 |
| `/reset#token=…` | 비밀번호 재설정 | 둘 다 |

## 가입이 2단계인 이유를 화면이 말해야 한다

S4a는 가입을 둘로 쪼갰다 — ① 웹메일만 받아 링크를 보내고, ② **링크를 연 사람이** 이름·학번·비밀번호를 정한다. 비밀번호를 정하는 사람 = 메일함을 가진 사람이라, 남의 웹메일로 계정을 선점할 수 없다.

학생에게는 이게 **"왜 두 번 입력해요?"** 로 느껴진다. 그래서 1단계 화면이 앞으로 무슨 일이 일어나는지 미리 말한다.

```
┌ /signup ────────────────────────┐
│ ‹   가입 신청                    │
├─────────────────────────────────┤
│ 학교 웹메일 *                    │
│ [20231234@wsu.ac.kr           ] │
│                                 │
│ ① 메일로 링크를 보냅니다         │  ← 지금 단계를 brand 로
│ ② 링크를 열어 이름·학번·비밀번호 │
│ ③ 관리자 승인 뒤 로그인          │
│                                 │
│ [    인증 메일 받기         ]    │
│ 링크는 5분 안에 열어주세요        │
└─────────────────────────────────┘
```

- 3단계를 번호 매긴 목록으로 둔다. **여기서 번호는 장식이 아니라 실제 순서**이고, 현재 단계를 `brand` 로 표시한다.
- `5분` 을 버튼 아래에 미리 적는다. 메일을 열었을 때 이미 만료돼 있는 것이 이 흐름의 가장 흔한 실패다.
- 보내고 나면 같은 화면이 **보냈습니다** 상태로 바뀐다 — `20231234@wsu.ac.kr 로 보냈어요` + `메일이 안 오면 60초 뒤 다시 보낼 수 있어요` + `다시 보내기`(60초 카운트다운 동안 `disabled`).

### 응답이 항상 202라는 것

`POST /api/auth/signup` 은 **이미 가입된 메일이든 아니든 202** 를 준다(존재 여부를 숨긴다). 화면도 그에 맞춰 **결과를 구분해 말하지 않는다** — 언제나 "보냈어요"다.

이미 가입된 사람은 메일이 안 온다. 그래서 보낸 화면에 `이미 가입한 메일이면 메일이 오지 않습니다. 로그인해 보세요.` 를 한 줄 두고 `로그인` 링크를 건다. 이게 없으면 그 사람은 영원히 메일을 기다린다.

## `/verify` — 링크를 연 화면

주소의 **fragment**(`#token=…`)에서 토큰을 읽는다. 서버 로그와 `Referer` 에 토큰이 남지 않게 하려는 것이므로(S4a §2.3), 화면 쪽 규칙이 따라온다:

- 읽자마자 `history.replaceState` 로 주소에서 지운다.
- 문서에 `<meta name="referrer" content="no-referrer">`.
- **열자마자 `POST /verify/open`** 을 부른다 — 토큰을 쓰지 않고 유효한지 확인하고 입력 시간을 30분으로 늘린다. 폼을 다 채운 뒤에 만료를 알게 되면 처음부터 다시 해야 한다.

```
┌ /verify ────────────────────────┐
│ 가입 완료                        │
│ 20231234@wsu.ac.kr              │  ← /verify/open 이 돌려준 email, 읽기 전용
├─────────────────────────────────┤
│ 이름 *     [김민준            ]  │
│ 학번 *     [20231234          ]  │
│ 비밀번호 * [••••••••          ]  │
│            8자 이상              │
│ [        가입 신청          ]    │
└─────────────────────────────────┘
```

- `email` 은 입력이 아니라 **확인**이다. 읽기 전용으로 보여준다.
- 학번은 `^[0-9A-Za-z-]+$` — 공백·전각을 막는다(S4a §3.4).
- **409 `이미 등록된 학번입니다`** 는 토큰을 소비하지 않는다. 학번 입력만 에러 상태로 두고 나머지는 그대로 유지한다 — 오타를 고쳐 다시 제출하는 흐름이다.
- 400(만료·무효·재사용·이미 가입)은 전부 **같은 문구** `링크가 만료되었거나 잘못되었습니다` 다. 화면도 구분하지 않고, `/signup` 으로 돌아가는 버튼을 준다.
- 성공하면 폼이 사라지고 **`승인을 기다리는 중입니다`** 한 화면으로 바뀐다. 관리자가 승인해야 로그인된다는 것, 승인 메일이 온다는 것을 적는다.

## `/login`

```
┌ /login ─────────────────────────┐
│ 우송 ESC                         │
│ 학교 웹메일 [                 ]  │
│ 비밀번호    [                 ]  │
│ [        로그인            ]     │
│ 가입 신청 · 비밀번호를 잊었어요   │
└─────────────────────────────────┘
```

실패 응답이 둘뿐이고, **둘을 다르게 다뤄야 한다**(S4a §3.4):

| 응답 | 문구 | 화면 |
|---|---|---|
| 401 | `이메일 또는 비밀번호가 틀립니다` | 폼 아래 에러. 어느 쪽이 틀렸는지 말하지 않는다 — 서버가 일부러 합쳤다 |
| 403 | `승인 대기 중` | 에러가 아니라 **안내**로 바꾼다 — `아직 승인되지 않았어요. 관리자 승인 뒤 로그인할 수 있어요.` `neutral` Banner |
| 429 | 분당 5회 초과 | `잠시 후 다시 시도해 주세요` |

403을 적색으로 칠하지 않는다. 학생이 뭘 잘못한 게 아니다.

토큰은 **메모리에 둔다**(S4a §4.3의 개발 페이지와 같은 방식). `localStorage` 에 JWT를 넣지 않는다 — 즐겨찾기 같은 편의값과 자격증명은 저장 자리가 달라야 한다. 새로고침하면 다시 로그인한다.

## `/reset`

`/verify` 와 같은 fragment 규칙이다. 다만 **입력 시간 연장이 없다**(비밀번호 하나라 5분으로 충분하다는 S4a 판단). 그래서 열자마자 남은 시간을 보여주지 않고, 만료되면 `/login` 의 `비밀번호를 잊었어요` 로 되돌린다.

재설정하면 **기존 JWT가 전부 무효**가 된다(`token_version += 1`). 다른 기기에서 로그아웃된다는 것을 성공 화면에 적는다.

## 관리자 로그인

관리자 웹에도 `/login` 이 있다. 같은 `POST /api/auth/login` 을 쓰고 화면만 `admin` 치수다.

- **가입 링크를 두지 않는다.** 관리자 계정은 CLI로만 만들어진다(S4a §4.4).
- `비밀번호를 잊었어요` 는 둔다 — `/forgot` 은 역할을 가리지 않는다.
- 로그인 전에는 사이드바를 그리지 않는다. 로그인 화면은 빈 바탕에 폼 하나다.

## 사용하는 컴포넌트

Input(email · password · text), Button(`primary` 제출), Banner(`neutral` 승인 대기 / `danger` 에러), Toast, Skeleton

인증 전용 — `components/domain/`:

- **`AuthShell`** — 로고 + 제목 + 폼 슬롯 + 하단 링크. 네 화면이 같은 껍데기를 쓴다. props: `title` · `surface`(`student` | `admin`)
- **`StepList`** — 가입 3단계. props: `steps` · `current`. 현재 단계만 `brand`

## 데이터 (서버 계약)

| 하는 일 | 엔드포인트 | 응답 |
|---|---|---|
| 가입 신청 | `POST /api/auth/signup` `{email}` | **항상 202** `{"status": "sent"}` |
| 링크 확인 | `POST /api/auth/verify/open` `{token}` | `{email}` · 400 |
| 가입 완료 | `POST /api/auth/verify` `{token, name, student_no, password}` | `{"status": "pending_approval"}` · 400 · 409 |
| 로그인 | `POST /api/auth/login` `{email, password}` | `{token, role, school_id, name}` · 401 · 403 |
| 재설정 요청 | `POST /api/auth/forgot` `{email}` | **항상 202** |
| 재설정 | `POST /api/auth/reset` `{token, password}` | 200 · 400 |
| 내 정보 | `GET /api/auth/me` (Bearer) | `UserOut` |

모든 `*_at` 은 **naive UTC 로 직렬화된다**(`Z` 없음, S4a §3.4). `api/client.ts` 에서 한 번 변환하고 화면은 변환된 값만 본다.

## 상태

- **로딩**: 제출 버튼 `loading`. 폼 전체를 가리지 않는다.
- **에러**: 필드 단위 에러는 Input의 `error`, 흐름 단위는 폼 위 Banner.
- **레이트리밋(429)**: email당 분당 5회. 남은 시간을 모르므로 `잠시 후 다시 시도해 주세요` 로 두고 버튼을 10초 잠근다.
- **메일 도메인 상한(429)**: 가입에서만. `지금 가입 신청이 몰리고 있어요. 잠시 후 다시 시도해 주세요.`

## 미결

1. **시안이 없다** — 이 문서는 S4a 를 읽고 쓴 것이고 아직 그리지 않았다. mh-06에서 그린다
2. **JWT 저장 위치** — 메모리로 잡았다. 새로고침마다 로그인이 번거로우면 `sessionStorage` 까지 열지 wj와 협의
3. **로그아웃** — S4a 에 엔드포인트가 없다(토큰 폐기는 `token_version` 뿐). 화면에서 토큰을 버리는 것으로 족한지 확인
4. **학생 웹 첫 진입과의 관계** — 조회도 로그인이 필요하면 `/{bld}` 가 사실상 로그인 뒤 화면이 된다. [student-room.md](student-room.md) 미결 5와 같은 항목
