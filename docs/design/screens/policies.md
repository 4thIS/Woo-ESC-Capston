## 목적 · 진입

학생이 가입할 때 개인정보를 무엇에 쓰는지 **읽을 수 있어야** 한다(개인정보 보호법 제30조 — 처리방침 공개). 그래서 약관은 로그인 없이 열리는 별도 화면이고, 가입 버튼 바로 아래에서 그 화면으로 보낸다.

| 어디서 | 무엇으로 | 어떻게 연다 |
|---|---|---|
| `/signup` · `/verify` 버튼 아래 | 동의 안내 한 줄의 `이용약관` · `개인정보 처리방침` | **새 탭** |
| 메인 페이지 바닥글 | `이용약관` · `개인정보 처리방침` | 같은 탭(라우터 이동) |
| 주소 직접 | `/policies` · 없는 문서 | `/policies/terms` 로 보낸다 |

- **로그인 없이 연다.** 가입 전에 읽는 문서라 로그인 벽(`LoginGate`)을 걸지 않는다.
- 가입 화면에서는 **새 탭**이다(`target="_blank" rel="noopener"`). 같은 탭이면 쳐 둔 입력값이 사라지고, `/verify` 는 열자마자 주소에서 메일 토큰을 지웠으므로(auth.md 「`/verify`」) 돌아와도 가입을 마칠 수 없다.

## 문서 · 조항 — 주소를 가진다

- **문서 하나 = 주소 하나** — `/policies/terms`(이용약관), `/policies/privacy`(개인정보 처리방침). 문서 사이 이동은 링크다.
- **조항 하나 = 앵커** — `#t1`, `#p3` 처럼. 목차는 그 앵커로 가는 링크다.
- 문서는 **데이터로 늘린다.** 문서를 하나 더 넣으면 칩·문서 목록·목차가 함께 늘어난다. 화면은 문서 수를 가정하지 않는다.
- 본문 블록은 넷뿐이다 — 문단 · 번호 목록 · 점 목록 · 2열 표. HTML 을 그대로 넣지 않는다.

## 구성

헤더는 `StudentHeader` — 제목 `약관 및 정책`, 왼쪽 `‹` 는 메인 페이지 `/` 로(`메인 페이지`).

### 본문 (두 폭 공통)

본문 칸은 최대 720px, 위에서 아래로:

| 요소 | 문구 · 내용 | 스타일 |
|---|---|---|
| 문서 제목 | `이용약관` / `개인정보 처리방침` | `font.size.xl` 700 |
| 시행일 | `시행일 2026-10-28` | `font.size.sm` `text.3`, 제목 아래 간격 `space.1` |
| 머리말 | 문서 한 문장 소개 | `font.size.sm` `text.2` |
| 조항 제목 | `제1조 (목적)` | `font.size.lg` 700 |
| 조항 본문 | 문단 · 목록 · 표 | 본문 크기, **행간 1.75**(긴 법률 문장이라 다른 화면보다 넓다) |

- 블록 사이 `space.5`, 조항 안 `space.2`. 목록은 왼쪽 들여쓰기 1.3em, 항목 사이 `space.1`.
- 표: 전체 폭, `font.size.sm`. 머리 칸 `sunken` 바탕 + `text.2` `medium`, 칸 아래 `line.1` 1px. 첫 칸은 줄바꿈하지 않는다(항목 이름). 폭이 모자라면 표만 가로로 넘긴다 — 화면 전체는 가로 스크롤이 생기지 않는다.
- 앵커로 갔을 때 조항 제목이 붙박이 헤더(58px)에 가리지 않게 위로 `58px + space.4` 를 띄운다.

### 폰 `< 640`

```
┌ 약관 및 정책 ────────────────────┐
│ ‹  약관 및 정책                   │
├─────────────────────────────────┤
│ (이용약관) ( 개인정보 처리방침 )   │  ← 문서 칩 줄, 가로로 넘김
├─────────────────────────────────┤
│ 이용약관                         │
│ 시행일 2026-10-28                │
│ 이 약관은 …                      │
│ ┌ 목차 N개                  ▾ ┐ │  ← 접힌 목차
│ └───────────────────────────┘ │
│ 제1조 (목적)                     │
│ …                               │
└─────────────────────────────────┘
```

- **문서 칩 줄** — 헤더 아래, 아래 `line.1` 1px. 칩은 높이 40px, 좌우 여백 `space.4`, `radius.full`, `line.2` 테두리 + `text.2`. 문서가 늘어도 되게 **가로로 넘기고 스크롤바는 숨긴다.**
- 고른 문서 칩: 테두리 `text.1` + 글자 `text.1` 700. **`brand` 를 쓰지 않는다** — 문서 고르기는 1차 액션이 아니다(SegmentedControl 과 같은 이유).
- **접는 목차** — 머리말 아래 `<details>`. `sunken` 바탕 + `line.2` 1px + `radius.lg`. 머리 `목차 N개`(700, 높이 `control.height.md`), 오른쪽 끝에 `▾`(펼치면 `▴`, `text.3`). 처음엔 접혀 있다. 문서를 바꾸면 다시 접힌다.

### 넓은 폭 `≥ 640`

```
┌ 약관 및 정책 ─────────────────────────────────────────────┐
│ ‹  약관 및 정책                                            │
├──────────────┬────────────────────────────────────────────┤
│ 문서          │ 이용약관                                   │
│ ▌이용약관     │ 시행일 2026-10-28                          │
│  개인정보 …   │ 이 약관은 …                                │
│              │                                            │
│ 목차          │ 제1조 (목적)                               │
│  제1조 (목적) │ …                                          │
│  제2조 (용어) │                                            │
│  …           │                                            │
└──────────────┴────────────────────────────────────────────┘
   260px, sunken    본문 최대 720px
```

- **왼쪽 260px 고정 칸** — 학생 웹 넓은 폭 틀처럼 왼쪽이 늘 서 있다. `sunken` 바탕 + 오른쪽 `line.2` 1px, 안쪽 여백 `space.5` `space.4`. 헤더 아래에 붙어(sticky) 화면 높이만큼 서고, 목차가 길면 **그 칸 안에서** 스크롤한다.
- 칸 안: `문서` 라벨 → 문서 목록 → `목차` 라벨 → 목차. 라벨은 `font.size.xs` 700 `text.3`.
- 문서 목록 한 줄은 여백 `space.2` + `radius.sm`, `text.2`. 고른 문서는 `surface` 면 + `line.2` 1px 안쪽 테두리 + `text.1` 700 — SegmentedControl 의 선택된 칸과 같은 말투다. `brand` 없음.
- 목차 링크는 `font.size.sm` `text.2`, hover 에 `text.1`.
- 칩 줄과 접는 목차는 그리지 않는다(왼쪽 칸이 그 일을 한다). 본문 여백은 `space.6` `space.7`.

## 가입 동의 안내 — `PolicyConsent`

`/signup` · `/verify` 의 제출 버튼 아래 한 줄이다. `/verify` 는 버튼 **바로 아래**, `/signup` 은 버튼 아래 `링크는 5분 안에 열어주세요` 의 **다음 줄**이다([auth.md](auth.md) `/signup` — 5분 안내가 버튼에 붙는다).

| 화면 | 문구 |
|---|---|
| `/signup` | `계속하면 이용약관과 개인정보 처리방침에 동의하는 것으로 봅니다.` |
| `/verify` | `가입 신청을 누르면 이용약관과 개인정보 처리방침에 동의하는 것으로 봅니다.` |

- **체크박스를 두지 않는다.** 버튼을 누르는 것을 동의로 보고(이용약관 제4조), 그 사실을 버튼 아래에 적는다. 동의 시각은 가입 시각과 같아 따로 저장하지 않는다.
- `/verify` 문구가 다른 이유 — 계정이 실제로 생기는 곳이 `/verify` 의 `가입 신청` 이다. `/signup` 은 아직 메일만 보내므로 `계속하면` 이다.
- 스타일: `font.size.sm` `text.2`, 행간 1.6. 두 문서 이름은 링크 — `text.1` `medium` + 밑줄(밑줄 간격 2px). **`brand` 를 쓰지 않는다** — 그 화면의 `brand` 채움은 제출 버튼 하나다.

## 상태

서버를 부르지 않는다(문서는 웹에 들어 있다). 로딩·에러 상태가 없다. 없는 문서 주소는 에러 화면이 아니라 `/policies/terms` 로 보낸다.

## 사용하는 컴포넌트

`StudentHeader`. 문서 칩·문서 목록·접는 목차는 이 화면에만 있으므로 `PolicyView.vue` 안에 둔다(components.md 「어디에 두나」). `PolicyConsent` 는 `/signup`·`/verify` 두 곳이 써서 `web/src/auth/` 에 둔다.

## 미결

1. **문서 안의 빈 값** — 개인정보 보호책임자(`[이름 · 직위 · 메일]`)와 메일 발송 서비스(`[메일 발송 서비스]`)가 대괄호 자리표시로 화면에 그대로 보인다. 값은 운영자(cw)가 정한다 — 정하면 `policies.ts` 의 `POLICY_INFO` 만 바꾼다. 디자인은 바뀌지 않는다
2. **문서 이력** — 시행일이 바뀔 때 이전 판을 보여 줄지(문서마다 `이전 판` 링크). 지금은 최신 판 하나만 둔다
