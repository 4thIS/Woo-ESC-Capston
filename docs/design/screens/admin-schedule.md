## 목적 · 진입

**강의실 하나의 일주일을 한 장으로 본다.** 페이지1의 표가 "무엇이 등록돼 있나"를 다룬다면, 이 화면은 "그래서 이 강의실의 한 주가 어떻게 생겼나"를 다룬다. 빈 시간대와 겹침은 표로는 보이지 않고 격자로만 보인다.

진입: 페이지1 표의 `호수` 클릭. 또는 **이 화면에서 바로 고른다.**

**상단 좌측의 `건물` · `강의실` Select 두 개가 곧 화면 제목이다.** 별도 `<h1>`을 두지 않는다 — 제목과 선택이 같은 것을 가리키는데 둘로 나누면 어느 쪽이 현재 값인지 헷갈린다. `font.size.lg` + `weight.bold`로 제목처럼 보이게 하고, 테두리로 고를 수 있다는 것만 알린다.

건물을 바꾸면 강의실 Select가 그 건물의 목록으로 갈리고 첫 강의실이 선택된다. 강의실을 바꿔도 **보고 있는 주는 유지한다** — 같은 주의 다른 강의실을 견주는 것이 이 화면에서 가장 잦은 동작이다.

셀을 눌러 편집도 한다 — 아래 「편집」.

## 레이아웃

```
┌─ 상단 ──────────────────────────────────────────────────┐
│ [공학관 ▾] [401호 ▾]  ◀ 10/19~10/25 ▶   ☐야간 ☐주말 [+ 슬롯 추가] │
├─ 범례 ──────────────────────────────────────────────────┤
│ [사용중] 수업·시험·특강·대여는 라벨로 구분   [휴강]   ● 완료 ○ 대기 │
├─ 격자 ──────────────────────────────────────────────────┤
│      │ 월 9/21 │ 화 9/22 │ 수 9/23 │ 목 9/24 │ 금 9/25 │…│
│ 09:00│  셀     │         │  셀     │         │         │ │
│ 09:30│         │         │         │         │         │ │
│  ⋮   │                                                  │
└─────────────────────────────────────────────────────────┘
```

- **열 = 요일**, `SlotOut.day` 1~7(월~일)을 그대로 쓴다. 토·일은 기본으로 접고 상단 토글로 편다 — 대부분의 강의실이 주중만 쓴다. 야간 보기와 같은 규칙으로, 주말에 슬롯이 있으면 자동으로 켜진다. 열 폭은 걱정하지 않아도 된다 — 1440px에서 5열이면 하루 219px, 7열이어도 156px이라 블록 안 세 줄이 다 들어간다.
- **행 = 30분 단위. 기본은 09:00~18:00 (18행 · 792px)이고, `야간 보기` 토글로 22:00까지 편다(26행 · 1144px).** 행 높이는 고정 44px.
- **야간 보기는 필요하면 자동으로 켜진다** — 보고 있는 주에 `e_h > 18`인 슬롯이나 예약이 하나라도 있으면 켠 상태로 시작한다. 그러지 않으면 19시 수업이 화면에 없다. 사용자가 끄면 그 선택을 유지한다.
- 격자는 세로 스크롤하고 요일 헤더와 시각 열은 붙어 있다(`position: sticky`).
- 22:00 이후에 걸친 슬롯(`e_h` ≥ 22)은 마지막 행에서 잘라 그리고 블록 하단에 `~HH:MM`을 적는다. 격자를 늘리지 않는다.

> **왜 26행이 아닌가** — 09:00~22:00으로 그려 보니 격자만 1144px, 화면 전체가 1400px이었다. 1440×900 화면에서 17:00 이후가 통째로 안 보인다. 강의는 09~18시에 몰리는데 야간까지 그리느라 **실제로 쓰는 구간의 절반을 스크롤해야 했다.** 18행이면 화면 전체가 1040px이라 1080p에서는 다 들어오고, 900px 화면에서도 마지막 한 행만 걸린다.
- 슬롯은 `s_h:s_m`~`e_h:e_m` 길이만큼 **행을 가로질러 하나의 블록**으로 그린다. 30분 격자는 배경이고, 슬롯은 그 위에 절대 배치한다.
- 격자 컨테이너: `line.2` 1px + `radius.lg`. 행 구분선 `line.1`, 열 구분선 `gray.50`. 요일 헤더 아래만 `line.2`.
- 셀 여백 `space.1`(4px) — 블록끼리 붙지 않게.

### 슬롯 블록

| 상태 | 표현 | 토큰 |
|---|---|---|
| 사용중 (`CLASS`·`EXAM`·`SPECIAL`·`RENTAL`) | 연한 적색 틴트 + 1px 테두리, 상단에 진한 적색 라벨 | `room.busy.fill` / `.line` / `.label` |
| 휴강 (`CANCELLED`) | 점선 테두리, 과목명 취소선 | `room.free.line` / `.text` |
| 빈강의실 (`EMPTY`) · 빈 시간 | **아무것도 그리지 않는다** | — |

블록 안: 라벨(`수업중`/`시험중`/`특강`/`대여중`, `font.size.xs` 700) → 과목명(`md` 500) → 교수(`xs`, `text.3`). 높이가 모자라면 교수부터 지운다.

**네 상태를 색으로 나누지 않는다.** 전부 같은 `room.busy`이고 구분은 라벨 텍스트가 한다(`tokens.md` — e-Paper RED 이분법과 1:1).

### 예약과 시험기간을 겹쳐 보인다

이게 페이지2가 표보다 나은 유일한 이유다. 격자는 날짜를 갖고 있으므로 **날짜 기반 데이터를 요일 축에 얹을 수 있다.**

- **예약**(`ResvOut.date`)은 그 날짜가 보고 있는 주에 들어오면 해당 요일 열에 슬롯과 같은 모양으로 그린다. 라벨 앞에 `예약 · `을 붙여 시간표 슬롯과 구분한다. 시간표 슬롯과 겹치면 두 블록을 나란히 **반씩 폭으로 나누고**, 두 블록 사이의 **겹친 시간 구간에만 `danger` 3px 세로 막대**를 긋고 그 위에 `겹침 11:00–12:00` 라벨을 하나 놓는다. 숨기지 않는다 — 겹친 걸 보라고 있는 화면이다.

> **왜 테두리가 아닌가** — 처음에는 겹친 두 블록에 각각 2px `danger` 테두리를 둘렀다. 그려 보니 "무엇이 겹쳤다"가 아니라 **"경고가 두 개"**로 읽혔다. 적색 상자가 둘이면 눈이 겹침이 아니라 개별 블록을 본다. 표시를 **하나**로 줄이고 그것을 정확히 겹친 구간에 놓으면 겹침이 바로 읽힌다.
- **시험기간**(`ExamOut.date_start`~`date_end`)에 걸린 날은 **요일 헤더 아래에 얇은 띠**로 표시한다(`room.busy.fill` 바탕 + `room.busy.label` 글자, "시험기간"). 셀은 건드리지 않는다.

## 사용하는 컴포넌트

Select(강의실), Button(`primary` 슬롯 추가 / `ghost` 주 이동), Badge(유형), Modal(슬롯 폼, 삭제 확인), Toast, OutboxDot, Loading, EmptyState. **Table은 쓰지 않는다** — 커스텀 격자다.

슬롯 폼 Modal은 [페이지1](admin-rooms.md)과 **같은 컴포넌트**다. 검증 규칙(겹침·바이트 상한·`source`)이 한 곳에만 있어야 한다.

## 데이터 (서버 계약)

| 하는 일 | 엔드포인트 |
|---|---|
| 건물 목록 | `GET /buildings` → `BuildingOut[]` |
| 강의실 목록 | `GET /rooms` → `RoomOut[]`. `building_id`로 프론트에서 거른다 |
| 시간표 | `GET /rooms/{id}/slots` → `SlotOut[]` |
| 예약 | `GET /rooms/{id}/reservations` → `ResvOut[]` |
| 시험기간 | `GET /rooms/{id}/exams` → `ExamOut[]` |
| 추가·수정 | `PUT /rooms/{id}/slots` (`SlotIn`) |
| 삭제 | `DELETE /rooms/{id}/slots/{day}/{s_h}/{s_m}` |
| 하루 비우기 | `DELETE /rooms/{id}/slots?day=N` |

이 화면은 **강의실 하나**만 보므로 페이지1과 달리 건물 단위 API가 필요 없다. 세 번 호출해 겹쳐 그린다.

주 이동(`◀ ▶`)은 서버를 다시 부르지 않는다 — 시간표는 요일 기반이라 주가 바뀌어도 같고, 예약·시험기간만 날짜로 다시 거른다. 보고 있는 주가 예약 7일 지평 밖으로 나가면 그 주의 예약은 **`예정` 배지**로 그린다(페이지1 §2와 같은 규칙).

## 편집

- **슬롯 클릭** → 수정 Modal. 시작 시각을 바꾸면 키가 바뀌므로 **삭제 후 추가**로 처리한다(페이지1과 동일).
- **빈 칸 클릭** → 추가 Modal. `day`와 `s_h:s_m`을 누른 자리에서 미리 채우고, 종료는 +1시간을 기본값으로 둔다.
- **드래그로 만들지 않는다.** 09:00~10:30 같은 구간을 드래그로 그리면 30분 격자에 스냅되는 규칙, 겹침 처리, 취소 동작을 전부 따로 정해야 한다. 값은 폼에서 숫자로 넣는다(`docs/design/README.md` — 값은 숫자로).
- **겹침은 저장 전에 막는다.** 서버는 같은 키만 막으므로 09:00–11:00과 10:00–12:00이 둘 다 들어간다.
- `source`가 1(포털)인 슬롯을 수정하면 `source: 2`로 올라간다 — 이후 CSV 재임포트에 덮이지 않는다. Modal에 그 사실을 hint로 적는다: **"저장하면 이 슬롯은 수동 편집으로 바뀌어 CSV 임포트에 덮이지 않습니다."**

## 상태

- **로딩**: 요일 헤더와 시각 열은 그리고 격자 본문에 Loading.
- **빈 상태**: 격자는 그대로 두고 가운데에 "이 강의실에 등록된 시간표가 없습니다" + `슬롯 추가` · `페이지1에서 CSV 가져오기`. 빈 격자 자체가 정보이므로 격자를 지우지 않는다.
- **에러**: Toast(danger) + 재시도. 이전 격자를 유지한다.
- **저장 후**: 해당 블록의 OutboxDot이 `queued`에서 시작한다. `failed`면 점이 `danger`가 되고 블록에 2px `danger` 테두리.

## 미결

1. 예약과 슬롯이 겹칠 때 반씩 폭을 나누는 방식이 3개 이상 겹치면 읽히지 않는다. 실제로 그런 경우가 생기는지 확인 후 결정

> 격자 축(30분 × 26행)은 **웹의 표시 축일 뿐**이고 단말과 무관하다. e-Paper 의 `today[24]`는 교시 기반(09:00~22:55)이라 칸 수가 다르지만, 슬롯 자체는 양쪽 다 `s_h:s_m`~`e_h:e_m` 임의 시각으로 저장되므로 변환이 필요 없다. 두 축을 맞추려 들지 않는다.
