# 관리자 — 회원 승인

- 시안: ⚠ 미정 — 아직 안 그렸다 (mh-06)
- 소비자: wj → `web/src/views/`
- 전제: `tokens.md` v2 (`admin` 치수 세트) · `components.md`
- 서버 계약: wj의 **S4a §4.2**(`docs/specs/2026-09-23-s4a-auth-design.md`)
- 대상: **데스크톱 전용** (`bp.desktop` ≥ 1024px) — `README.md` 규칙

## 목적 · 진입

**학생이 가입 신청하면 여기서 승인한다.** 승인하지 않으면 그 학생은 로그인할 수 없다(S4a §4.1 — `pending_approval` 은 로그인 403).

진입: 사이드 메뉴 `회원`. 대시보드 요약의 `pending_approval` 경고를 눌러도 온다.

**이 화면이 막히면 학생 웹 전체가 막힌다.** 가입 흐름의 마지막 관문이라, 신청이 쌓여 있다는 것이 관리자 눈에 띄어야 한다 — 사이드 메뉴 `회원` 옆에 대기 건수를 배지로 둔다.

## 레이아웃

```
┌─ 상단 ────────────────────────────────────────────────┐
│ 회원        [승인 대기 5] [전체 ▾]   [호수 검색      ] │
└───────────────────────────────────────────────────────┘
┌─ 목록 ────────────────────────────────────────────────┐
│ 이름 │ 학번 │ 웹메일 │ 역할 │ 상태 │ 신청 │ 승인 │ 작업 │
│ 김민준│20231234│…@wsu.ac.kr│학생│대기중│2시간 전│ — │[승인][거절]│
│ 이정민│20221111│…@wsu.ac.kr│학생│활성 │3일 전│어제│    [정지]  │
│ 관리자│  —   │admin@…│관리자│활성 │  —  │ — │      —     │
└───────────────────────────────────────────────────────┘
```

- **상태 필터가 기본 `승인 대기`** 다. 이 화면을 여는 이유가 그것이다. `전체`·`활성`·`거절`·`정지`로 바꿀 수 있다.
- 정렬은 대기 건이 **오래된 순**(먼저 온 사람 먼저), 나머지는 `created_at` 최신순.
- 행 높이 32px. 컬럼 폭: 이름 96 · 학번 104 · 웹메일 남는 폭 · 역할 72 · 상태 88 · 신청 96 · 승인 96 · 작업 136.

## 상태 넷

| `status` | 라벨 | Badge | 가능한 동작 |
|---|---|---|---|
| `pending_approval` | 대기중 | `neutral` + `outline` | `승인` `거절` |
| `active` | 활성 | `neutral` + `solid` | `정지` |
| `rejected` | 거절됨 | `neutral` + `outline`, 사유를 툴팁으로 | 없음 (본인이 재신청) |
| `disabled` | 정지됨 | `danger` + `outline` | `해제` |

**적색은 `disabled` 에만 쓴다.** 대기중과 거절됨은 무채색이다 — 관리자가 아직 판단하지 않았거나 이미 끝난 것이지, 문제 상황이 아니다.

## 동작

| 버튼 | 엔드포인트 | 확인 |
|---|---|---|
| `승인` | `POST /api/admin/users/{email}/approve` | 없음 — 되돌릴 수 있다(`정지`) |
| `거절` | `POST .../reject` `{reason}` | **Modal 필수** — 사유가 학생에게 메일로 그대로 간다 |
| `정지` | `POST .../disable` | Modal — 그 사람의 토큰이 즉시 무효가 된다 |
| `해제` | `POST .../enable` | 없음 |

- **`승인`에 확인을 두지 않는다.** 이 화면의 주 동작이고 되돌릴 수 있다. 대기 5건을 승인하는 데 모달을 다섯 번 닫게 하지 않는다.
- **`거절`은 사유가 필수다.** 입력하지 않으면 제출할 수 없고, `학번이 잘못되었습니다` 같은 예시를 placeholder로 둔다. 학생이 이 문장만 보고 다시 신청해야 한다.
- **`정지`는 무거운 동작이다.** `token_version` 이 올라 그 사람이 쓰던 세션이 즉시 끊긴다. Modal 본문에 그 사실을 적는다.
- 관리자 자신(`role=admin`)은 목록에 나오지만 **`정지` 대상이 아니다**(400). 작업 칸을 비우고 `CLI 에서만 변경` 을 `text.3` 으로 적는다 — 버튼을 두고 400을 받게 하지 않는다.

### 승인·거절은 메일을 보낸다

둘 다 커밋 뒤 메일이 나간다(S4a §3.4). 메일 발송은 **응답을 기다리지 않으므로**, 화면은 성공 Toast에 `메일로 알렸습니다` 를 덧붙이되 **발송 성공을 보장하는 문구로 쓰지 않는다** — `승인했습니다. 학생에게 메일이 갑니다.` 정도다.

메일 상한(종류별 시간당, 승인·거절 200통)에 걸리면 서버가 조용히 생략한다. 화면은 그 사실을 알 수 없다.

## 상태

- **로딩**: 표 본문에 Skeleton 5행.
- **빈 상태**: 필터가 `승인 대기`인데 0건이면 **"승인을 기다리는 신청이 없습니다"** — 평소 상태이므로 버튼을 붙이지 않는다. 전체가 0건이면 "아직 가입한 회원이 없습니다" + 학생 웹 주소 안내.
- **409**: 상태가 이미 바뀐 경우(다른 탭에서 승인). Toast로 `이미 처리된 신청입니다` + 목록 새로고침.
- **에러**: Toast(danger) + 재시도.

## 사용하는 컴포넌트

Table, Badge(상태·역할), Button(`primary` 승인 / `ghost` 거절·정지·해제), Modal(거절 사유, 정지 확인), Toast, Select(상태 필터), Input(검색), Skeleton, EmptyState

새 컴포넌트는 없다 — 기존 것으로 그린다.

## 데이터 (서버 계약)

| 하는 일 | 엔드포인트 |
|---|---|
| 목록 | `GET /api/admin/users?status=` → `UserOut[]` |
| 승인 | `POST /api/admin/users/{email}/approve` → `UserOut` · 409 |
| 거절 | `POST /api/admin/users/{email}/reject` `{reason}` → `UserOut` · 409 |
| 정지 | `POST /api/admin/users/{email}/disable` → `UserOut` · 409 · 400(관리자) |
| 해제 | `POST /api/admin/users/{email}/enable` → `UserOut` · 409 |

`UserOut` = `email, school_id, role, status, name, student_no, created_at, approved_at` (화이트리스트 — `pw_hash` 는 어떤 응답에도 없다).

**`reject_reason` 이 `UserOut` 에 없다.** 목록에서 거절 사유를 보여주려면 필드가 필요하다 — 아래 미결 2.

전부 `require_admin` + 학교 스코프다. 타 학교 회원은 404다.

## 미결

1. **시안이 없다** — 이 문서는 S4a 를 읽고 쓴 것이다. mh-06에서 그린다
2. **`reject_reason` 노출** — `UserOut` 화이트리스트에 없어 거절 사유를 목록에서 못 보여준다. 관리자가 자기가 왜 거절했는지 다시 볼 수 없다. additive로 요청할지 wj와 확인
3. **검색 범위** — 이름·학번·메일 중 무엇으로 찾을지. 전시 규모(회원 수십)에서는 필터만으로 충분할 수도 있다
4. **대기 건수 배지** — 사이드 메뉴에 띄우려면 폴링이 필요하다. 대시보드 요약(`/api/admin/summary` 의 `pending_approval.count`)을 60초마다 부르는 것으로 대신할지 결정
