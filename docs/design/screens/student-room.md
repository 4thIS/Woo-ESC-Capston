# 학생 웹 — 강의실 (S10)

- 시안: [캔버스](https://claude.ai/artifact/NLQyYEEdt4Rv6Dn7JZZuHi) `Student-Gate`(로그인 벽) · `Student-Entry` · `Student-Room` · `Student-Week` · `Student-Reserve` · `Student-My` · `Student-Wide`(1280 폭)
- 소비자: wj → `web/src/views/`
- 전제: `tokens.md` v2 (`student` 치수 세트) · `components.md`
- 대상: **모바일 우선.** `bp.mobile` → `bp.tablet` → `bp.desktop` 세 폭 모두에서 동작한다
- 서버 계약: wj의 **S10**(`docs/specs/2026-09-23-s10-student-analytics-design.md`) · **S4a**(`…-s4a-auth-design.md`). 이 문서의 API·규칙은 전부 그 둘을 따른다

## 목적 · 진입

학생이 **복도에서 폰으로 "지금 이 강의실 비었나"를 확인한다.** 그게 전부다.

진입은 **별도 도메인을 직접 치고 들어오는 것**이다(로드맵 §5 — QR 폐기, 2026-09-16 팀 결정). 이 한 가지가 화면 설계를 지배한다:

- 학생은 **어느 강의실인지 모르는 상태로** 도착한다. 첫 화면이 강의실 하나일 수 없다.
- 주소가 곧 상태다. 친구에게 링크를 보내면 같은 화면이 열려야 한다.
- 브라우저 뒤로가기가 동작해야 한다. **앱이 아니다.**

관리자 웹과 같은 코드베이스(`web/`)이지만 진입 도메인이 다르다.

**전부 로그인이 필요하다.** 조회도 예약도 마찬가지다 — S10 §3이 `/api/student/**` 전부에 `require_student` 를 건다. 학교 스코프를 판정하려면 신원이 있어야 하기 때문이다. 학교 웹메일로 가입 신청 → 메일 링크 → 관리자 승인 → 로그인이고, 그 화면들은 [auth.md](auth.md)에 있다.

JWT 가 24시간이라 하루 한 번이지만, **"복도에서 폰으로 빨리 확인"이라는 이 화면의 목적과는 분명히 상충한다.** 그래서 첫 화면이 로그인 벽으로 시작하지 않도록 아래 §로그인 벽 규칙을 둔다.

## 라우트

여섯이다. `E`는 `BuildingOut.bld` — 서버에 이미 있는 A~Z 한 글자다. **전부 로그인이 필요하다.**

| 경로 | 화면 | 비고 |
|---|---|---|
| `/{bld}` | 건물의 강의실 목록 | **첫 진입.** `/` 로 오면 건물 선택 후 리다이렉트 |
| `/{bld}/{room}` | 그 강의실 | 공유 가능한 딥링크 — 주소를 그대로 보내면 된다. 별도 `링크 복사` 버튼은 두지 않는다 |
| `/{bld}/{room}/week` | 이번 주 | 모바일에서만 별도 화면 — 아래 「넓은 폭」 |
| `/{bld}/{room}/reserve` | 예약 신청 | **로그인 필요.** 아래 「예약」 |
| `/me` | 내 신청 | **로그인 필요.** 신청·승인 상태, 체크인, 취소 |
| `/login` · `/signup` · `/verify` · `/reset` | 인증 | [auth.md](auth.md) |

예: `esc.wsu.ac.kr/E/401`

- 건물·강의실이 없으면 404 화면 + `/{bld}` 로 돌아가는 링크. 주소를 잘못 친 경우가 흔하다.
- **즐겨찾기**를 `localStorage`에 호수 배열로 남긴다(`esc.fav = ["E-401", "E-405"]`). 다음 방문에 첫 화면 위쪽에 뜬다. 서버에 즐겨찾기 필드가 없어서이고(S4a `users` 스키마), 기기를 바꾸면 사라지는 것을 감수한다.
- 마지막으로 본 건물도 함께 남겨 `/` 로 들어왔을 때 그리로 보낸다.

## 화면 1 — `/{bld}` 강의실 목록

```
┌ 헤더 58 ────────────────────────┐
│ 우송 ESC            [공학관 ▾]  │
├─────────────────────────────────┤
│ 5곳 이 지금 비어 있어요          │  ← 24px bold
│ 공학관 18개 강의실 · 10:42 기준  │
│                                 │
│ 즐겨찾기  ★ 을 눌러 모아둡니다    │
│ [★401호 수업중] [★405호 비어있음]│  ← 48px
│                                 │
│ 공학관 전체       ☑ 빈 강의실만   │
│ ┌─────────────────────────────┐ │
│ │ 401호 수업중·캡스톤디자인 › ★│ │  ← 56px
│ │       10:00 에 비어요        │ │
│ │ 402호 비어있음            › ☆│ │
│ │       13:00 까지            │ │
│ └─────────────────────────────┘ │
│ ● 문 앞 e-Paper 와 같은 내용     │
└─────────────────────────────────┘
```

- **맨 위는 시간표가 아니라 개수다.** 학생이 원하는 건 "지금 빈 곳"이지 시간표가 아니다. 주간 시간표는 세 번째 화면으로 민다.
- 목록의 각 행은 **호수보다 상태를 먼저 말한다.** 큰 글씨는 호수(식별)이고, 그 옆 줄이 상태와 언제 바뀌는지다.
- 행 높이 56px(터치 하한 48 이상). 행의 **왼쪽 대부분이 링크**이고, 오른쪽 48px가 즐겨찾기 토글이다. 링크 안에 버튼을 넣지 않는다 — 중첩되면 어느 쪽이 눌렸는지 읽기 어렵고 스크린리더가 잘못 읽는다.

### 즐겨찾기

`최근 본 강의실`을 대신한다. 자동으로 쌓이는 기록 대신 학생이 ★로 **직접 고른다.**

- 매일 같은 강의실 두세 곳을 보는 쓰임이라 자동 기록보다 정확하고, 무엇이 왜 거기 있는지가 분명하다.
- 토글 위치는 두 곳 — 목록 행 오른쪽 48px 버튼, 강의실 페이지 헤더의 ★.
- 즐겨찾기가 비어 있으면 그 섹션을 **통째로 감춘다.** "아직 없습니다" 같은 빈 상태를 두지 않는다 — 첫 방문자에게 빈 상자를 먼저 보여줄 이유가 없다.
- 아이콘은 `★`(`brand`) / `☆`(`text.disabled`). 색만으로 구분하지 않도록 모양이 함께 바뀐다. `aria-label`은 `즐겨찾기 추가` / `즐겨찾기 해제`.
- 저장은 `localStorage` 다. 서버 저장이 필요해지면 `users` 에 컬럼 하나가 추가돼야 하고, 그건 이 화면의 결정이 아니다(미결 7).
- `빈 강의실만` 체크박스는 **기본 켜짐.** 18개를 다 보여주는 것보다 5개를 보여주는 게 목적에 맞는다. 끄면 전체가 보인다.
- 페이지 바탕 `bg.student`(`gray.25`), 카드 `surface`. 관리자 웹의 "흰 바탕 + 헤어라인"을 그대로 쓰면 모바일에서 카드 경계가 사라진다.

## 화면 2 — `/{bld}/{room}` 강의실

```
┌ 헤더 58 ────────────────────────┐
│ ‹   공학관 401호              ★ │  ← ‹ 는 /{bld} 로 가는 진짜 링크
├─────────────────────────────────┤
│ 오늘          10월 23일 금       │
│ ┌───────────────────────────┐   │
│ │ 09:00 캡스톤디자인 [수업중] │   │  ← 48px
│ │ 10:00 비어있음 —13:00 [지금]│   │  ← brand.tint 행
│ │ 13:00 운영체제     [수업]  │   │
│ └───────────────────────────┘   │
│ [이번 주 전체 보기         ›]    │
├─────────────────────────────────┤
│ [    이 강의실 예약하기     ]    │  ← 하단 고정 48px
│   비어 있는 시간만 · 7일 이내    │
└─────────────────────────────────┘
```

- **`지금` 카드를 두지 않는다.** 목록 화면(`/{bld}`)이 이미 각 강의실의 현재 상태를 말하고 있어 같은 말이 두 번이었다. 여기서는 오늘 하루의 흐름을 보여주는 것으로 충분하다.
- 대신 **지금에 해당하는 행을 세운다** — 바탕 `brand.tint`, 시각 `brand` + 700, 오른쪽에 `지금 10:42` 배지(`brand` 채움 + 흰 글자). 카드를 지우면서 '지금'이 통째로 사라지면 학생이 목록에서 현재 시각을 스스로 찾아야 한다.
- 이 배지에 **적색을 쓰지 않는다.** 적색은 `사용중` 전용이라 '지금'에 쓰면 두 뜻이 섞인다. 주간 격자의 '지금' 선과 같은 규칙이다.
- `오늘` 목록은 **빈 구간도 행으로 보여준다.** 수업만 나열하면 언제 비는지를 학생이 계산해야 한다.
- `‹`는 `/{bld}`로 가는 `<a>`다. 브라우저 뒤로가기와 결과가 같아야 한다.
- 헤더 오른쪽은 **즐겨찾기 ★ 토글**이다. `링크 복사`가 있던 자리인데, 모바일 브라우저에 공유·주소 복사가 이미 있어 중복이라 뺐다.
- 하단은 **예약 버튼이 고정**된다 — 아래 「예약」.

## 화면 3 — `/{bld}/{room}/week` 이번 주

**관리자 페이지2와 같은 격자다 — 요일이 가로, 시간이 세로.** 형태를 맞추는 이유는 같은 시스템을 두 번 배우지 않게 하기 위해서다. 그리고 이 형태에서는 **빈 칸이 곧 비어 있는 시간**이라, 학생이 찾는 것이 따로 표시 없이 읽힌다.

규칙은 관리자와 같고 **눈금만 줄인다.**

| | `bp.mobile` (390) | `bp.tablet` 이상 |
|---|---|---|
| 30분 행 높이 | 24px | 32px |
| 18행 높이 | 432px | 576px |
| 시각 열 | 34px | 40px |
| 하루 열 폭 | 64px | 200px 이상 |
| 블록 내용 | 과목명만 (2줄 줄바꿈 허용) | 유형 라벨 + 과목명 + 시각 |
| 위치 | 별도 화면 | `/{bld}/{room}` 안에 함께 |

범위는 09:00~18:00 18행, 주중 5열. 관리자의 `야간 보기`·`주말 보기` 토글은 두지 않는다 — 학생 화면에 스위치를 늘리지 않고, 해당 슬롯이 있으면 자동으로 편다.

**오늘 열**은 `brand.tint` 바탕 + `brand` 요일 머리로 세우고, 현재 시각에 `brand` 2px 가로선을 긋는다. **여기에 적색을 쓰지 않는다** — 적색은 `사용중` 전용이라 '지금'에 쓰면 두 뜻이 섞인다.

### 겹침 — 관리자와 규칙이 갈린다

**학생 웹은 겹친 `사용중` 블록을 하나로 합친다.**

```
금 10:00–12:00 알고리즘 + 금 11:00–13:00 동아리 대관
  → 관리자: 반씩 나눠 그리고 겹친 구간에 danger 막대
  → 학생  : 「알고리즘 외 1건 · 10:00–13:00」 한 덩어리
```

학생에게 중요한 건 "누가 쓰는지"가 아니라 **"쓰이는지"**다. 겹침을 해결해야 하는 쪽은 관리자이고, 학생은 그 방이 언제 비는지만 알면 된다. 실무적으로도 390px에서 반씩 쪼개면 한 칸이 32px이라 글자가 들어가지 않는다.

합친 블록의 라벨은 **먼저 시작한 것의 이름 + `외 N건`**, 시각은 합집합의 시작~끝이다.

## 예약 — `/{bld}/{room}/reserve`

**신청이지 확정이 아니다.** 학생이 시간을 고르고 신청하면 `requested` 상태로 쌓이고, **관리자가 승인해야** `approved` 가 되어 문 앞 e-Paper 로 나간다(S10 §0 — 2026-09-23 확정).

> 이 문서의 이전 판은 "신청 즉시 확정"이었다. wj의 S10 설계가 승인 단계를 두기로 확정하면서 바뀌었고, 화면에 **상태**라는 축이 하나 생겼다.

### 진입

강의실 화면 하단에 **고정된 `이 강의실 예약하기`**(48px, `brand` 채움). 헤더의 36px 보조 버튼 자리에 두지 않는다 — 이 화면의 1차 동작이고, 모바일에서 1차 동작은 엄지가 닿는 하단이다.

- **비로그인이면** 버튼을 누를 때 `/login` 으로 보내고, 로그인 뒤 원래 자리로 돌아온다.
- **`reservable = false` 인 방이면** 버튼을 아예 두지 않고 `이 강의실은 예약을 받지 않습니다` 한 줄로 대신한다(`RoomOut.reservable`, S4a).

### 화면

```
┌ 헤더 ───────────────────────────┐
│ ✕   공학관 401호 예약            │
├─────────────────────────────────┤
│ 날짜 · 오늘부터 7일까지          │
│ [오늘][토][일][월][화][수][목][금]│  ← 52px 칩 8개 (오늘~+7)
│ 비어 있는 시간 · 10월 24일 토    │
│ ┌───────────────────────────┐   │
│ │ ◉ 10:00 – 13:00     3시간 │   │  ← 52px
│ │ ○ 17:00 – 21:00     4시간 │   │
│ └───────────────────────────┘   │
│ 쓸 시간  [10:00 ▾] – [12:00 ▾]  │  ← 5분 단위, 15~120분
│ 무엇에 쓰나요 *                  │
│ [캡스톤 스터디          18/20 B] │
│ 신청하면 관리자 승인 뒤 확정돼요  │
├─────────────────────────────────┤
│ 10월 24일 토 10:00–12:00 [신청하기]│
└─────────────────────────────────┘
```

**이름·학번을 받지 않는다.** 로그인한 사람이 누구인지 서버가 안다(`requested_by`). 가입 때 이미 이름·학번을 냈다(S4a §4.1 `verify`).

### 화면이 거는 제약

버튼이 바로 신청하지 않고 시간 고르기로 간다. 학생이 예약하는 건 강의실이 아니라 시간이기 때문이고, 그 과정에서 S10 §2.4의 제약이 **고를 수 없게** 걸린다.

| 제약 | 값 | 화면이 하는 일 |
|---|---|---|
| 날짜 | KST 오늘 ~ +7일 | **날짜 칩 8개**(오늘 포함)가 곧 이 제한이다. 그 밖은 없다 |
| 시각 | 5분 단위, 시작 < 끝 | Select 옵션을 5분 간격으로만 만든다 |
| 길이 | 15 ~ 120분 | 종료 Select에서 범위 밖을 지운다 |
| 과거 | 시작 ≤ 지금이면 거부 | 오늘 칩에서 지난 구간을 지운다 |
| 건수 | 미래 `requested`+`approved` ≤ **3** | 3건이면 버튼을 `disabled` + `신청은 3건까지 할 수 있어요` |
| 빈도 | 하루 **10회** | 429를 Toast로 — `오늘은 더 신청할 수 없어요. 내일 다시 시도해 주세요` |
| 겹침 | 슬롯·`approved`·**`requested`**·시험기간과 1분이라도 | 서버가 준 `free` 구간만 목록에 올린다 — 아래 주 |
| 방 용량 | 창 안 24건 | 409를 `이 강의실은 예약이 다 찼어요` 로 |

**겹침 판정에 `requested` 도 들어간다 — 같은 시간은 선착순 한 명이다.**

그래서 **빈 구간을 화면이 계산하면 안 된다.** 남의 `requested` 는 학생에게 보이지 않으므로(§남의 예약), 화면이 `주간 표`의 원본만 보고 빈 칸을 그리면 **그 칸이 구조적으로 409가 난다** — 경합이 아니라 매번 그렇다. 그래서 `비어 있는 시간` 목록은 **서버가 준 `free` 구간**을 그대로 쓴다(아래 §데이터).

목록을 보고 고르는 사이에 남이 먼저 신청하는 **진짜 경합**은 여전히 남는다. 그때는 Toast(`danger`) + 목록을 다시 불러 갱신한다. 화면이 할 일은 **왜 실패했는지 분명히 말하는 것**이다.

```
  { date, s_h, s_m, e_h, e_m, subject }        → 201 ResvMineOut (status: "requested")
```

- **`id` 를 화면이 채번하지 않는다.** 서버가 배정해 응답으로 돌려준다(S4b §2.5).
- `subject` 는 **UTF-8 바이트** 상한이다 — `P.SUBJ_MAX` = **20 B**(`lora_proto/proto.h`). 한글 6자면 18 B 라 여유가 거의 없다. `18 / 20 B` 로 남은 양을 보여주고, 넘으면 입력을 막는다.
- `type` 은 서버가 6(대여) 고정, `professor` 는 빈 문자열이다 — 폼에 없다.
- **문 앞 e-Paper 에는 `"학생 예약"` 으로 나간다**(S10 §2.5). 학생이 적은 용도는 본인과 관리자만 본다. 폼에 그 사실을 한 줄로 적는다: `문 앞 화면에는 "학생 예약"으로만 표시돼요`.

## 내 신청 — `/me`

신청한 뒤 학생이 돌아오는 자리다. `GET /api/student/me/reservations`.

```
┌ 헤더 ───────────────────────────┐
│ ‹   내 신청                      │
├─────────────────────────────────┤
│ ┌───────────────────────────┐   │
│ │ [승인됨] 공학관 401호       │   │
│ │ 10/24 토 10:00–12:00       │   │
│ │ 캡스톤 스터디               │   │
│ │ [체크인]        [취소]      │   │  ← 체크인은 창 안에서만
│ ├───────────────────────────┤   │
│ │ [대기중] 공학관 405호       │   │
│ │ 10/26 월 14:00–16:00       │   │
│ │ [신청 취소]                 │   │
│ ├───────────────────────────┤   │
│ │ [거절됨] 공학관 401호       │   │
│ │ 사유: 학과 행사와 겹칩니다   │   │
│ └───────────────────────────┘   │
└─────────────────────────────────┘
```

### 상태 다섯 — 색이 아니라 라벨이 진다

| `status` | 라벨 | 표현 |
|---|---|---|
| `requested` | 대기중 | `neutral` + `outline` 배지. 카드 테두리 `line.2` |
| `approved` | 승인됨 | `busy` 틴트 배지 — 이 방은 그 시간에 **쓰인다** |
| `rejected` | 거절됨 | `neutral` + `outline`, 카드 `opacity` 없이 사유를 본문에 |
| `cancelled` | 취소됨 | 〃 |
| `expired` | 만료됨 | 〃 . `승인 전에 시간이 지났어요` 한 줄 |

`approved` 에만 `room.busy` 틴트를 쓴다. 나머지 넷은 무채색이다 — **적색은 "그 방이 실제로 쓰인다"는 뜻이고, 신청·거절·취소는 방을 쓰지 않는다.**

### 체크인

`POST /me/reservations/{id}/checkin`. 창은 **시작 −10분 ~ 시작 +15분**(S10 §4.1).

- 창 밖에서는 버튼을 **숨기지 않고 `disabled`** 로 두고 아래에 `10:50부터 체크인할 수 있어요` 를 적는다. 버튼이 사라지면 학생이 기능의 존재를 모른다.
- 체크인하면 버튼 자리가 `✓ 10:52 체크인` 으로 바뀐다.
- 안 하면 No-show로 집계된다(S10 §2.6). 그 사실을 `체크인하지 않으면 다음 예약이 제한될 수 있어요` 같은 협박으로 쓰지 않는다 — 지금 규칙에 그런 제재가 없다.

### 취소와 철회는 다르다

| 상태 | 버튼 | 일어나는 일 |
|---|---|---|
| `requested` | `신청 취소` | **행이 삭제된다**(S10 §2.1 — id를 돌려주려고). 목록에서 사라진다 |
| `approved` · 시작 전 | `취소` | `cancelled` 로 남고 노드에 `RESV_DEL` 이 나간다 |
| `approved` · 시작 후 | 없음 | 409. 버튼을 두지 않는다 |

둘 다 확인 Modal을 거친다. `requested` 쪽 본문에 **"신청을 거두면 기록이 남지 않습니다"** 를 적는다 — 행이 지워지는 것이 사용자에게도 보이는 결과다.

## 넓은 폭 — `bp.tablet` 이상

**화면을 키우는 게 아니라 더 보여준다.** 라우트는 그대로 `/{bld}/{room}` 하나다.

| | `bp.mobile` | `bp.tablet` 이상 |
|---|---|---|
| 강의실 목록 | 별도 화면(`/{bld}`) | **좌측 340px 고정.** 폰에서 뒤로가기로 오가던 것이 한 화면에 |
| 이번 주 | 별도 화면(`/week`) | 우측에 **같은 격자**로 함께. 눈금만 커진다 |
| 다음 비는 시간 | `지금` 카드 안 한 줄 | **별도 카드**로 승격 (`10:00 – 13:00 · 3시간`) |
| `오늘` 목록 | 시각 + 과목 + 배지 | 시각 구간 + 과목 + 교수 + 배지 |
| 예약 진입 | 하단 고정 48px `이 강의실 예약하기` | **헤더 오른쪽** 40px `이 강의실 예약하기`(`brand` 채움) |

`/week` 라우트는 넓은 폭에서 `/{bld}/{room}`으로 리다이렉트한다 — 이미 그 안에 있다.

**예약 버튼은 헤더 오른쪽으로 올린다.** 모바일에서 하단에 고정한 이유는 엄지가 닿는 자리라서였는데, 넓은 폭에는 그 제약이 없고 하단 고정 바는 이번 주 격자의 아래를 가린다. 헤더 오른쪽은 처음 시안에서 `링크 복사`가 있던 자리다 — 데스크톱 브라우저도 주소창 복사가 한 번이라 중복이어서 빼고, 이 화면의 1차 동작을 그 자리에 둔다. 비로그인·`reservable = false` 규칙은 모바일과 같다(위 「예약 · 진입」).

**색 값은 폭에 따라 바뀌지 않는다.** 바뀌는 것은 `student` 치수 세트와 배치뿐이다.

### `layout` 을 가용성과 색으로 나눠 쓴다

`layout` 은 e-Paper와 같은 값이다(S10 §2.3). 화면은 이것을 **두 가지 다른 질문에** 쓰는데, 답이 다르다.

| 질문 | 기준 | 쓰는 곳 |
|---|---|---|
| **예약할 수 있나 (가용성)** | `layout === 4` 만 비어있음 | `지금 빈 강의실` 개수 · `비어 있는 시간` 목록 |
| **무슨 색으로 그리나** | `tokens.md` 의 `room.*` — RED(1·5·6·7) / BLACK(2·3·4·8) | 격자 블록 · 배지 |

**둘을 섞지 않는다.** 휴강(3)과 쉬는시간(2)은 BLACK이라 `room.free` 색을 쓰지만 **예약 가능한 시간은 아니다** — 그 구간은 `비어 있는 시간` 목록에 없다. 색은 e-Paper와 1:1로 유지하고, 예약 가능 여부는 서버가 준 `free` 구간이 말한다.

휴강과 진짜 빈 시간은 **라벨로 구분한다** — 격자 블록에 `휴강`(점선 + 취소선) / 빈 칸(아무것도 안 그림).

### 남의 예약은 `"예약됨"` 으로만 보인다

주간 표의 `ResvPublicOut{id, date, s_h, s_m, e_h, e_m, mine, label}` 에서 `label` 은:

- **내 것**(`mine: true`)·**관리자가 넣은 것** → `subject` 그대로
- **남의 학생 예약** → `"예약됨"` 고정 (S10 §3)

격자 블록에 이 `label` 을 그대로 쓴다. 화면이 판단하지 않는다 — 서버가 이미 가렸다. `mine: true` 인 블록만 `brand` 1px 테두리로 표시해 "내가 잡은 것"을 구분한다.

### 로그인 벽

조회 API도 `require_student` 다(S10 §3). **비로그인 방문자는 아무것도 못 본다.**

그래도 빈 로그인 폼을 바로 세우지 않는다 — 주소를 치고 들어온 사람이 자기가 뭘 잘못 찾아왔는지 알 수 없다. `/{bld}` 로 비로그인 진입하면:

```
┌─────────────────────────────────┐
│ 우송 ESC                         │
│ 공학관의 빈 강의실을 확인하고     │
│ 예약을 신청할 수 있어요.          │
│ 학교 웹메일로 로그인하세요.        │
│ [        로그인            ]     │
│ 처음이신가요? 가입 신청            │
└─────────────────────────────────┘
```

**무엇을 볼 수 있는지 한 문장**과 **어느 건물인지**(주소의 `bld` 로 안다)를 먼저 말한다. 로그인 뒤에는 원래 주소로 돌아간다. 세션 중 401(토큰 만료)도 같은 화면으로 보내되 `다시 로그인해 주세요` 를 얹고 돌아올 주소를 기억한다.

### ⚠ `WeekOut` 이 원본만 준다 — 서버 계산이 필요하다

S10 `WeekOut` 은 `slots` · `approved` 예약 · `exams` 를 **원본 그대로** 준다. 이 화면은 그것으로 두 가지를 못 한다.

1. **빈 구간을 계산할 수 없다.** 남의 `requested` 가 응답에 없으므로(§남의 예약), 화면이 빈 칸으로 그린 자리가 **구조적으로 409**가 된다.
2. **겹친 블록을 합칠 수 없다.** 합치기는 `room_state` 규칙인데, 그것을 브라우저에 복제하면 펌웨어·서버에 이어 **세 번째 구현**이 생긴다.

→ wj에게 **additive 요청**: `WeekOut` 에 요일별 `busy` 구간(정규 슬롯 · `approved` · **남의 `requested`** · 시험기간을 `room_state` 규칙으로 합친 것)과, 예약 화면이 쓸 `free` 구간을 넣어 준다.

```
WeekOut + busy: [{ day, spans: [{ from, to, label, type, mine }] }]
             + free: [{ date, spans: [{ from, to }] }]     오늘~+7
```

**`room_state` 규칙을 브라우저에 복제하지 않는다.**

## 상태

- **로딩**: 목록 자리에 Skeleton 5행. 오늘 목록 자리에 Skeleton 3행.
- **빈 상태**: `빈 강의실만`이 켜져 있는데 결과가 0이면 "지금은 모든 강의실이 사용 중입니다" + 체크 해제 버튼. 건물에 강의실이 없으면 "등록된 강의실이 없습니다".
- **에러**: 화면 상단 Banner(`danger`) + `다시 시도`. **이전 내용을 지우지 않는다** — 오래된 값이라도 아무것도 없는 것보다 낫고, 그때는 갱신 시각이 오래됐음을 아래 줄이 말한다.
- **갱신**: 화면 하단에 `문 앞 e-Paper 와 같은 내용 · 10:41 갱신`. 데이터가 5분 이상 오래되면 그 줄을 `danger`로 바꾼다.
- **자동 새로고침**: 60초마다. 탭이 백그라운드면 멈춘다(`document.hidden`).
