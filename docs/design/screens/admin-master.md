# 관리자 — 건물 · 강의실 (마스터)

- 시안: [캔버스](https://claude.ai/artifact/NLQyYEEdt4Rv6Dn7JZZuHi) `Admin-Master` · `Admin-Master-Bulk`
- 소비자: wj → `web/src/views/`
- 전제: `tokens.md` v2 (`admin` 치수 세트) · `components.md`
- 서버 계약: **S2** `server/app/domain/router.py`(건물·강의실 CRUD, 이미 구현됨) + **S4a §4.3**(`require_admin`·학교 스코프·`rooms.reservable`·부분 PATCH)
- 대상: **데스크톱 전용** (`bp.desktop` ≥ 1024px) — `README.md` 규칙

## 목적 · 진입

**모든 화면이 서 있는 바닥이다.** 시간표도 예약도 노드도 `rooms` 위에서 돈다. 이 목록이 비어 있으면 [페이지1](admin-rooms.md)에 고를 강의실이 없고, [학생 웹](student-room.md)에는 보일 방이 0개다.

그런데 이 화면이 없었다 — 서버에는 `POST /api/buildings`·`POST /api/rooms` 가 S2부터 있었고 S4a가 거기에 `reservable` 을 얹었는데, 그것을 부를 화면을 아무도 그리지 않았다(PR #41 cw 리뷰).

진입: 사이드 메뉴 `건물 · 강의실`. **메뉴에서 맨 위**에 둔다 — 설치 순서가 곧 이 순서다(건물 → 강의실 → 노드 배정 → 시간표).

> **사이드 메뉴가 하나 늘어난다.** 기존 다섯(`강의실 설정`·`주간 시간표`·`노드 상태`·`전송 현황`·`회원`) 위에 `건물 · 강의실` 이 들어가 여섯이 된다. 다른 화면 스펙의 메뉴 목록도 같이 읽는다.

## 학교는 여기서 만들지 않는다

S4a §4.3이 `POST /api/schools` 와 `DELETE /api/schools/{id}` 를 **없앴다.** CLI(`create-school --name --net-id --email-domain`)로만 만든다. `PATCH /api/schools/{id}` 는 `name` 만 받고 `net_id`·`email_domain` 은 CLI다.

그래서 화면에 학교 목록이 없다. 사이드바 아래에 **지금 로그인한 관리자의 학교를 읽기 전용으로** 적고(`우송대 · net_id 75 · wsu.ac.kr`) 그 아래 `학교는 CLI 에서만 만든다` 한 줄을 둔다. 버튼을 두고 405를 받게 하지 않는다.

## 레이아웃

```
┌─ 사이드 ─┬─ 건물 · 강의실 ─────────────────────────────────────┐
│ 건물·강의실│ 여기서 만든 방만 다른 화면에 나온다                 │
│ 강의실 설정├────────────────────┬──────────────────────────────┤
│ 주간 시간표│ 건물      3 / 26    │ 공학관 강의실   18곳 · 보임 15│
│ 노드 상태 │ bld│이름 │모뎀│방│  │ 호수│층│유닛│학생 예약│노드│ │
│ 전송 현황 │  E │공학관│m1│18│◀ │ 401 │4 │ 1 │ ☑ 받음 │…  │ │
│ 회원     │  S │사회관│m2│12│  │ 402 │4 │ 2 │ ☑ 받음 │…  │ │
│          │  L │도서관│미배정│0││ 405 │4 │ 1 │ ☐ 안 받음│…  │ │
│ 우송대    │                     │                              │
│ net_id 75 │ [+ 건물]            │ [범위로 추가] [+ 강의실]      │
└──────────┴────────────────────┴──────────────────────────────┘
```

**좌우 2단이다.** 왼쪽에서 건물을 고르면 오른쪽이 그 건물의 강의실로 바뀐다. 건물은 많아야 26개(아래 §bld)라 목록이 길어질 일이 없어 패널로 세워도 가로가 아깝지 않다 — [페이지1의 트리](admin-rooms.md)를 상단으로 올린 판단과 반대인데, 거기서는 강의실을 고르는 일이 가끔이고 표를 읽는 일이 내내였다. 여기서는 **건물을 고르는 것 자체가 화면의 절반**이다.

- 건물 패널 396px 고정, 강의실 표가 남는 폭.
- 건물 행 44px, 강의실 행 42px. 선택된 건물 행은 `brand.tint` 바탕 + 왼쪽 3px `brand` 막대.
- 강의실 표 컬럼: 호수 72 · 층 52 · 유닛 64 · 학생 예약 128 · 노드 남는 폭 · 작업 92.

## 건물

### `bld` 는 한 글자이고 전역에서 유일하다

`BuildingIn.bld` 는 `^[A-Za-z]$` — **한 글자**다. 무선 주소라서 S4a가 **학교가 달라도 겹칠 수 없게** 막았다(409). 두 가지 결과가 화면에 나온다.

1. **건물은 전 학교 합쳐 26개가 상한이다.** 헤더에 `3 / 26` 을 적는다. 남은 수를 모르면 관리자가 26번째에서야 알게 된다.
2. **타교가 쓰는 글자는 이 목록에 없다.** 학교 스코프가 걸러내기 때문이다. 화면이 미리 막을 수 없고 **저장할 때 409로만 안다.** 그래서 409를 Toast로 띄우지 않고 **글자 입력 칸에 붙여** 보인다 — `다른 학교가 이미 쓰는 글자입니다. 다른 글자를 고르세요.` 나머지 입력은 그대로 둔다.

폼에는 이미 쓰인 글자를 `쓰는 중: E S L` 로 적어 둔다. 내 학교 것만이지만 없는 것보다 낫다.

### `modem_id` 를 바꾸면 조용히 끝나지 않는다

서버가 `PATCH /api/buildings/{id}` 에서 `modem_id` 가 바뀐 것을 보면 두 가지를 한다(`domain/router.py`).

- **대기 중 전송을 새 모뎀으로 재지정한다** — `api.reassign_queued(bld, rooms, new_modem)`.
- **옛 모뎀과 새 모뎀 양쪽에 config 를 다시 내린다** — `api.config_changed(mid)` × 2.

건물 이름만 고치러 들어온 관리자가 드롭다운을 잘못 건드려 이걸 일으킬 수 있다. **`modem_id` 가 바뀌었을 때만 확인 Modal** 을 띄우고, 본문에 **대기 건수를 숫자로** 적는다 — `대기 중 7건이 m2 로 옮겨집니다. 옛 모뎀(m1)과 새 모뎀 양쪽이 설정을 다시 받습니다.` 이름·`bld` 만 바꾼 저장은 묻지 않는다.

`modem_id` 드롭다운에는 **그 학교 모뎀만** 나온다(S4a — 타교 모뎀은 404). `미배정`(`null`)도 고를 수 있다.

### 모뎀이 없는 건물

`modem_id = null` 이면 그 건물의 강의실은 **갱신을 못 받는다.** 방을 만들 수는 있지만 문 앞 화면은 영영 안 바뀐다. 건물 행에 `미배정` 을 `danger` 틴트 배지로 세운다 — 상태 배지에 적색을 쓰는 몇 안 되는 자리다. 실제로 기능이 죽어 있기 때문이다.

### 건물 삭제

그 건물의 **강의실·시간표·예약·시험기간이 전부 사라진다.** 확인 Modal에 지워질 것의 개수를 적고(`강의실 18곳 · 시간표 142건 · 예약 9건`), **건물 이름을 그대로 입력**해야 버튼이 풀린다. 되돌릴 수 없고, 벽에 붙은 노드는 그대로 남아 고아가 된다.

강의실이 0곳인 건물은 이름 입력 없이 지운다 — 잃을 것이 없다.

## 강의실

| 컬럼 | 값 | 비고 |
|---|---|---|
| 호수 | `RoomOut.room` | 1~9999 정수. `tabular-nums` |
| 층 | `room // 100` | **읽기 전용 파생값.** 입력 칸이 없다 |
| 유닛 | `RoomOut.units` | 1 또는 2 |
| 학생 예약 | `RoomOut.reservable` | Checkbox. 아래 |
| 노드 | `NodeOut` 조인 | `연결됨 · 3.98 V` / `48시간 넘게 보고 없음` / `단말 없음` |
| 작업 | | `수정` · `삭제` (`ghost`) |

### `reservable` 체크박스가 이 화면의 요점이다

`/api/student/rooms` 는 **`reservable=1` 인 방만** 준다(S10 §157). 끄면 그 방은 **학생 웹에서 존재하지 않는다** — 목록에도, 예약 화면에도, 주간 표에도 안 나온다.

**문 앞 e-Paper 는 그대로 돈다.** 시간표도 예약도 관리자가 넣은 것은 평소대로 나간다. 두 경로가 갈리는 유일한 자리라 컬럼으로 세워 한눈에 보이게 한다.

- 기본값은 **꺼짐**(`reservable: bool = False`, S4a). 새로 만든 방은 학생에게 안 보인다 — 안전한 기본값이지만 **관리자가 켜는 것을 잊으면 학생 웹이 빈 채로 남는다.**
- 그래서 표 헤더에 `18곳 · 학생 웹에 보이는 곳 15` 를 적고, **그 수가 0이면 표 위에 Banner** 를 세운다 — `학생 예약을 받는 강의실이 없습니다. 학생 웹 목록이 비어 있습니다.`
- 체크박스는 즉시 저장한다. Modal도 저장 버튼도 없다 — 되돌리기가 같은 클릭 한 번이다. 실패하면 체크 상태를 되돌리고 Toast를 띄운다.
- 저장은 **부분 PATCH** 로 보낸다: `PATCH /api/rooms/{id}` 에 `{"reservable": true}` 만. 전체 바디를 보내면 다른 탭에서 바뀐 `units` 를 덮어쓴다.

### 층은 서버에 없다

`RoomOut` 에는 `building_id` 와 `room: int` 뿐이다. 층은 `room // 100` 으로 화면이 파생한다 — [페이지1의 트리](admin-rooms.md)와 **같은 규칙**이어야 한다. 401 → 4층, 1203 → 12층, 100 미만은 `기타`.

그래서 **층 입력 칸이 없다.** 호수를 411로 고치면 층이 따라 바뀐다. 표의 층 컬럼 헤더에 `호수 ÷ 100` 을 주석으로 달아 관리자에게도 규칙을 알린다.

### `units` 를 2 → 1 로 줄일 때만 묻는다

한 강의실에 문이 둘이면 `units = 2` 이고 노드도 둘이다. 2에서 1로 내리면 **`unit 2` 가 기대 노드 목록에서 사라지는데 단말은 벽에 그대로 붙어 있다.** 그 단말은 갱신을 못 받고 화면이 옛 내용으로 굳는다.

- **줄이는 방향에만** 확인 Modal: `402호의 2번 단말이 목록에서 사라집니다. 벽에서 떼어 주세요.`
- **늘리는 방향은 묻지 않는다.** 새 자리가 [노드 화면](admin-nodes.md)에 `unseen` 으로 뜰 뿐이고, 그것이 곧 "여기에 단말을 달아라"는 안내다.

### 강의실 삭제

그 방의 **시간표·예약·시험기간이 함께 사라진다.** 확인 Modal에 개수를 적는다(`시간표 12건 · 예약 2건이 함께 지워집니다`). 노드가 배정돼 있으면 그 사실도 적는다 — `문 앞 단말(unit 1)은 갱신을 받지 못하게 됩니다.`

건물 삭제와 달리 **이름 입력은 요구하지 않는다.** 방 하나는 다시 만들면 되고, 매번 타이핑을 시키면 정리 작업이 고통스러워진다.

## 범위로 추가

한 건물에 방 30개를 하나씩 넣는 것은 실사용이 안 된다. 그래서 Modal 하나를 더 둔다.

```
시작 호수 [401]  끝 호수 [415]  유닛 [1]
☑ 학생 예약을 받는다

만들어질 방   15곳 중 12곳 · 이미 있는 3곳은 건너뛴다
[401][402][403][404][405]⟨406⟩⟨407⟩⟨408⟩[409][410]…
                          ↑ 이미 있음 — 점선 + 취소선

[취소] [12곳 만들기]
```

- **범위 문법을 늘리지 않는다.** 층마다 호수가 연속인 건물이 드물어서(강의실 사이에 화장실·계단이 있다) `401-405,409-415` 같은 문법을 만들어도 늘 어긋난다. 대신 **만들 방을 칩으로 미리 보여주고 눌러서 빼게** 한다. 규칙을 배우는 것보다 보고 고르는 편이 빠르다.
- **이미 있는 호수는 자동으로 빠진다.** 점선 테두리 + 취소선으로 보여 주되 선택은 못 한다. 조용히 지워 버리면 "왜 12곳이지?"가 된다.
- 버튼 라벨이 **실제로 만들 개수**를 말한다 — `12곳 만들기`. `추가` 가 아니다.

### 서버에 벌크 엔드포인트가 없다

`POST /api/rooms` 를 **12번 보낸다.**

- 진행 중에는 버튼을 `loading` 으로 잠그고 라벨을 `5 / 12 만드는 중` 으로 바꾼다. 12번 왕복이라 체감이 길다.
- **일부만 실패해도 되돌리지 않는다.** 성공한 방은 그대로 두고 실패한 호수만 칩으로 남겨 `재시도` 하게 한다. 되돌리려면 DELETE를 다시 보내야 하는데 그것도 실패할 수 있어 상태가 더 불분명해진다. [시험기간 일괄 추가](admin-rooms.md)와 같은 규칙이다.
- **방 하나마다 모뎀에 config 가 한 번씩 나간다**(`config_changed`). 12곳이면 12번이다. 화면이 막을 수 있는 것은 아니지만, 끝난 뒤 Toast에 `공학관 모뎀Pi 에 설정이 다시 내려갔습니다` 를 한 줄 적어 관리자가 [노드 화면](admin-nodes.md)의 변화를 예상하게 한다.

## 사용하는 컴포넌트

Table, Button(`primary` 추가 / `ghost` 수정·삭제), Input, Select, **Checkbox**(`reservable`·유닛), Modal(건물 폼·강의실 폼·범위 추가·확인 4종), Toast, Banner(`reservable` 0곳), Badge(`미배정`), EmptyState, Skeleton, SidebarNav.

새 컴포넌트는 없다. **`RoomTree` 는 쓰지 않는다** — 여기서는 트리가 아니라 건물 목록과 강의실 표다. 트리는 "이미 있는 방들 중에서 고르는" 장치이고, 이 화면은 그 방들을 만드는 곳이다.

## 데이터 (서버 계약)

전부 `require_admin` + 학교 스코프다(S4a §4.3). 타교 자원은 404이지 403이 아니다.

| 하는 일 | 엔드포인트 |
|---|---|
| 건물 목록 | `GET /api/buildings` → `BuildingOut[]` (내 학교만) |
| 건물 추가 | `POST /api/buildings` (`BuildingIn{school_id, name, bld, modem_id?}`) |
| 건물 수정 | `PATCH /api/buildings/{id}` — **부분 수정** |
| 건물 삭제 | `DELETE /api/buildings/{id}` |
| 강의실 목록 | `GET /api/rooms` → `RoomOut[]`. `building_id` 로 거르고 `room // 100` 으로 층을 만든다 |
| 강의실 추가 | `POST /api/rooms` (`RoomIn{building_id, room, units, reservable}`) |
| 강의실 수정 | `PATCH /api/rooms/{id}` — **부분 수정**. 체크박스는 `{"reservable": …}` 만 |
| 강의실 삭제 | `DELETE /api/rooms/{id}` |
| 모뎀 목록 | `GET /api/lora/modems` → `ModemOut[]` (`modem_id` 드롭다운) |
| 노드 상태 | `GET /api/admin/nodes` → `NodeOut[]` (노드 컬럼) |

**새로 만들 서버 필드가 없다.** `reservable` 은 S4a가 이미 `RoomIn/RoomOut` 에 넣는다.

### 서버가 알아서 하는 것 — 화면이 흉내 내지 않는다

| 언제 | 서버가 하는 일 |
|---|---|
| 건물 추가 | 없음. 방이 없어 재전송할 config 가 없다(모뎀은 최초 연결 때 config 를 받는다) |
| 건물 `modem_id` 변경 | `reassign_queued` + 양쪽 모뎀 `config_changed` |
| 건물 삭제 | 그 모뎀에 `config_changed` |
| 강의실 추가 · 수정 · 삭제 | 그 건물 모뎀에 `config_changed` |

화면은 이 중 **아무것도 대신 부르지 않는다.** `선택한 곳 동기화` 같은 버튼을 여기에 두지 않는다 — [페이지1](admin-rooms.md)의 것이고, 여기서는 서버가 자동으로 한다.

## 상태

- **로딩**: 건물 패널·강의실 표 각각 Skeleton. 건물 3행분, 강의실 6행분.
- **빈 상태 — 건물 0개**: 이 시스템의 첫 화면이다. EmptyState에 `건물을 먼저 만드세요` + `+ 건물`, 그리고 **설치 순서를 세 줄로** 적는다(건물 → 강의실 → 노드 배정 → 시간표). 여기서 막히면 아무 화면도 쓸 수 없다.
- **빈 상태 — 강의실 0곳**: `이 건물에 강의실이 없습니다` + `범위로 추가` 를 1차 액션으로. 하나씩 넣는 것보다 범위가 정상 경로다.
- **에러**: Toast(`danger`) + 재시도. 목록은 지우지 않는다.
- **자동 새로고침 없음.** 마스터 데이터는 관리자가 바꿀 때만 바뀐다. [노드 화면](admin-nodes.md)의 30초 폴링과 다르다.

## 미결

1. **`school_id` 를 화면이 아는가** — `BuildingIn` 이 `school_id` 를 요구한다. JWT에 학교가 들어 있으니 서버가 채워도 되는데 S4a가 명시하지 않았다. 화면이 보내야 한다면 로그인 응답에서 학교 id를 받아 둬야 한다. wj 확인
2. **`bld` 를 수정할 수 있나** — 서버는 `PATCH` 로 받는다. 그런데 `bld` 는 무선 주소라 바꾸면 그 건물 노드가 전부 주소를 잃는다. 수정 폼에서 `bld` 를 잠글지, 잠근다면 어떻게 바꾸게 할지(삭제 후 재생성?) 확인 필요 — **`modem_id` 변경보다 위험하다**
3. **삭제 전 개수를 어디서 세나** — 확인 Modal에 `시간표 142건` 을 적으려면 그 수를 알아야 한다. S4b의 건물 단위 조회(`GET /api/admin/buildings/{id}/slots`)를 세어 쓸 수 있으나 142건을 받아 길이만 쓰는 낭비다. 카운트만 주는 응답이 있으면 좋다 — additive 요청 후보
4. **노드 컬럼이 이 화면에 있어야 하나** — [노드 화면](admin-nodes.md)과 겹친다. 강의실을 만든 직후 "단말이 붙었나"를 보는 자리라 넣었는데, 목록이 커지면 매 행마다 조인이 부담이다. 구현 때 측정 후 결정
5. **CSV 로 방을 만들 수 있나** — S2b의 CSV 임포트는 시간표용이고, 없는 방을 만들지는 않는 것으로 읽었다. 만약 만든다면 이 화면의 범위 추가와 규칙이 갈리지 않아야 한다. wj 확인
