# 메인 페이지 — `/` (로그인 전)

- 시안: [캔버스](https://claude.ai/artifact/NLQyYEEdt4Rv6Dn7JZZuHi) `Landing`(390) · `Tablet-Landing`(768) · `Wide-Landing`(1280)
- 소비자: wj → `web/src/student/views/`
- 전제: `tokens.md` v2 (`student` 치수 세트) · `components.md`
- 관련: [auth.md](auth.md)(로그인 탭) · [student-room.md](student-room.md)(`/` 건물 선택 · 로그인 벽)
- 대상: 학생 웹. **반응형** — `bp.mobile` · `bp.tablet` · `bp.desktop` 세 폭에서 배치가 바뀐다

## 목적 · 진입

주소를 치고 들어온 사람에게 **이 웹으로 무엇을 할 수 있는지**를 학생 입장에서 보여 주고 로그인·가입으로 보내는 화면이다. 지금까지는 `/` 에 로그인하지 않고 들어오면 바로 로그인 벽이 섰다 — 처음 온 학생은 가입할 이유를 볼 수 없었다.

**학교 소개가 아니라 서비스 소개다.** 1판(학교 이름 + 세 줄)은 로그인 벽과 거의 같아서 바꿨다(2026-10-14 리뷰). 학교 이름을 쓰지 않으므로 로그인 전 화면은 지금처럼 **학교를 모른다** — 공개 API 가 필요 없다.

| 누가 `/` 로 오나 | 보이는 것 |
|---|---|
| 로그인하지 않음 | **이 화면** |
| 로그인함 | 지금 그대로 건물 선택(또는 바로 건물로) — [student-room.md](student-room.md) 「`/` — 건물 선택」 |

- **`/` 에서만 이 화면을 띄운다.** `/E/401` 같은 딥링크로 비로그인 진입하면 지금처럼 로그인 벽(`LoginGate`)이다 — 그 사람은 이미 볼 곳을 알고 왔다.
- 학생·관리자는 여기서 가르지 않는다. 로그인 화면 맨 위 `학생 | 관리자` 탭에서 고른다([auth.md](auth.md)). 관리자를 위해 바닥글에 `관리자 로그인`(→ `/admin/login`) 링크 하나만 둔다.

## 구성 — 위에서 아래로 넷

| # | 구역 | 바탕 | 내용 |
|---|---|---|---|
| 1 | 히어로 | `surface` + 아래 `line.2` | 작은 머리말 · 큰 제목 · 설명 · `로그인` / `가입 신청` · 강의실 목록 미리보기 |
| 2 | 학생이 할 수 있는 일 | `bg.student` | 기능 카드 넷 |
| 3 | 시작하는 방법 | `surface` + 위 `line.2` | 가입 3단계 |
| 4 | 바닥글 | `surface` + 위 `line.2` | 서비스 한 줄 · `관리자 로그인` |

헤더는 학생 웹 공통 높이 58px. 왼쪽 로고 + `ESC`, 오른쪽 `로그인`(`secondary`). 태블릿 이상에서는 그 왼쪽에 `가입 신청`(`ghost`)을 더한다.
- 헤더 버튼 높이는 **40px** — 학생 헤더의 다른 링크 버튼과 같다. `sm`(28px)은 폰에서 누르기 작다(PR #94).

### 1. 히어로

| 요소 | 문구 | 스타일 |
|---|---|---|
| 머리말 | `강의실 시간표 · 예약` | `font.size.sm` 700 `text.2` |
| 제목 | `빈 강의실, 폰으로 바로 확인하세요.` | 700 · 폰 26px / 태블릿 32px / 넓은 화면 40px · 행간 1.3. 폰과 넓은 화면은 쉼표 뒤에서 줄을 바꾼다 |
| 설명 | `지금 비어 있는 강의실을 찾고, 이번 주 시간표를 보고, 필요한 시간에 예약을 신청하세요. 학교 웹메일로 가입하면 됩니다.` | 16px `text.2` 행간 1.65 · 최대 520px |
| 버튼 | `로그인`(→ `/login`) · `가입 신청`(→ `/signup`) | `로그인` = `primary`(이 화면의 **유일한 brand 채움**) · `가입 신청` = `secondary`. 높이 52px |
| 보조 | `학교 웹메일로 가입 · 관리자 승인 뒤 이용` | `font.size.xs` `text.3` |
| 미리보기 | 강의실 목록 카드 | 아래 「미리보기는 실제 화면 조각이다」 |

### 2. 학생이 할 수 있는 일

제목 `학생이 할 수 있는 일` + 부제 `복도에서 폰으로, 수업 사이 쉬는 시간에.` 아래에 카드 넷. 카드는 `surface` + `line.2` 1px + `radius.lg`, 안에 제목(17px 700) · 설명(14px `text.2`) · 맨 아래 미리보기(`sunken` 판 위).

| 카드 | 설명 | 미리보기 |
|---|---|---|
| **지금 빈 강의실** | 건물을 고르면 강의실마다 지금 수업 중인지, 언제까지 비어 있는지 보여요. 자주 가는 강의실은 ★ 로 맨 위에. | 강의실 행 셋 — `비어있음`(`text.3` 라벨) · `수업중`(`room.busy` 배지) |
| **이번 주 시간표** | 강의실 하나의 월~금 시간표를 한 화면에. 수업 · 시험 · 특강 · 내 예약이 같이 보여요. | 월~금 × 5칸 격자. 사용중 블록 `room.busy`, 내 예약은 `brand` 1px 테두리(student-room.md 와 같은 규칙) |
| **예약 신청** | 비어 있는 시간을 골라 신청하면 관리자가 승인해요. 7일 이내 · 비어 있는 시간만. 승인되면 시간에 맞춰 체크인. | `다음 예약` 카드 + `신청 → 승인 → 체크인` 알약. 현재 단계만 `brand.tint` + `brand` 테두리 |
| **문 앞 화면과 같은 정보** | 강의실 문 앞 전자종이와 웹이 같은 시간표를 봐요. 승인된 예약은 문 앞 화면에도 떠요. | 전자종이 축소판 — 흰 바탕 · 검정 글자 · 적색 `사용중` 띠 하나(terminal-epaper.md 의 3색 그대로) |

### 3. 시작하는 방법

제목 `시작하는 방법` + 부제 `처음 한 번만 하면 돼요.`, 번호 단계 셋. 번호는 `line.3` 테두리 원 안 숫자 — **`brand` 를 칠하지 않는다**(현재 단계가 없는 안내다. 가입 화면의 `StepList` 는 현재 단계를 칠한다).

1. `학교 웹메일로 가입 신청` — `메일로 링크가 와요. 5분 안에 열어 주세요.`
2. `이름 · 학번 · 비밀번호 입력` — `링크를 연 화면에서 계정을 마무리해요.`
3. `관리자 승인 뒤 로그인` — `승인되면 메일이 와요. 그때부터 로그인할 수 있어요.`

폰에서는 그 아래 `가입 신청하기`(`secondary`, 전체 폭)를 한 번 더 둔다 — 히어로까지 다시 올라가지 않게. 태블릿 이상은 헤더의 `가입 신청` 으로 충분해 두지 않는다.

### 4. 바닥글

`ESC — 전자종이 · LoRa 강의실 시간표 게시 시스템`(`font.size.xs` `text.3`) + 오른쪽 `관리자 로그인`(→ `/admin/login`, `text.2` 링크).

## 반응형 — 세 폭

| | 폰 `< 640` | 태블릿 `640–1023` | 넓은 화면 `≥ 1024` |
|---|---|---|---|
| 좌우 여백 | `space.4`(16) | 40px | 80px, 내용 최대 1120px 가운데 |
| 히어로 | 한 줄로 쌓기: 글 → 버튼(전체 폭, 세로로) → 미리보기 | **가운데 정렬** 한 칸: 글 → 버튼(가로) → 미리보기(최대 440px) | **2단**: 왼쪽 글 + 버튼, 오른쪽 미리보기 440px. 세로 가운데 맞춤 |
| 기능 카드 | 1열 | 2열 | 4열 |
| 시작하는 방법 | 세로 목록 + `가입 신청하기` | 3열 | 왼쪽 제목 280px + 오른쪽 3열 |
| 헤더 | `로그인` | `가입 신청` · `로그인` | 같음 |

- 카드 높이는 **행 안에서 맞춘다**(grid 기본 stretch). 미리보기는 카드 바닥에 붙인다 — 설명 길이가 달라도 미리보기 윗선이 한 줄로 선다.
- 넓은 화면 기능 카드 한 칸은 약 268px 이다. 시간표 미리보기가 이 폭에서 5열을 유지해야 한다 — 요일 칸이 30px 아래로 줄면 라벨을 지우고 색 블록만 남긴다.

## 미리보기는 실제 화면 조각이다

그림·사진·일러스트를 쓰지 않는다. 미리보기는 **학생 웹에 실제로 있는 화면의 축소**를 같은 토큰으로 그린 것이다 — 로그인 뒤 화면을 미리 보여 주는 것이 가장 정확한 설명이라서다.

- **데이터는 고정된 예시**다. 로그인 전이라 실제 강의실을 받을 수 없다(조회 API 가 전부 `require_student`). 건물·호수는 `공학관 401` 같은 흔한 이름으로 두고, 실제 데이터처럼 보이게 하려고 서버를 부르지 않는다.
- 미리보기는 **눌리지 않는다**(링크·버튼 아님). `aria-hidden` 은 걸지 않되 각 미리보기 묶음에 `role="img"` + `aria-label`(`강의실 목록 예시`, `주간 시간표 예시` …)로 한 덩어리로 읽힌다.
- 색 규칙은 본 화면과 같다 — `room.busy` 적색 라벨, `room.free` 무채색, `brand` 는 내 예약 테두리와 현재 단계뿐. 미리보기라고 색을 더 쓰지 않는다.
- 히어로 미리보기는 `강의실 목록` 4행(★ 즐겨찾기 1개, 사용중 2개 — `수업중` · `시험중`). 기능 카드 1의 미리보기는 같은 것의 3행.

## 상태

서버를 부르지 않으므로 로딩·에러 상태가 없다. 로그인한 상태로 `/` 에 오면 이 화면을 그리지 않고 건물 선택으로 간다.

## 사용하는 컴포넌트

`StudentHeader`, Button(`primary` · `secondary` · `ghost`)

미리보기 넷과 기능 카드는 이 화면에만 있으므로 `student/views/landing/` 옆에 둔다(components.md 「어디에 두나」). 배지는 `components/` 의 Badge·`TypeBadge` 를 그대로 쓴다 — 미리보기용으로 따로 만들지 않는다.

## 미결

1. **문구** — 제목·설명·카드 설명은 초안이다. 팀 리뷰에서 확정
2. **문 앞 화면 문장의 정확성** — `승인된 예약은 문 앞 화면에도 떠요` 는 LoRa 전송이 끝나야 참이다(몇 분 걸릴 수 있다). `곧 떠요` 로 낮출지 cw 와 확인
