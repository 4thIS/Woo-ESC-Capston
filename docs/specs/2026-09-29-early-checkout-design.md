# 학생 조기 퇴실 — 설계 (spec)

- 생성일시: 2026-09-29
- 수정일시: 2026-09-29 (§3 끝 시각 규칙 — 시작+1분 제거 / 체크인 뒤엔 시작 전에도 퇴실, 관리자 상태 열 / 체크인은 시작 시각부터 — 사용자 결정)

## 0. 배경 · 위치

S10(`2026-09-23-s10-student-analytics-design.md`)의 학생 예약은 승인 → 체크인까지 있고, 체크인한 학생이 일찍 나가도 예약은 끝 시각까지 강의실을 잡는다. 문 앞 e-Paper 는 계속 "사용중"이고, 남은 시간은 다른 학생이 신청할 수 없다.

이 문서는 체크인한 학생이 **조기 퇴실**을 눌러 남은 시간을 바로 비우는 기능을 S10 위에 더한다. 공중 프로토콜(`lora_proto/`)은 바꾸지 않는다 — 기존 `RESV_DEL` 로 노드의 예약을 지운다.

## 1. 목표 · 비목표

### 목표

- 체크인한 학생이 조기 퇴실할 수 있다 — 체크인하면 **취소 대신 조기 퇴실**이다.
- **체크인은 시작 시각부터**(시작 ~ +15분). S10 의 "시작 −10분부터"를 바꾼다 — 시작 전엔 그 방을 앞 수업·예약이 쓰고 있을 수 있고, 시작 전 체크인·퇴실이라는 어색한 경우가 생기기 때문이다(2026-09-29 사용자 결정). 서버 `CHECKIN_BEFORE = 0`.
- 퇴실하면 **바로 빈 강의실**이 된다 — 문 앞 e-Paper 에서 예약이 지워지고, 학생 목록·주간 격자에서도 비어 보인다.
- 남은 시간은 다른 학생이 신청할 수 있다(기존 최소 15분·5분 격자 규칙 그대로).
- 퇴실 시각이 남는다(학생 내 예약 카드, 학생·관리자 예약 응답).
- 관리자 예약 표에서 예약마다 사용중·조기 퇴실 등 상태를 정확히 보여 준다.

### 비목표 (이번엔 안 함 / 후속)

- 원래 예정된 끝 시각 보존 — 퇴실하면 끝 시각을 퇴실 시각으로 당긴다(§2). 원래 끝 시각은 남기지 않는다.
- 주간 시간표 격자의 조기 퇴실 표시 — 표(강의실 설정 → 예약)에만 상태를 보인다.
- 퇴실 통계(조기 퇴실률 등) — `checked_out_at` 이 남으니 필요하면 후속으로 집계한다.
- 관리자가 대신 퇴실 처리 — 관리자는 기존 취소(시작 뒤에도 가능)를 쓴다.

## 2. 데이터 · 계약

**방식: 끝 시각을 당긴다.** 퇴실하면 예약의 `e_h`·`e_m` 을 퇴실한 분(초 버림)으로 바꾸고 `checked_out_at` 에 퇴실 시각을 적는다.

- 이유: 서버에서 예약의 끝 시각으로 "사용 중"을 판단하는 곳이 여섯 군데다 — 현재 상태(`room_state`), 학생 주간 격자(`student_router`), 매일 노드 승격(`daily`), 노드 재동기화(`topology`), 통계(`analytics`), 겹침·빈 구간(`reserve._blockers`). 끝 시각을 당기면 여섯 곳이 그대로 맞는다. `checked_out_at` 만 더하고 원래 끝을 두면 여섯 곳 모두에 "실제 끝 = 퇴실 시각" 계산을 넣어야 하고, 하나만 빠져도 e-Paper 가 "사용중"으로 남는다.
- `reservations.checked_out_at` (DATETIME, NULL 가능, UTC — `checked_in_at` 과 같은 규칙) — alembic 마이그레이션으로 추가(additive).
- 상태(`status`)는 `approved` 그대로다. 새 상태를 만들지 않는다 — `ck_resv_status` 와 상태 필터를 건드리지 않는다.

## 3. 접근 제어 / 제약

퇴실은 예약한 학생 본인만(기존 `/me/reservations/{id}` 와 같은 소유 확인). 조건을 모두 만족해야 한다.

| 조건 | 어기면 |
|---|---|
| `status == 'approved'` | 409 "{status} 상태에서는 불가" (기존 `_require`) |
| 체크인했다(`checked_in_at` 있음) | 409 "체크인한 예약만 퇴실할 수 있습니다" |
| 아직 퇴실하지 않았다(`checked_out_at` 없음) | 409 "이미 퇴실했습니다" |
| 끝 시각 전(`now < 끝`) | 409 "이미 끝난 예약입니다" |

- 동시성: 체크인·취소와 같은 `_ID_LOCK` 안에서 처리한다 — 퇴실과 관리자 취소가 엇갈려 취소된 행에 퇴실이 찍히지 않게.
- 체크인이 시작 시각부터라 퇴실은 늘 시작 뒤다(끝 ≥ 시작). 학생 웹은 체크인한 예약에 취소 버튼을 보이지 않는다.
- 새 끝 시각 = 퇴실한 분(초 버림). 시작한 그 분 안에 퇴실하면 길이 0 예약이 된다 — 끝이 지금 이하라 모든 곳에서 바로 빈 강의실이고, 새 신청은 늘 지금 뒤에 시작하므로(`validate_request`) 길이 0 이 막는 신청도 없다. (처음에는 max(퇴실 분, 시작 + 1분)으로 정했으나, 실제로 돌려 보니 그 1분 동안 '사용중'으로 남아 "바로 빈 강의실"을 어겨 고쳤다 — 2026-09-29)
- 퇴실한 예약은 다시 노드로 가지 않는다 — 매일 승격(`daily._promote`)은 끝난 예약을 건너뛰고, 재동기화(`topology`)는 `pushed_at` 이 있는 예약만 싣는데 퇴실이 `pushed_at` 을 비운다.

## 4. 인터페이스 계약

**새 엔드포인트** — `POST /api/student/me/reservations/{id}/checkout`

- 본문 없음. 성공 200 → `ResvMineOut`(퇴실 반영된 행). 실패는 §3 표의 409, 남의 예약·없는 id 는 기존과 같이 404.

**응답 필드 추가(additive)** — `ResvMineOut` 에 `checked_out_at: datetime | null`. 학생 `/me/reservations` 와 관리자 예약 응답(둘 다 `_mine_out`)에 같이 나온다. 관리자 강의실·건물 예약 목록(`ResvWithRoom`, `GET /api/rooms/{id}/reservations`·`/api/buildings/{id}/reservations`)에 `checked_in_at`·`checked_out_at`. 기존 필드는 그대로라 BREAKING 아님.

**노드(공중)** — 퇴실하면 `push_del` 로 `RESV_DEL` 을 enqueue 한다. "보낸 적 있고 아직 안 끝난 예약만" 판단은 **당기기 전의 원래 끝 시각**으로 한다(`push_del(..., end=원래 끝)`). 보낸 적 없는 예약(창 밖 등)은 아무것도 보내지 않는다. `pushed_at` 은 비운다.

## 5. 영역별 영향

| 영역 | 변경 |
|---|---|
| `server/` | 모델 컬럼·마이그레이션, `reserve.checkout()`, 학생 라우터 엔드포인트, `_mine_out`·`ResvMineOut` 필드 |
| `web/` | `ResvMineOut` 타입, `studentApi.checkout`, 규칙 함수(퇴실 가능 여부), 내 예약 카드 **조기 퇴실** 버튼 + 확인 창 + "✓ 14:23 퇴실" 표시, 다음 예약 카드가 퇴실한 예약을 다음 예약으로 치지 않게 |
| `web/` 관리자 | 강의실 설정 → 예약 표에 **상태** 열 — 학생 예약: 예정 / 체크인 대기(시작 ~ +15분) / 사용중(체크인, 안 끝남) / 조기 퇴실 HH:MM / 사용 완료 / 미체크인(창 지남). 관리자가 넣은 예약은 — |
| `lora_proto/`·`firmware/`·`modempi/` | 없음 (기존 `RESV_DEL`) |
| `server/lora_service/` | 없음 (기존 `enqueue_resv_del` 호출만) |

학생 웹: 체크인한 카드는 **오른쪽 위에 빨간(danger) 조기 퇴실 버튼**, 취소 버튼 없음(사용자 결정 — danger 는 스펙상 삭제·에러·실패 전용이라 mh 협의 필요). 문구: 버튼 **조기 퇴실**, 확인 창 제목 "조기 퇴실", 본문 "퇴실하면 문 앞 화면에서 예약이 지워지고, 남은 시간은 다른 사람이 예약할 수 있어요.", 성공 알림 "퇴실했어요", 카드 표시 "✓ 14:23 퇴실". 409 는 기존처럼 문장 + 재조회.

## 6. 무회귀 · 롤아웃

- 마이그레이션은 컬럼 추가만 — 기존 행은 NULL(퇴실 안 함)이고 동작이 같다.
- 서버 PR 을 먼저 머지하고 웹 PR 이 뒤따른다(web/CLAUDE.md — 서버에 없는 필드를 가정하지 않는다).
- 통계: 퇴실한 예약은 체크인한 예약으로 그대로 센다(`checked_in`). 끝이 당겨져 점유 시간은 실제 사용 시간이 된다.

## 8. 성공 기준

- 체크인한 학생이 진행 중에 조기 퇴실하면: 응답에 `checked_out_at`, 끝 시각이 퇴실 분, 노드에 보냈던 예약이면 `RESV_DEL` 1건, 학생 목록에서 그 강의실이 비어 있음, 남은 시간(15분 이상)이 예약 가능 구간으로 뜸.
- §3 표의 경우가 모두 409, 시작 전 체크인은 409("체크인은 시작 시각부터 15분 후까지입니다").
- 관리자 예약 표에서 사용중·조기 퇴실이 구분된다.
- 학생 웹: 조기 퇴실 → 확인 → "✓ 퇴실" 표시, 사이드바 다음 예약 카드에서 사라짐.
- 기존 서버·웹 테스트와 E2E 무회귀.

## 9. 열린 결정 (plan 단계에서 확정)

- 없음 — 시작 전 퇴실(비목표), 원래 끝 시각(보존 안 함), 관리자 화면(비목표)은 위에서 정했다.
