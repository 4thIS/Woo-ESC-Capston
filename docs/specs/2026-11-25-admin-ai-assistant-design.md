## 0. 배경 · 위치

관리자는 지금 강의실마다 화면을 열어 시간표·예약·시험기간을 칸에 맞춰 입력한다. "803호 이번 주 금요일 15시부터 18시까지 특강"처럼 **한 문장으로 말하면 되는 일**도 화면 세 개를 거친다. 건물 관리자가 늘면(#160) 이 비용이 사람 수만큼 커진다.

이 문서는 관리자 웹에 **AI 비서** 탭을 더해, 관리자가 채팅으로 요청하면 AI 가 모자란 정보를 되묻고, **바뀌기 전·후 주간표를 나란히(GitHub 머지 확인처럼)** 보여 준 뒤, 관리자가 [적용]을 눌러야 반영되게 한다.

핵심 결정 (2026-11-25 브레인스토밍):

1. **운영 기능**으로 만든다(시연용 아님). 건물 관리자가 매일 쓰는 수준.
2. **양식 채우기형**: 모델은 문장을 정해진 양식(JSON)으로 **옮기기만** 한다. 날짜 계산·되묻기·검증·전후 비교·적용은 전부 코드가 한다. 작은 모델이 약한 일(날짜 계산, 여러 단계 판단, 형식 지키기)을 코드로 옮겨 작은 모델로도 운영 정확도를 내기 위해서다.
3. 모델은 **Gemma 4 E2B 를 파인튜닝**해 **관리자 브라우저에서**(WebGPU) 돌린다. 모델 파일은 **Hugging Face Hub** 공개 저장소에서 받는다(구글 드라이브는 대용량 확인 페이지·CORS·할당량 때문에 브라우저 직접 다운로드에 맞지 않음).
4. 관리자의 문장은 **외부 AI 서비스로 나가지 않는다** — 브라우저 안의 모델이 처리하고 우리 서버로만 간다.

## 1. 목표 · 비목표

### 목표
- 관리자가 채팅으로 다음 여섯 가지를 처리한다.
  - A. 날짜별 일정(예약) 등록·수정·삭제 — 특강·대여·휴강·보강
  - B. 시험기간 등록·수정·삭제
  - C. 정규(주간) 시간표 추가·수정·삭제
  - D. 학생 예약 신청 승인·거절
  - E. 조회 — 빈 강의실, 강의실 일정, 대기 중 신청, 노드 상태 (확인 화면 없이 답만)
  - F. 여러 강의실 한 번에 ("8층 전체")
- 바꾸는 일은 **반드시 전·후 비교 확인 화면과 [적용] 버튼**을 거친다.
- 미리보기에서 본 결과와 실제 적용 결과가 **같은 코드**로 만들어져 어긋나지 않는다.
- 모델·규격·서버·화면을 서로 독립적으로 바꾸고 배포할 수 있다(모델 교체 = 안내 파일 한 줄).

### 비목표 (이번엔 안 함 / 후속)
- 강의실·건물 생성·삭제, 노드 등록, 노드 명령(`REQUEST_STATUS` 등) — 구조·하드웨어를 바꾸는 일이라 AI 비서에 맡기지 않는다.
- 정해진 작업 목록 밖의 자유 질문("지난달 가장 많이 빈 강의실 분석") — `unknown` 으로 답한다.
- 학생 웹의 AI 기능.
- 채팅 글로 적용("응 해줘") — 적용은 버튼으로만.
- 2단계로 미룸: 되돌리기, 학습용 기록 내보내기·재학습 자동화, 모델을 못 돌리는 PC 를 위한 서버 측 대체 실행.

## 2. 전체 구조

```
[관리자 브라우저 — AI 비서 탭]                         [홈서버 FastAPI]
 채팅 화면 (wj)
 Gemma 4 E2B 파인튜닝 모델 (Web Worker, WebGPU)
 Hugging Face 에서 처음 1회 받아 브라우저에 보관
   문장 → 양식 JSON ──────────────────────────────▶  ① 해석: 날짜·시각(assistant_proto) + 강의실(DB)
                                                     ② 대화: 빈 칸·애매함 → 정해진 질문(+선택 버튼)
                                                     ③ 미리보기: 변경을 실제로 돌려 보고 rollback
 확인 화면 (왼쪽 기존 │ 오른쪽 수정) ◀──────────────      → 전·후 주간표 + 표시(추가/삭제/수정)
 [적용] ──────────────────────────────────────────▶  ④ 적용: 저장된 변경 목록을 한 트랜잭션으로
                                                          → outbox → 모뎀Pi → 노드 → 기록
```

원칙:
- **모델은 DB 를 보지 않는다.** 문장 → 양식 변환만 한다. 그래서 RAG 가 필요 없고 학습 데이터에 실제 교수명이 들어갈 일도 없다.
- **판단은 서버가 한다.** 모델 출력은 제안일 뿐이다. 권한·검증·충돌 판단은 기존 서버 규칙을 그대로 쓴다.
- **프론트는 규격 코드를 갖지 않는다.** 지시문·출력 문법·생성 설정은 서버의 모델 안내(§6)로, 상태 요약은 서버의 응답으로 받는다.

## 3. 양식 규격 — `assistant_proto/` (새 계약, cw 전담)

`lora_proto/` 와 같은 위치·규율의 **단일 진실원**이다. 파인튜닝 데이터·평가(wj), 서버(cw), 프론트(wj)가 같은 파일을 쓴다.

```
assistant_proto/
├── README.md                 ← 규격 설명 + 해석 규칙 표 + lockstep 절차
├── schema/form.v1.json       ← 양식 JSON Schema (출력 문법 강제에도 그대로 씀)
├── prompt/                   ← 고정 지시문, 상태 요약 형식
├── vectors/forms.v1.jsonl    ← 예문 → 정답 양식 (약 100개, 계약 예문)
├── vectors/resolve.v1.jsonl  ← 표현 + 기준 시각 → 푼 값 (해석기 예문)
└── assistant_proto/          ← Python 패키지: 양식 검증, 날짜·시각 해석기, 상태 요약 만들기 (DB 없음, 순수 함수)
```

서버는 `lora-proto` 처럼 경로 의존성으로, `ml/` 도 같은 패키지를 쓴다(평가 채점이 서버와 같은 해석기를 써야 하므로).

### 3.1 양식 모양

```json
{"v": 1, "intent": "event.add",
 "target": {},
 "set": {"rooms": ["803"], "when": "이번 주 금요일", "time": "15시부터 18시까지", "type": "특강"}}
```

- `target` = 무엇을(찾을 조건), `set` = 어떻게(새 값). 추가는 `set` 만, 삭제는 `target` 만, 수정은 둘 다, 조회는 `target` 에 조건.
- `target`·`set` 이 가질 수 있는 칸: `rooms`(문자열 목록), `when`, `time`, `type`, `subject`, `professor`, `reason`, `requester`. 그 밖의 칸은 규격 위반(`additionalProperties: false`).
- **`rooms`·`when`·`time`·`subject`·`professor`·`reason`·`requester` 는 문장 속 표현을 그대로 옮긴다.** 모델은 계산하지 않는다.
- **`type` 만 고른다**: `수업`·`시험`·`휴강`·`빈강의실`·`특강`·`대여` (서버의 type 1~6 과 같은 순서). 동의어("보강"→수업, "대관"→대여, "세미나·초청강연"→특강, "중간고사·기말"→시험)는 학습으로 가르친다.
- `v` = 규격 판. 서버는 자기가 아는 판이 아니면 거절한다(§11).

### 3.2 작업 종류 (intent) 18개

| 묶음 | intent | 예문 |
|---|---|---|
| A 날짜별 일정 | `event.add` · `event.change` · `event.remove` | "803 금 15~18 특강", "다음 주 화 자료구조 휴강", "목요일 보강" |
| B 시험기간 | `exam.add` · `exam.change` · `exam.remove` | "801·803 12/15~19 시험기간" |
| C 정규 시간표 | `class.add` · `class.change` · `class.remove` | "803 월 9~12 자료구조 김교수로 바꿔" |
| D 학생 신청 | `request.approve` · `request.reject` | "801 내일 신청 승인", "장비 점검이라 거절" |
| E 조회 | `ask.free_rooms` · `ask.schedule` · `ask.requests` · `ask.node` | "금요일 오후 빈 강의실?", "801 배터리?" |
| 대화 | `fill` · `cancel` · `unknown` | 되물음에 대한 답, "취소", 지원하지 않는 요청·잡담 |

F(여러 강의실)는 작업이 아니라 `rooms` 에 여러 개 — 모든 작업에 적용된다.

| intent | 꼭 필요 | 선택 | 비고 |

### 3.4 상태 요약과 이어지는 답

첫 문장은 문장만 모델에 넣는다. 되물은 뒤의 답은 서버가 준 **상태 요약**을 앞에 붙인다.

```
상태: event.add | 803 | 11/27(금) | 15:00~18:00 | 특강 | 이름 ?
질문: 특강 이름은 무엇인가요?
관리자: 알고리즘 특강이요
```
→ `{"v": 1, "intent": "fill", "target": {}, "set": {"subject": "알고리즘 특강"}}`

- `fill` 은 바뀐 칸만 낸다("아 801도 같이" → `set.rooms: ["801"]` 은 서버가 **더한다**).
- 상태 요약의 모양은 규격(`prompt/`)에 정하고, 서버만 만든다. 학습 데이터·서버·프론트가 같은 모양을 쓴다.
- 대화 중 전혀 다른 새 요청이 오면 모델은 그 작업의 intent 를 내고, 서버는 앞 대화를 버렸다고 알린 뒤 새로 시작한다.

### 3.5 날짜·시각 해석기 (순수 함수, `assistant_proto`)

기준 시각(KST)을 받아 표현을 값으로 푼다. 풀지 못하면 "못 풂"을 돌려준다(추측하지 않는다). 규칙 전체는 `assistant_proto/README.md` 표와 `vectors/resolve.v1.jsonl` 이 원본이다. 큰 원칙:

- 주의 시작은 월요일(서버 `clock.week_start` 와 같다). "이번 주 X요일"·"다음 주 X요일"은 그 주의 그 요일.
- 요일만("금요일")은 오늘 포함 가장 가까운 그 요일.
- "12/3"·"12월 3일" — 올해, 이미 지났으면 내년. "3일"만은 이번 달, 지났으면 다음 달.
- 기간("12/15~19", "15일부터 19일까지"), 목록("화, 목", "화목") 지원.
- 시각: "15시", "15:30", "3시 반", "오전/오후 3시". 오전·오후 없는 1~8시는 오후(13~20시)로 본다(수업 시간대).
- 길이: "3시부터 3시간" 지원. "3~6시"·"3시부터 6시까지" 지원.
- 요일(정규 시간표): "월", "월요일", "매주 월".

해석 결과는 확인 화면에 **항상 구체적인 날짜·시각으로** 보이므로, 규칙이 관리자의 뜻과 다르면 그 자리에서 드러난다.

### 3.6 계약 예문

`vectors/forms.v1.jsonl` 의 약 100개 예문(문장 + 앞 상태 → 정답 양식)은 (a) 서버 테스트, (b) 파인튜닝 최종 평가의 일부, (c) 프론트 견본으로 함께 쓴다. **학습 데이터에는 넣지 않는다.**

## 4. 대화 흐름 (서버, cw)

- 대화 상태(작업, 채운 칸, 마지막 질문)를 서버 DB 에 둔다. **30분** 말이 없으면 만료.
- 매 턴: 양식 검증 → 칸 합치기 → 해석(날짜·시각은 `assistant_proto`, 강의실은 DB) → 다음 단계 결정:
  - `ask` — 빈 칸·애매함: 정해진 질문 + (고를 수 있으면) 선택 버튼. 예: "803호가 두 건물에 있습니다" → [공학관 803] [인문관 803]. 건물 관리자는 자기 건물만 보이므로 대부분 생기지 않는다.
  - `preview` — 칸이 다 찼다: §5 미리보기.
  - `answer` — 조회 작업: 글 + 표 데이터. 확인 화면 없음.
  - `error` — `unknown`·규격 위반·해석 실패: "다르게 말해 주세요, 예: …" 와 예문.
- 선택 버튼을 누르면 모델을 거치지 않고 버튼 값이 바로 서버로 간다.
- 수정·삭제 대상 찾기: `target` 조건으로 기존 항목을 찾아 0건이면 "찾지 못했습니다", 여러 건이면 목록 버튼.
- "취소"(`cancel`)는 진행 중인 대화를 버린다.

## 5. 미리보기 · 적용 · 기록

### 5.1 기존 쓰기 코드 정리 (wj 코드, cw 가 고치고 wj 가 리뷰)

지금 `_write_resv`·`_write_exam`·승인·거절은 함수 안에서 커밋한다. 이것을 **쓰기만 하고 커밋하지 않는 함수**로 나누고, 기존 라우터는 그 함수 + 커밋 + 알림으로 바꾼다. `enqueue_*` 는 이미 세션 모드(커밋 안 함)라 그대로 쓴다.

- 기존 API 의 동작·응답은 바뀌지 않는다. **기존 테스트가 고치지 않고 그대로 통과**하는 것이 이 정리의 합격 기준이다.
- 확정 변경 목록(ops)의 각 항목은 이 함수 하나에 1:1 로 대응한다: `slot.put`·`slot.del`·`resv.put`·`resv.del`·`exam.put`·`exam.del`·`request.approve`·`request.reject`.

### 5.2 미리보기

1. 세션을 열고 바뀌기 전 주간 데이터를 읽는다.
2. 확정 변경 목록을 5.1 의 함수로 실행하고 flush 한 뒤 바뀐 뒤 데이터를 읽는다.
3. **rollback** — 도메인 행도 outbox 행도 남지 않는다.
4. 미리보기 기록을 저장한다: 확정 변경 목록, 관련 데이터의 **지문(hash)**, 만료 **10분**, 1회용.

예약·시험 번호를 새로 받는 변경이 있으면 미리보기도 `_ID_LOCK` 안에서 돈다(적용과 같은 규칙).

응답은 바뀌는 (강의실, 주)마다 전·후 주간 데이터와 표시를 담는다. 주간 데이터 모양은 관리자 주간표가 쓰는 모양(정규 시간표·예약·시험기간)과 같다. 추가·삭제·수정 표시는 **서버가 계산**한다(프론트가 따로 비교하지 않는다).

### 5.3 막음 · 경고 · 안내

| 종류 | 예 | [적용] |
|---|---|---|
| 막음 | 지난 날짜, 권한 밖 강의실, 노드 예약 용량 24 초과, 포털 수업(source 보호), 시작 ≥ 끝, 번호 소진 | 비활성 + 이유 |
| 경고 | 기존 수업·예약과 시간이 겹침, 대기 중인 학생 신청과 겹침, 노드 오프라인(연결되면 전송) | 누를 수 있음 |
| 안내 | 오늘~+7일 밖 일정은 저장 후 그날이 가까워지면 문 앞에 전송(기존 규칙) | — |

### 5.4 적용

- 모델 출력을 다시 쓰지 않고 **미리보기에 저장된 확정 변경 목록**을 실행한다.
- 지문이 달라졌으면(그사이 다른 변경) 적용하지 않고 409 + 새 미리보기.
- 여러 강의실이어도 **한 트랜잭션** — 하나라도 실패하면 아무것도 바뀌지 않는다.
- 권한을 다시 확인한다. 미리보기 하나는 한 번만 적용된다(두 번 눌러도 한 번).
- 커밋 후 관련 모뎀Pi 에 알린다. 프론트는 기존 전송 추적(`outboxTrack`)으로 "문 앞 반영 중 → 완료"를 보여 준다.

### 5.5 기록

- **변경 기록**: 누가·언제·어떤 문장으로·어떤 확정 변경을 적용했는지, 모델 출력, 규격 판, 모델 판, outbox 번호. 관리자 웹 AI 비서 탭에 "변경 기록" 목록.
- **대화 기록(학습용)**: 매 턴의 문장·모델 출력·서버 응답·관리자가 고친 내용. 서버에만 두고 **180일** 뒤 매일 작업(`/jobs/daily`)이 지운다. 학습에 쓸 때는 이름 등을 지운 형태로 내보내는 도구(2단계)를 거쳐서만 wj 에게 넘긴다.

### 5.6 되돌리기 (2단계)

적용할 때 반대 변경 목록을 함께 저장한다(추가↔삭제, 수정→이전 값). 기록의 [되돌리기]는 같은 미리보기·확인 화면을 거친다. 그 뒤 같은 항목이 다른 경로로 바뀌었으면(지문 불일치) 자동으로 되돌리지 않고 이유를 보인다.

## 6. 인터페이스 계약

모두 관리자 전용(`ManagerUser`), 건물 범위(`MgrScope`) 적용. 범위 밖은 기존 규칙대로 404.

| 메서드 · 경로 | 설명 |
|---|---|
| `GET /api/assistant/model` | 지금 쓸 모델 안내: 규격 판, 실행 도구, Hugging Face 저장소·**커밋 해시로 고정한 판**, 파일 목록(이름·크기·SHA-256), 고정 지시문, 출력 문법(JSON Schema), 생성 설정 |
| `POST /api/assistant/turns` | 한 턴. 입력 `{conversation_id?, utterance, form? \| choice?}` (form·choice 중 하나). 출력 `{conversation_id, kind: ask\|preview\|answer\|error, message, choices?, model_context?, preview?, answer?}` — `model_context` 는 다음 턴에 모델 앞에 붙일 상태 요약 |
| `POST /api/assistant/previews/{id}/apply` | 적용. 출력 `{change_id, outbox_ids}`. 지문 불일치 409(+새 미리보기), 만료·재사용 410 |
| `GET /api/assistant/changes` | 변경 기록 목록(자기 범위) |
| `POST /api/assistant/changes/{id}/revert` | 되돌리기 미리보기 (2단계) |

기존 API 의 요청·응답은 바뀌지 않는다(새 경로만 추가 — additive).

## 7. 웹 — AI 비서 탭 (wj)

- 사이드바 **맨 위 별도 묶음 "AI"** 에 "AI 비서" 탭, 경로 `/admin/assistant`. 건물 관리자·최고 관리자 모두.
- 배치: 넓은 화면은 왼쪽 대화(약 380px) + 오른쪽 확인 화면(나머지). 미리보기가 없을 때 오른쪽은 "할 수 있는 일" 예문. 좁은 화면은 확인 화면이 전체를 덮는다.
- 확인 화면: 바뀌는 (강의실, 주)마다 기존 │ 수정 주간표를 나란히. 추가 = 초록 `+`, 삭제 = 빨강 `−` + 취소선, 수정 = 노랑 "이전 → 이후"(색 + 기호). 위에 변경 요약 글과 막음·경고·안내. 강의실이 많으면 강의실별 요약 표(+1/−0)를 먼저, 누르면 펼침. 주간표는 기존 `WeekView` 그리기를 재사용한다.
- 모델: 처음엔 받지 않고 "AI 모델 받기 (약 1.5 GB, 처음 한 번)" 버튼. 진행률·이어받기·저장 공간 점검. 다른 화면 미리 받기(`prefetchViews`)에 모델은 넣지 않는다. 모델은 **Web Worker** 에서 돌리고, 탭을 옮겨도 대화·불러온 모델이 유지된다. 안내(§6)의 판이 바뀌었을 때만 다시 받고 SHA-256 을 확인한다.
- WebGPU 가 없거나 메모리가 모자라면 "이 PC 에서는 AI 비서를 쓸 수 없습니다(이유)" + 기존 화면 안내.
- 모델이 나오기 전 개발은 **개발용 대역**으로: 양식 JSON 을 직접 넣거나 원본 E2B + 예문 방식.

**디자인 스펙**: mh 가 팀에서 빠지므로(2026-11-25) `docs/design/` 스펙은 **cw 가 쓰고 wj 가 구현**한다. "스펙 먼저 머지, 코드는 따라감" 규율은 유지한다.
- cw: `docs/design/screens/admin-assistant.md`(배치·색·다운로드 안내·빈 상태·오류 상태) 초안, `components.md` SidebarNav 아이콘에 AI 비서 아이콘 추가, `admin-master.md` 메뉴 순서 갱신 → 먼저 머지.
- wj: 그 스펙대로 `NavIcon`·화면 구현. 화면에서 토큰 우회 하드코딩 금지(기존 규칙).

## 8. 모델 — `ml/` (wj)

### 8.1 0단계: 브라우저 실행 도구 실험 (약 1주)

| 후보 | 장점 | 확인할 것 |
|---|---|---|
| WebLLM | JSON Schema 문법 강제 | Gemma 4 E2B 지원, 튜닝 모델 변환 경로 |
| Transformers.js | HF 직접 로드, 예제 많음 | 문법 강제 없음, 속도 |
| LiteRT-LM Web | 구글 공식, E2B·E4B 지원 목록 | 문법 강제, 튜닝 모델 변환 |
| wllama (llama.cpp) | GBNF 문법 강제, GGUF 변환 쉬움 | WebGPU 안정성 |

원본 E2B 로 **학과 관리자 PC**(안 되면 비슷한 사양 PC)와 wj 노트북에서 첫 다운로드 시간·초당 토큰·메모리·문법 강제 동작을 잰다. **문법 강제가 되는 도구가 1순위**(형식 깨짐을 구조로 없앤다). 결과물: 선정 문서 + 원본 E2B 기준 점수(§8.3 지표).

### 8.2 학습 데이터

1. **템플릿 생성기**(Python): 작업 × 칸 값 × 문장 틀 → (문장, 정답 양식). 강의실·과목·교수명은 **가상 값**(공개 저장소에 올라가므로).
2. **다양화**: 큰 모델(Claude)로 구어체·줄임말("금욜")·띄어쓰기 생략·오타 변형. 가상 데이터만 보낸다(실제 기록은 보내지 않음). **자동 검증** — 변형 문장에 정답 표현이 실제로 들어 있고, 그 표현을 `assistant_proto` 해석기로 푼 값이 원래와 같을 때만 남긴다.
3. **이어지는 답·거절**: `fill`·`cancel`·`unknown`(지원하지 않는 요청·잡담)을 전체의 10~15%.
4. **사람 시험 문장 약 300개**: 팀원·조교·학과 직원이 실제로 쓸 법한 요청, 손 라벨. **학습에 절대 넣지 않는다.**

| 묶음 | 양 | 용도 |
|---|---|---|
| 학습 | 5,000~10,000 (생성) | 학습 |
| 검증 | 약 500 (생성, 학습에 없는 문장 틀) | 학습 중 점검 |
| 시험 | 약 300 (사람) + 계약 예문(§3.6) | 합격 판정 |

### 8.3 합격선 (사람 시험 문장, **배포할 양자화 모델** 기준)

| 지표 | 합격선 |
|---|---|
| intent 정확도 | ≥ 97% |
| 칸 정확도 (해석기로 푼 값 기준 — 표현이 달라도 같은 값이면 정답) | ≥ 95% |
| 양식 전체 일치 | ≥ 90% |
| 형식 오류 (JSON 깨짐·규격 위반) | 0% (문법 강제) / 강제가 없으면 ≤ 1% |
| 위험 오류: 추가·수정을 삭제로 | ≤ 0.5% |
| 응답 시간 (관리자 PC, 문장 1개) | ≤ 5초 |

비교: 원본 E2B + 예문 몇 개 / 튜닝 E2B / (E2B 가 못 미칠 때만) 튜닝 E4B.

### 8.4 학습

LoRA SFT(Hugging Face TRL·PEFT 또는 Unsloth). 입력 = 짧은 고정 지시문 + (상태 요약) + 관리자 문장, 출력 = 양식 JSON. Gemma 4 생각 모드는 끈다. 16 GB GPU 하나(Kaggle·Colab)로 충분하다고 본다(실측 전 어림). 실행마다 설정·데이터 판·seed·평가 보고서를 `ml/reports/` 에 남긴다.

### 8.5 변환 · 배포 · 판 관리

1. LoRA 를 합치고 0단계에서 고른 도구 형식으로 변환, int4 양자화(약 1.5 GB).
2. **양자화 모델로 시험 세트를 다시** 돌려 합격선 확인. 브라우저에서 예문 20개를 돌려 Python 결과와 같은지 확인.
3. Hugging Face 공개 저장소(조직은 §15 열린 결정)에 업로드, 판 태그(v1.0.0). 모델 카드: 가상 데이터로 학습·개인정보 없음, 평가 결과, Apache 2.0. 업로드 토큰은 wj 만, 커밋 금지.
4. 서버의 모델 안내(§6)는 저장소 안 파일(`server/app/assistant/model.json`, cw)에서 읽는다. 릴리스 = wj `ml/` PR(평가 보고서 첨부) → cw 가 합격선 확인 → HF 태그 → 안내 파일의 판을 바꾸는 PR 머지 = 배포. 롤백 = 이전 판으로 되돌리는 PR.

### 8.6 재학습 (2단계)

서버에 모인 "모델이 틀리고 관리자가 고친 사례"를 이름 등을 지워 내보내 다음 판 학습에 더한다.

## 10. 접근 제어 · 제약

- 모든 새 경로는 관리자 전용 + 건물 범위. 건물 관리자는 자기 건물의 강의실만 해석·미리보기·적용된다. 적용 시 권한을 다시 본다.
- 모델 출력은 제안일 뿐 — 모든 변경은 기존 서버 검증(source 보호, 용량 24, 바이트 상한, 지원 글자)을 지난다.
- 관리자 문장은 브라우저 → 우리 서버로만 간다. 외부 AI API 로 보내지 않는다(학습 데이터 다양화에는 가상 데이터만 외부 모델에 보낸다).
- 턴 요청에 관리자별 상한(예: 분당 60)을 둔다. 문장 길이 상한을 둔다.
- 화면은 모델·서버가 준 글을 글자로만 표시한다(HTML 로 해석하지 않음).
- 서버는 워커 1개(기존 규칙) — 대화·미리보기 상태는 DB 에 둔다(프로세스 메모리에 두지 않음).

| 영역 | 방식 |
|---|---|
| `assistant_proto` | 양식 검증, 계약 예문이 규격을 지키는지, 해석기 예문(기준 시각 고정), 상태 요약 형식 비교 |
| 서버 | 테스트용 실물 SQLite. 되묻기→답→미리보기→적용 흐름, **미리보기 결과 = 적용 결과**, 미리보기 뒤 outbox·도메인 행 0, 지문 불일치 409, 다강의실 하나 실패 시 전부 취소, 권한 범위, 두 번 적용, 쓰기 정리 뒤 **기존 테스트 무수정 통과** |

CI 는 규격·해석기·서버·웹 테스트만 돈다. 모델 평가는 무거워서 PR 에 보고서를 첨부해 사람이 확인한다.

## 14. 단계 · 롤아웃

```
0단계 (동시 시작, 약 1주)
  cw : assistant_proto v1 (규격, 필수 칸, 상태 요약, 예문 ~100, 해석기 + 테스트) → 단독 PR 먼저 머지
  cw : 화면 스펙 초안(admin-assistant.md·아이콘·메뉴 순서) → 머지
  wj : 브라우저 실행 도구 실험, 원본 E2B 기준 점수, 관리자 PC 측정

1단계 (약 3~4주, 어림)
  cw : 쓰기 코드 정리(wj 리뷰) → 마이그레이션 → AI 백엔드(대화·강의실 해석·미리보기·적용·기록·모델 안내)
  wj : 데이터 생성·다양화·사람 시험 문장 → 학습 → 평가 → 변환 → HF v1
  wj : AI 비서 탭 — 모델 전에는 개발용 대역으로
  끝: 18가지 작업이 홈서버에서 처음부터 끝까지, 합격선 통과, 관리자 PC 실사용 확인

2단계
  되돌리기, 학습용 기록 내보내기·재학습, 서버 측 대체 실행(선택), 변경 기록 화면 다듬기
```

배포 순서: 규격 → 마이그레이션 → 쓰기 정리 → 백엔드(모델 안내는 아직 비활성) → 화면 → 모델 v1 안내 활성. 모델 안내가 비어 있으면 AI 비서 탭은 "준비 중"을 보인다 — 백엔드·화면을 모델보다 먼저 배포해도 안전하다. `main` 머지 = 홈서버 반영(`esc-autodeploy`)이므로 새 필수 env 는 없게 설계한다.
